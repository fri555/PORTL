# 信息摘要看板 v3.9 前端设计

## 目标与范围

以《信息摘要看板 · 产品需求文档》v3.9 为信息摘要模块的唯一需求基线，重构管理层工作台中的信息摘要组件、领域类型、演示数据与行为测试。保留现有工作台的双栏结构，不改造日程、待办、系统入口或顶部总览。

本轮要让老板在五分钟内完成三件事：识别需要关注的业务事项、查证 AI 结论所依据的钉钉原文、在工作台内发起后续行动。

## 方案选择

采用模块级重构：

- 保留 `SystemPortalsView` 与 50:50 工作台布局。
- 重构 `InformationDigestPanel`，拆分详情层、行动表单和关注设置等职责。
- 扩展 `workbench` 领域类型与 mock 数据，同时保持个人实时数据入口可映射到新结构。
- 用组件行为测试覆盖分类、详情、空态、分页、关闭与行动入口。

不采用只改 Tab 文案的方式，因为旧组件的默认聚合、悬浮详情、外跳查证和行动表单均与 v3.9 冲突。不扩大为整页重构，避免把信息摘要 PRD 变成工作台全量改版。

## 领域模型

### 业务事项

业务事项是从一条或多条授权消息中聚合出的工作对象，不等同于原始消息或视觉卡片。每个业务事项必须且只能拥有一个主分类：

1. `followup`：重点跟进
2. `decision`：待我决策
3. `risk`：风险预警
4. `business`：经营动态
5. `watch`：我的关注

事项包含标题、摘要、影响、优先级、评分、冲突状态、最新时间和来源证据。评分参与排序，但不出现在卡片正面。

### 来源证据

来源证据是支持某个业务事项判断的授权消息记录，包含发送人、会话、原文和时间。AI 分析与来源证据在界面上必须使用不同区域与标签，避免用户误把生成内容当成原文。

### 行动草稿

行动草稿是从业务事项上下文生成、等待用户确认的发消息、建待办或建日程内容。详情层只解释事项，不承载行动表单；行动草稿在独立弹层中编辑和确认。

## 信息架构

### 模块头部

头部包含：

- 标题“信息摘要”
- 实时连接或真实快照状态
- “最后更新 HH:MM”
- 手动刷新按钮及加载状态

刷新完成后以轻量反馈告知用户，不改变当前 Tab 和滚动位置。

### 分类导航

五个 Tab 严格按 PRD 顺序展示。默认进入“重点跟进”。每个 Tab 只展示其主分类事项，不再提供旧版“高优 TOP5”跨分类聚合。

### 事项卡片

卡片正面包含：

- 业务域与优先级
- 标题、摘要和影响
- 冲突提示（存在时）
- 来源数量与最新时间
- 关闭入口
- 由数据配置的行动按钮，最多三个

点击卡片主体打开详情层；点击关闭或行动按钮不得同时打开详情。卡片正面不显示评分、完整原文或 AI 建议列表。

### 详情层

使用右侧抽屉式详情层，适配工作台阅读节奏，包含：

- 标题、摘要、影响、优先级和评分
- 数据冲突说明
- 独立标注的“AI 分析”区域
- 独立标注的“钉钉原文”区域
- 最多十条来源记录
- 每条来源上的“关注该群”和“关注该人”
- 右上角关闭

详情层不放发消息、建日程、建待办按钮，不提供跳转钉钉或外部系统的链接。

### 行动弹层

行动按钮位于卡片独立操作区：

- `send_msg`：发消息
- `create_todo`：建待办
- `create_calendar`：建日程

每个事项由数据明确声明可用行动，最多三个。点击后打开独立对话框，展示“AI 生成 · 可编辑”的预填内容；确认后调用现有 DWS 行动服务或在快照模式给出不落库的演示反馈。写权限缺失时按钮灰显并解释原因。

## 状态与分页

- 每个 Tab 首批最多显示五条。
- 当滚动区接近底部时，继续追加最多五条，不使用独立“下一页”。
- 已关闭事项立即从当前视图移除，底层数据保持不变。
- “风险预警”无数据时显示“近期平稳，暂未发现风险信号”。
- “我的关注”初始无订阅时显示“暂无关注项”，并提供“新增关注”。
- 其他分类无数据时说明当前时间范围内没有可展示事项。
- 未授权状态使用 PRD 指定的授权引导卡片；同步中显示近 30 天数据同步进度，不渲染虚假业务事项。

## 关注设置

新增关注使用独立对话框，支持群聊、人员和关键词三种来源。原型至少覆盖：

- 在三种来源类型间切换
- 选择一个群或人员
- 输入关键词
- 展示已选规则与最多二十条限制
- 删除规则
- 确认后让“我的关注”进入有内容状态

不在原型中实现真实通讯录或会话接口。

## 视觉方向

延续当前工作台冷静、轻量的管理界面，不引入新的整页视觉语言。信息摘要的识别性来自“证据链”而非装饰：

- 蓝色用于可操作与 AI 分析。
- 红色只用于高风险、冲突和失败。
- 琥珀色用于中优先级与待确认状态。
- 绿色用于平稳、成功和已连接。
- 原文区域采用中性灰底和清晰的发送人/会话/时间层级。

唯一强调元素是详情层中的“AI 分析 / 钉钉原文”双轨结构，用视觉边界持续提醒用户哪些是结论、哪些是证据。保留当前 17px 卡片标题、13px 条目标题、12px 正文、10px 辅助信息的工作台字号体系。

## 组件边界

- `InformationDigestPanel`：头部、Tab、分页状态和事项列表协调。
- `DigestItemCard`：单个事项的判断信息与独立行动区。
- `DigestDetailDrawer`：评分、AI 分析、冲突和来源证据。
- `DigestActionDialog`：三种行动草稿的编辑与确认。
- `WatchRuleDialog`：关注规则的新增与删除。

组件通过显式 props 和事件通信，不直接共享弹层内部状态。数据映射和排序放在纯函数中，便于独立测试。

## 数据流与兼容

1. mock 或 DWS 个人数据进入统一的业务事项数组。
2. 先排除已关闭事项，再按主分类过滤。
3. 分类内按冲突/破线优先规则及评分倒序排列。
4. 列表按五条一批暴露给视图。
5. 详情层只读取选中事项。
6. 行动弹层根据事项声明的行动类型创建独立草稿。

现有个人数据若缺少新字段，映射层提供安全默认值；不得在组件模板中散落兼容判断。

## 错误处理

- 刷新失败：保留已有数据，在头部显示可重试提示。
- 行动失败：弹层保留用户编辑内容，并展示后端返回的可理解原因。
- 无写权限：禁用对应行动，不尝试调用服务。
- 来源缺失：标记“来源暂不可用”，不得用 AI 内容代替原文。
- 数据冲突：始终显式展示各来源差异，不自动选择一个值作为事实。

## 测试与验收

使用 Vitest 与 Vue Test Utils 先写失败测试，再实现：

- 五个 Tab 的名称、顺序和互斥过滤。
- 默认每批最多五条，滚动到底追加下一批。
- 卡片正面不展示评分，详情层展示评分。
- AI 分析和钉钉原文区域可区分。
- 详情层不包含三种行动按钮或外跳链接。
- 每卡片行动按钮不超过三个，点击打开独立表单。
- 风险空态、关注空态、授权态和刷新失败态。
- 关闭事项后从视图移除。
- 新增关注后展示关注事项。
- 冲突与排序规则。
- 键盘可达、焦点可见和窄屏抽屉布局。

完成前运行聚焦测试、完整测试、类型检查和生产构建，并在常见桌面宽度与窄屏下进行浏览器验证。

## 非目标

- 不实现后端评分算法、词库配置或消息聚类。
- 不接入真实通讯录、群列表或授权接口。
- 不改造日程、待办、系统入口和工作台整体布局。
- 不实现审批动作。
- 不新增任何钉钉深链或外部系统跳转。
