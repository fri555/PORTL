## 0. 执行摘要

本报告在既有草案基础上，对行业做法做了**真实数据校验**，并结合你们选定的两家底座供应商（DeepSeek V4、阿里百炼）的实际计费规则，重算了成本底座，补充了草案缺失的**工程层（限速/熔断/审计）**与**内部结算中枢架构**。

**六个核心结论：**

1. **「积分/Credits」是行业统一抽象层**。主流平台均用统一计量单位屏蔽不同模型、不同任务的计价差异，兑换比例集中在 **0.01–0.05 元/积分**，并锚定现金（Coze 1000:1、腾讯云 100:1、Evol 约 6900:1）。你们的「金币」思路完全正确。
2. **三级配额（企业→部门/项目→个人）+ 共享池 + 个人独占配额** 是行业事实标准，Coze 企业版、腾讯云 Token Plan、阿里百炼坐席制都是同一范式。
3. **超额三模式**：自动扣款续费（Coze）、拦截消耗（阿里云 STAROps）、等待重置（月度额度）。预警普遍设在 70%/90%/100%。
4. **工程层靠「令牌桶 + 多时间窗 + 成本熔断」**：秒级防 DDoS、分钟级防滥用、日/月级防资源吸血；429 响应要带回 `Retry-After`、限流头、成本头，做到成本透明。

**三个必须直面的硬约束（红牌）：**

- 🔴 **百炼 Token Plan 团队版条款限制**：白纸黑字「仅限在兼容的 AI 编程和智能体工具中**交互式使用，不可用于自动化脚本或应用后端**」。你们是后端多租户 Agent 平台，直接调用会违反 ToS、有封禁风险。**必须改用百炼「按量付费 / 资源包 / 节省计划」接入，不要用 Token Plan 坐席**。
- 🔴 **DeepSeek V4 峰谷定价**：高峰时段（每日 9:00–12:00、14:00–18:00，北京时间）价格 **×2**。金币若按固定比例锚定人民币，峰时底层成本翻倍会直接吃掉毛利。建议按「高峰价」锚定或预留 30% 缓冲。
- 🔴 **草案的成本估算偏高 3–7 倍**：草案按原价/旧价估算（如标准任务 0.02–0.04 元），而 DeepSeek V4 Pro 当前为**永久 2.5 折**（输入 3 元 / 输出 6 元每百万 token），标准任务真实成本约 **0.006 元**。本报告已用真实单价重算（见 §4.2）。

## 2. 行业 token 额度管理调研：别人怎么做

> 本节核验并修订了草案第二章。外部平台数据已用 2026-07 官方文档复核；标注「内部」的腾讯系产品名（STAROps / Hermes / ClawPro 等）来自贵方草案与内部知识，未做外部联网验证，仅作范式参考。

### 2.1 积分 / 信用额度抽象层（兑换比例）

| 平台 | 兑换比例 | 说明 |
|------|---------|------|
| 扣子（Coze）企业版 | **1000 积分 : 1 元** | 积分不足自动从火山引擎现金账户按 1000:1 扣款 |
| 腾讯云 Token Plan | 100 积分 : 1 元 | 积分池按月预付费，不同模型单价不同 |
| 阿里云无影共享积分包 | 1 积分 ≈ ¥0.05 | 实际按合同折扣 |
| Evol 团队版 | 1000 积分 ≈ $1（约 6900:1 元） | 积分当月有效 |
| GitLab Credits | 1 Credit = $1 | 月末按实际用量结算 |
| Microsoft Copilot Studio | $200/月 = 25,000 Credits（≈0.008 美元/Credit） | 或按量 0.01 美元/Credit |
| **阿里百炼 Token Plan** | **¥0.00792 / Credit**（标准坐席折算） | Credits 统一计量，跨模型通享 |

**核心发现**：行业集中在 **0.01–0.05 元/积分**，统一抽象层屏蔽了模型/任务计价差异。

### 2.2 三级配额体系（企业 → 部门 → 个人）

- **腾讯云 ClawPro**：企业级总控（全局 Token 上限 + Agent 总数兜底）→ 部门级资源池切分 → 个人级精细限制，呈「漏斗型」。
- **扣子企业版**：可按企业成员/角色、工作空间、组织、设备/自定义实体设置用量限额；企业成员**共享企业版积分池**。
- **OpenAI API**：6 个账号层级（Free + Tier1–5），层级由累计消费决定，对应不同的速率与用量上限——这是「账号层级→配额」的另一种落地。
- **OpenAI ChatGPT Enterprise**：支持在工作区、群组、个人用户三层灵活配置月度积分限额。

### 2.3 配额类型

- **累计额度**：从开始使用到当前的总量上限。
- **周期额度**：按月/按日重置（行业以「月」为主）。
- 两者常组合使用（月度总池 + 日度护栏）。

### 2.4 超额处理三模式

| 模式 | 代表 | 做法 |
|------|------|------|
| 自动扣款续费 | 扣子企业版 | 积分不足按 1000:1 从现金账户自动扣款 |
| 拦截消耗 | 阿里云 STAROps | 达上限自动拦截消耗积分的操作 |
| 等待重置 | 阿里云 Hermes Agent | 月度用完后等待下月重置或订阅积分包 |

### 2.5 资源池模式：共享池 + 个人独占配额

- **扣子企业版**：企业成员共享企业版积分（共享池），席位增购即增购订阅积分。
- **腾讯云 Token Plan**：同一套餐下所有 API Key 共享积分池，可为每个 Key 设**独占配额**与**配额上限**。
- **GitLab Credits**：组织范围池化，自动抵消重度/轻度用户差异。
- **百度千帆**：席位制 + 企业共享积分包。

### 2.6 消耗计量：差异化扣减

- **按任务复杂度**（Warp）：任何交互至少 1 积分，复杂交互按 LLM 模型、工具调用次数、任务复杂度、上下文量差异化。
- **按模型类型**（百炼 Token Plan）：不同算力等级模型设固定 Credits 扣减比例，无需区分输入输出单独核算。
- **按成果定价（新兴）**：LTM BlueVerse Currency 按业务成果而非资源消耗计费，含固定+可变混合结构——值得在体系里预留接口。

## 3. 工程层：配额 / 限速 / 成本熔断怎么做（草案缺失，重点补齐）

行业成熟的配额系统不是「设个数就完事」，而是**令牌桶算法 + 多时间窗 + 成本熔断**的组合。

### 3.1 令牌桶 + 多时间窗防御体系

| 窗口 | 目的 | 典型配置 |
|------|------|---------|
| 秒级（1–60s） | 防 DDoS / 突发流量 | 令牌桶 `burst_capacity=5, refill_rate=1/s`（高成本模型） |
| 分钟级（1–60min） | 防常规滥用 | `rolling_window=300, max_requests=500` |
| 长周期（日/月） | 防「资源吸血鬼」长期占用 | 日/月硬顶；电商预留促销弹性、教育放宽学期初末 |

> 反例：某社交平台只设日配额，凌晨遭爬虫榨干，单日 API 费用损失 $15k。

### 3.2 模型档位分级限速

模型成本可差百倍，必须分级：

| 模型档 | 策略 |
|-------|------|
| GPT-4 级（贵） | 阶梯递减配额 + token/s 限制，企业版可购突发额度 |
| Claude 级 | 并发数限制 + 请求延迟监控，启用智能降级 |
| 国产/开源级（便宜） | 时长限制 + GPU 利用率监控，开放批量请求 |

### 3.3 429 响应透明化设计（最佳实践）

完整 429 应包含五层信息，让调用方和财务都看得见：

```
HTTP/1.1 429 Too Many Requests
Retry-After: 63
X-RateLimit-Limit: 100
X-RateLimit-Used: 78
X-RateLimit-Reset: 3600
X-Cost-Limit: $1.00
X-Cost-Used: $0.42
X-Cost-Per-Request: $0.005
X-Upgrade-Url: https://api.example.com/plans
X-Diagnostic-Code: RATE_LIMIT_03
```

### 3.4 成本熔断与硬顶

| 维度 | 公式 | 硬顶示例 |
|------|------|---------|
| 单次请求 | `base_cost + tokens×price` | $0.10 / req |
| 每分钟 | `sum(requests_cost)` | $1.00 / min |
| 每日 | `cumulative_cost` | $50.00 / day |

触发：`daily_cost > quota × 1.2` → 熔断冷却 + 通知财务。

### 3.5 滥用检测

- **流量指纹**：同一 API Key 1 小时内出现在 3+ 国家触发告警；傅里叶变换识别周期性攻击。
- **沙箱行为监控**：定义危险工具链（如 `file.read → http.post`、`db.query → email.send`），建立用户行为基线做异常打分。

## 4. 内部金币（虚拟积分）结算模型建议

### 4.1 兑换比例选择

行业集中在 0.01–0.05 元/积分。草案给的 **10 金币 = 1 元（1 金币 = 0.1 元）** 属于「高面额」档，可行但偏粗。三种取向：

| 比例 | 面额 | 适用性 |
|------|------|--------|
| **10 : 1**（草案） | 1 金币 = 0.1 元 | 心理账户好管理，但微任务需小数金币（0.008 金币） |
| 100 : 1 | 1 金币 = 0.01 元 | 折中，行业常见（腾讯云） |
| 1000 : 1 | 1 金币 = 0.001 元 | 精细、误差小（Coze），但数字大 |

**建议**：若你们希望员工对「每天领了多少、花了多少」有直觉（朝暮偏好直观），**10:1 完全可用**；但扣减内部建议保留 4 位小数避免累积误差。若未来接财务自动分摊、需精细对齐分账，可过渡到 100:1。

### 4.2 金币消耗锚定真实成本（🔴 修正草案估算）

**关键修正**：草案任务分级的「人民币成本」偏高 3–7 倍（用的是原价/旧价）。以下用 **DeepSeek V4 Pro 平时价（3/6 元每百万，永久 2.5 折）** 为锚点重算，并以 **10 金币 = 1 元** 折算金币：

| 任务等级 | Token 量级 | 真实成本（V4 Pro 平时） | **消耗金币（10:1）** |
|---------|-----------|------------------------|---------------------|
| 微型（意图识别/抽取） | ~200 | ~¥0.0008 | 0.008 |
| 小型（一句话问答） | ~750 | ~¥0.003 | 0.03 |
| 标准（普通问答/润色） | ~1,500 | ~¥0.006 | 0.06 |
| 增强（写邮件/小方案） | ~4,000 | ~¥0.015 | 0.15 |
| 复杂（10 页文档/RAG） | ~12,000 | ~¥0.048 | 0.48 |

> ⚠️ **但 Agent 任务不等于单次对话**。带工具调用、多轮、RAG 的 Agent 任务可达普通对话的 **10–1000 倍**（单 Agent 企业级场景平均约 90 次工具调用、100 万 token；智能体工作流可达 60 万 token）。这类任务真实成本几十到上百元，**单任务可能消耗数百金币**。

**因此扣减模型建议（重要）：**

> **不要用「固定任务系数」脱离真实成本去扣金币。** 正确做法是：
> `金币消耗 = 实际 Token 用量 × 该模型实时单价（感知峰谷）× 难度/工具乘数（Agent 任务 3–20×）`
> 并设 **单任务硬上限（建议 500 金币）** 兜底，超出提示「任务过于复杂，请联系管理员」。

这样金币体系既能精确对齐底层成本（避免通胀/贬值），又能用乘数体现 Agent 的额外开销。

### 4.3 三级配额 + 共享池 + 独占配额

| 层级 | 管控内容 | 参考 |
|------|---------|------|
| 企业总池 | 月度总金币上限，全局兜底 | 腾讯云 ClawPro 企业级总控 |
| 部门/项目池 | 按部门/项目分配独立金币池 | 扣子空间/组织维度 |
| 个人配额 | 每日/每月个人上限（独占 + 含共享的上限） | 腾讯云 Key 独占配额 + 配额上限 |

**优先级**：任一层级达上限即阻止消耗。

### 4.4 抵扣顺序

推荐：**每日赠送额度 → 个人购买额度 → 团队共享池**。与百炼「坐席额度→共享包→暂停」同构，用户心智一致。

### 4.5 预警与超额机制

| 阈值 | 触发动作 | 参考 |
|------|---------|------|
| 日额度 70% | 推送「今日免费额度已用 70%，剩余 XX 金币」 | Cursor 支出预警 |
| 日额度 100% | 通知切购买额度或等重置 | — |
| 月累计 80% | 通知部门管理员 | — |
| 月累计 100% | 触发审批流 / 自动拦截 | 阿里云 STAROps 拦截 |

### 4.6 数据看板与成本分摊

- **实时用量**：按部门 / 项目 / 个人 / Agent 类型多维查看。
- **消耗明细**：每笔记录时间、操作人、任务类型、金币变动、余额、说明。
- **成本分账**：按组织、工作空间归属费用，支持「项目 + 资源用量 + 业务贡献」分摊（行业新趋势）。
- **预算 vs 实际**：财务同时看预算执行与实际支出。

## 5. 针对你们平台的落地建议（我们应该怎么做）

### 5.1 供应商与合规（选型红线）
- **DeepSeek V4**：可作为性价比锚点，注意峰谷定价。
- **阿里百炼**：**后端调用必须走「按量付费 / 资源包 / 节省计划」，严禁用 Token Plan 团队版坐席**（ToS 禁止后端自动化）。百炼同样统一账户结算、数据不出境、有 SLA，是合规优选。
- **腾讯云 TokenHub**：若体系内，7 月中旬上线的 DeepSeek-V4 原厂直供是可统一结算的备选。
- 建议做一个**统一接入网关**，把 DeepSeek / 百炼 / 未来模型都收敛到一套「内部 Credits 抽象 + 统一结算」，屏蔽供应商差异。

### 5.2 峰谷定价对冲
- 金币锚定建议**按 DeepSeek 高峰价（输入 6 / 输出 12 元每百万）保守折算**，或平时价折算后**预留 ≥30% 缓冲**，避免峰时毛利被吃。
- 或在产品层做「闲时激励」：非高峰时段金币消耗打 8 折，引导负载均衡。

### 5.3 内部结算中枢架构（参考 Taotoken 思路）
构建「模型资源池化 → 接入标准化 → 成本可视化 → 按项目分摊」的中枢：
1. 所有业务团队通过统一 SDK/网关调用，不直接持供应商 Key。
2. 网关做计量（token、工具调用、模型档位）→ 实时换算金币 → 写 consumption ledger。
3. 财务侧按「部门/项目/个人」出账单，对接内部结算。

### 5.4 多模型统一 Credits 抽象
- 内部只流通「金币」一种单位，底层 DeepSeek/百炼/未来模型的真实价差由网关折算层吸收。
- 模型升级（如从 Flash 切 Pro）对用户只体现为金币扣减变多，不暴露复杂计价。

### 5.5 单任务上限 + 预估提示
- 单任务硬上限（建议 500 金币），超限拦截。
- 任务发起前**显式预估金币消耗**（参考 §3.3 的成本透明头），避免「不知不觉烧光」。

### 5.6 给产品/财务的起步参数建议
- 兑换比例：**10 金币 = 1 元**（高面额、直观），内部 4 位小数记账。
- 每日赠送：**50 金币/人**（=¥5/人/日，≈¥150/人/月）。在真实 DeepSeek 单价下，这足够支撑大量日常对话；但重度 Agent 任务会快速耗尽，正好起到「体验充足 + 成本可控」的平衡。
- 月度池预留 **20–30% 缓冲**应对突发。

## 7. 风险与合规

1. **🔴 百炼 ToS 红线**：后端自动化不可用 Token Plan，务必走按量付费/资源包。
2. **🔴 峰谷定价**：固定金币锚定需按高峰价或加缓冲，否则峰时净成本翻倍吃掉毛利。
3. **金币通胀**：严格锚定现金成本（10:1），不随意增发；AI 模型成本波动快，**每季度复核一次**换算比例。
4. **合规属性**：明确金币是「虚拟记账单位」，避免被认定为具有货币属性引发合规风险。
5. **预留弹性**：预算预留 20–30% 缓冲。
6. **向成果定价演进**：体系预留接口，未来可部分转向「按业务成果」计费（参考 LTM BlueVerse）。
