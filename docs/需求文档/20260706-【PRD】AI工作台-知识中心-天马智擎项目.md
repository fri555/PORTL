# 产品概述

本章节详细描述产品的背景、内容和目标等进行详细定义，关于产品定义的其它内容请阅读本产品定义说明书。

## 产品概述

知识中心是天马智擎 AI 工作台的核心业务入口，定位为集团统一知识库管理与智能问答平台。用户可以在同一页面完成知识库浏览、文档上传、文件预览、权限管理和基于知识库的小智问答。

**内容层级结构（四层固定架构）**：本产品采用「**空间 → 知识库 → 文件夹 → 文件**」四层固定架构，对标钉钉知识库、语雀、Notion、飞书等主流产品的心智模型。

*   **知识库**：一类业务文档的容器（如"集团制度知识库"、"商品手册库"、"项目档案库"），承载权限等治理属性。

*   **文件夹**：知识库内部的一级组织单元，用于对文件做业务维度的二次归类（仅组织作用，不承载权限）。

*   **文件**：业务文档本体（PDF / DOC / DOCX / XLS / XLSX / TXT / MD / CSV 等）。

> **公共空间 / 个人空间为"数据隔离域"**，决定数据归属与可见边界，不作为内容层级出现。组织维度（部门/项目组）通过知识库自身的权限承担，**不在知识库之上再设"空间文件夹"层**，避免抽象冗余和心智负担。

## 产品目标

*   **统一知识入口**：用户可在知识中心切换公共空间/个人空间，并访问对应知识库与文件

*   **文件入库闭环**：用户上传文件后，可看到上传中、处理中、已完成、上传失败、处理失败等状态

*   **智能问答闭环**：用户可基于选定知识库或当前文件提问，答案展示来源引用

*   **权限安全闭环**：用户只能检索、预览、问答有权限访问的知识内容

*   **管理可追溯**：上传、删除、检索、问答、权限变更等关键操作均记录审计日志

## 同类产品/竞品调研(选写)

### 同类产品

1.  **钉钉知识库**

    1.  优势：与 IM、审批、日志、日程等 OA 场景天然集成，组织架构与权限体系接入成本低，适合钉钉生态内的基础知识沉淀。

    2.  不足：AI 问答入口较深、体验偏弱；文件树、版本管理、去重检测、生命周期治理等能力相对基础。

    3.  启示：MVP 阶段需对齐基础上传、检索、问答、文件树能力，并在问答入口、文件格式支持、细粒度文件树交互上形成差异。

2.  **飞书知识空间 / 飞书知识问答**

    1.  优势：RAG 工程能力较强，支持混合检索、Query 改写、重排序、溯源引用、多模型切换；权限与 AI 检索结合较成熟。

    2.  不足：成本较高，依赖企业在飞书生态内已有足够知识沉淀。

    3.  启示：中期应重点对标其“权限前置过滤 + 混合检索 + 溯源问答”链路，逐步建设专业 RAG 能力。

3.  **语雀**

    1.  优势：中文编辑器、目录树、知识库-目录-文档结构体验成熟，代码块、画板、Markdown 排版对研发与知识沉淀友好。

    2.  不足：AI 问答能力迭代较慢，与 IM/OA/审批等业务系统联动弱。

    3.  启示：文件树、目录层级、中文排版和文档组织方式可作为交互参考；天马智擎应以 AI 问答与业务联动形成差异。

4.  **Notion**

    1.  优势：Block 架构灵活，Database 多视图和模板生态成熟，适合个人、小团队和创意协作场景。

    2.  不足：企业级权限治理、本地化、私有化和国内访问稳定性不足。

    3.  启示：长期可参考其灵活信息组织方式，但当前不作为 MVP 主要对标对象。

5.  **Confluence**

    1.  优势：页面树、空间隔离、版本管理、审批链、插件生态成熟，是传统企业 Wiki 标杆。

    2.  不足：体验重、成本高、AI 能力弱，国内访问与本土化存在劣势。

    3.  启示：后续版本可参考其版本管理、审批流、空间治理能力，形成“轻体验 + AI 能力 + 企业治理”的替代价值。

6.  **AI 原生知识库平台（Dify、FastGPT、扣子/Coze、智巢 AI 等）**

    1.  优势：RAG、工作流编排、多模型切换、API 集成能力强，验证了“知识库 + AI 问答”的产品方向。

    2.  不足：多数缺少成熟文件管理、企业级权限、知识治理和精细化前端体验。

    3.  启示：天马智擎应吸收其 RAG 能力，同时补齐公共空间所需的文件树、权限、审计、版本、去重与生命周期管理。

    ### 结论

    *   **MVP 阶段**：对标钉钉知识库，优先完成上传、解析、检索、问答、权限和文件树管理。

    *   **中期阶段**：对标飞书知识问答，补强混合检索、重排序、溯源、权限前置过滤和 RAG 评测。

    *   **长期阶段**：吸收语雀/Confluence 的知识治理能力，以及 AI 原生平台的多模型与工作流能力，形成“AI 原生能力 + 企业级知识治理 + 业务场景集成”的差异化。

**2.层级结构**

> **本产品采用「空间 → 知识库 → 文件夹 → 文件」四层固定架构**。公共空间/个人空间为数据隔离域（决定数据归属和访问边界），不作为内容层级出现。隔离域之外的"组织维度"（部门/项目组）通过知识库自身的**权限**承担，不在层级中增设"空间文件夹"。

```plaintext
空间（公共空间 / 个人空间，仅作为数据隔离域）
 └── 知识库（业务文档容器，如"集团制度知识库"）
      └── 文件夹（知识库内部一级组织单元，仅一级深度）
           └── 文件（PDF / DOCX / MD / TXT / CSV）

说明：
* 空间 = 隔离域（公共空间：全员可见的知识；个人空间：当前用户私有知识）
* 知识库 = 一类业务文档的容器（如"集团制度"、"商品手册"、"项目档案"）
* 文件夹 = 知识库内部的一级组织单元（用于对文件做业务维度的二次归类）
* 文件 = 业务文档本体

```
> **为什么不加"空间文件夹"层？**

> 1. 钉钉/语雀/Notion/飞书等主流产品均采用「知识库-文件夹-文件」三层，加层会破坏用户已有心智。 2. 公共空间下的"集团整体/商品部"等组织维度，可由知识库本身 + 部门权限覆盖，避免抽象冗余。

> 3. 个人空间下的"日常工作/基础知识/个人资料"等用户习惯，可通过收藏知识库 + 个人空间默认收藏夹\*\*实现，不需要再起一层。

| **流程** | **说明** |

**关键规则**：

*   知识库内仅支持一级文件夹

*   同一文件只允许挂在一个位置，不能在树中重复出现

*   文件夹不支持权限设置（权限仅设置在知识库层级）

##### 3.2.4.1.7 补充说明

###### 安全检测

**病毒扫描**：上传至 OSS 后触发云安全服务扫描，阳性直接删除并记录安全日志。

**敏感词检测（上传文件）**：后端解析环节统一执行。采用 AC 自动机（Aho-Corasick）算法，将所有敏感词构建为 Trie 树，扫描文本一遍完成所有匹配，词库量不影响扫描速度。命中敏感词的文件标记为 process_failed（复用处理失败状态），不入库不索引。敏感词词库来源：基础词库采用开源项目（Sensitive-lexicon 等），覆盖涉政、色情、暴恐、广告等类别，后端内置随版本更新。二期支持运营后台自定义词库和豁免白名单管理。

**PII 检测**（二期增强）：解析文本后扫描身份证号、手机号、银行卡号等敏感信息，匹配 PII 的文件标记 `contains_pii=true`。

**格式伪装与加密检测**：

*   上传前前端校验，不进传输流程

*   上传中服务端魔数校验，识别伪装格式

*   加密文件标记 process\_failed

*   单文件最大100MB，后端单次处理最多10个文件

*   同名文件规则：同一知识库内同名自动追加序号 (1)、(2)，不覆盖，通过 SHA256 检测去重

*   解析失败自动重试2次（指数退避），超过则 process\_failed\_permanent

###### 文件清洗规则

**格式归一**：所有文档统一解析为结构化纯文本，保留标题、段落、表格基础结构。PDF依赖OCR（PyMuPDF）提取文本。

**冗余清洗**：自动过滤空白页、页眉页脚、水印、无效重复内容、乱码字符、无意义符号。

**编码统一**：全部转 UTF-8，杜绝解析乱码。

**无效文件过滤**：无有效文本内容的文件不进入向量化流程。

###### 向量化切块规则

**基础参数**：单块默认 512 token，块间 10% 重叠（约51 tokens），避免上下文断裂。

**分格式切块策略**：
- MD/TXT：优先按 H1/H2/H3 标题层级切块，超阈值再按固定 token 拆分
- PDF：按「页 + 段落」组合切块，长页面按段落拆分，保留页码溯源信息
- XLS/XLSX/CSV：按「表头 + 数据行」切块，每块保留表头语义，保证数据完整

**元数据挂载**：所有切块绑定以下字段用于权限过滤与问答溯源：
- fileName：源文件名
- kbId：所属知识库 ID
- space：所属空间
- pageNumber：页码（PDF 适用）
- paragraphIndex：段落序号
- uploader：上传者
- uploadedAt：上传时间

###### 异步消息队列处理

```plaintext
上传 → OSS存储 → 异步入队(topic:file_parse) → Worker池
├── pdf_worker: PyMuPDF逐页提取，书签→标题层级映射
├── docx_worker: python-docx提取，保留排版，层级→Markdown
├── xlsx_worker: openpyxl读取，表头+数据行结构保留
├── csv_worker: csv标准库读取，行结构保留
├── txt_worker: chardet编码探测，UTF-8/GBK/GB2312/ISO-8859-1
└── md_worker: 标题→分块边界，代码块整体保留
    → 清洗（HTML标签移除、多余空白压缩、Base64图片剥离）
    → 分块（滑动窗口 512tokens / overlap 10%）
    → 向量化（Embedding API）
    → 写入向量库

```

##### 3.2.5.1.5 业务规则和约束条件

*   上下文窗口：保留最近5轮对话

*   跨轮指代：支持代词消解

*   持久化：消息自动保存至 `kb_chat_history`，刷新可恢复

*   会话隔离：知识中心问答会话独立留存，与工作台主会话区分，支持在同一会话内持续对话

*   知识库问答只维护当前对话的上下文记忆，不提供新建/切换/删除会话功能

##### 3.2.5.1.6 接口说明

```plaintext
POST /api/knowledge/qa/ask 提问
GET /api/knowledge/qa/stream 流式输出答案
POST /api/knowledge/qa/feedback 反馈有用/无用
DELETE /api/knowledge/qa/clear 清空当前对话
GET /api/knowledge/qa/history 获取历史消息

```

##### 3.2.5.1.7 补充说明

**安全检测**：上传文件侧：后端解析环节统一执行，采用 AC 自动机匹配敏感词词库，命中标记为 process_failed。提问侧：依赖大模型原生风控，不做自定义敏感拦截。 Prompt 注入（模式匹配）。命中敏感词直接拒答并写入审计。命中 Prompt 注入则返回安全提示。

**RAG 链路**：

```plaintext
用户输入 → Query改写/意图识别 → Embedding检索(TOP-K) → 精排ReRank → 
阈值过滤 → Prompt构造(引用+上下文+问题) → LLM生成 → 内容过滤 → 展示

```

#### 3.2.5.2 溯源引用与预览联动

##### 3.2.5.2.1 功能需求描述

| EARS 模式 | 需求描述 |
| --- | --- |
| 普遍型 | \* 系统应在小智回答中使用 `[[ref:N]]` 标记引用来源，关联的引用来源在答案下方以卡片形式展示。<br>\* 系统应支持引用来源点击跳转：打开源文件预览并高亮对应大纲章节。 |

| 事件驱动型 | \* 当用户点击引用卡片上的来源序号时，系统应跳转到对应文档章节。<br>\* 当用户点击引用卡片上的引用序号（上标数字）时，系统应打开源文件预览标签。<br>\* 高亮持续3秒后自动消除。 |
