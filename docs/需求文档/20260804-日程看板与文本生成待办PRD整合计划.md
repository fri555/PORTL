## 3. 整合策略（推荐：主从 + 内联 / 方案C）

- 以**本地日程看板 PRD 为主文档**（保留 M1–M4 不变）。
- 将远程"文本生成待办"作为 **M5 的内联详规**吸纳（M1 提取 / M2 候选编辑 / M3 批量创建 + 状态/并发规则 + 提取提示词）。
- 远程文档**改名归档**为历史版本，不再以"日程看板"标题存在。
- 不选方案B（完全合并单PRD）：会破坏"日历浏览产品"与"待办创建能力"的边界，MVP 范围变模糊、文档变重。

## 4. 输入范围决策：会议笔记 + 自由文本（统一入口）

待办提取能力同时支持两个入口，共用同一套候选管理与编辑（M2）+ 批量创建（M3）+ 提取提示词：

- **入口A｜会议笔记**：M4 会议笔记工作区内的"AI 提取待办"，承接已保存笔记（绑定日程编号）。
- **入口B｜自由文本**：独立文本输入框 / 弹窗，粘贴或输入任意文本（无日程绑定）。
- 两者差异仅在"提取输入来源"：笔记来源绑定 `schedule_id`；自由文本来源为空，由用户在候选上手动补执行人/时间。
