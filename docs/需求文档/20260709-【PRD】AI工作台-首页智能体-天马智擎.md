# 2. 产品概述

## 2.1 产品定位
AI 工作门户首页智能体是面向企业普通员工的一站式 AI 协作入口。用户进入首页后，可在「日常办公模式」下通过 web-search + RAG 快速获取答案并落地为钉钉动作，或在「专家模式」下选择预置专家进行 plan-and-execute 结构化协作。产品以三栏布局为骨架（输入框为焦点，左右栏默认收起），先做功能闭环、再逐步增强。

## 2.2 产品目标

1. **降低 AI 使用门槛**：普通员工无需了解模型/函数/MCP 等底层概念，即可通过自然语言完成日常工作与专家协作。
2. **打通"问→答→落地"闭环**：日常办公模式从检索到生成到钉钉动作落地，形成端到端可用链路。
3. **专家能力开箱即用**：预置 10 位专家覆盖选品/导购/履约/营销/售后/数据/B2B/直播/投放/竞对场景，用户选择即协作。

## 2.3 用户角色

| 角色 | 说明 | MVP 范围 |
| --- | --- | --- |
| 普通员工 | 通过 SSO 登录使用首页智能体的企业员工，可使用日常办公模式与专家模式 | ✅ 唯一角色 |
| 管理员 | 在后台配置模型/函数/MCP/技能的管理人员，不通过前端首页操作 | 后台界面不在本 PRD 范围 |

### 2.4.1 竞品参考

| 分类 | 竞品 | 核心特征 | 与我方的关系 |

| 通用 AI 助手型 | Kimi（月之暗面） | 200 万字超长上下文，13 个场景提示词 + 19 套常用语模板，Kimi+ 智能体侧边栏选择 | 提示词策略与专家展示参考 |

### 2.4.2 差异化定位

| 差异化机会 | 行业现状 | 我方设计 |
| --- | --- | --- |
| 两模式统一入口 | 各产品要么单一模式、要么多 Agent 分散 | 日常办公 + 专家模式在同一首页 Tab 切换 |
| AI-first 工 | 钉钉/飞书 AI 为附属功能，Kimi 为纯对话页 | 首页以 AI 智能体为核心，输入框为焦点 |
| 专家 Hover/C | 各产品专家/智能体均为单一交互 | Hover 看简介，Click 展开提示词案例库进入协作（详见 3.5.8） |
| web-search | Kimi 有联网搜索，钉钉有知识库，但少有融合 | 检索路由自动判断公开/时效信息走 web-search，企业私有知识走 RAG |
| 钉钉动作落地 | 钉钉 AI 助理原生支持，其他产品不具备 | 日常办公模式答案可落地为钉钉待办/审批/通知 |

### 2.4.3 竞品调研结论

**MVP 阶段定位**：对标钉钉 AI 助理的能力覆盖度（日常办公 + 专家协作），参考飞书智能伙伴的入口设计（顶部输入框为焦点），借鉴 Coze 的项目式多 Agent 协作能力（plan-and-execute 专家编排）。核心差异化策略：① 两模式统一入口（日常+专家在同一首页 Tab 切换）；② web-search + RAG 融合检索；③ 答案落地为钉钉动作（待办/审批/通知）；④ 专家 Hover/Click 区分交互。合规警示：避免过度拟人化（参考《人工智能拟人化互动服务管理暂行办法》对通义千问/豆包 C 端智能体的下线影响）。

本节定义跨模块的通用行为规范，各功能模块默认遵循此约定，特殊场景在模块内单独说明。

### 3.1.1 模式切换

| 规则项 | 说明 |
| --- | --- |
| 可选模式 | 日常办公模式 / 专家模式 |
| 默认模式 | 日常办公模式 |
| 模式与会话绑定 | 一个会话绑定一种模式，创建后不可变更；切换模式 = 切换到对应模式的最近活跃会话（无则新建一个绑定该模式的空白会话） |

| 切换方式 | 用户手动切换，不做自动意图识别与模式自动路由 |

### 3.1.2 对话交互规范

| 规则项 | 说明 |
| --- | --- |
| 输入方式 | 多行输入，Enter 发送 / Shift+Enter 换行 |
| 发送控件 | 有内容时高亮可点击，无内容时置灰；生成中替换为停止控件 |
| 附件上传 | 输入区内提供附件上传入口，格式与大小约束见 3.1.4 |

| 安全检测 | 对话输入做敏感词与 Prompt 注入检测，命中即拦截 |

| 场景 | 状态 | 处理方式 |

### 3.1.4 文件上传约束

| 约束项 | 限制值 | 校验位置 | 拦截行为 |
| --- | --- | --- | --- |
| 文件数量上限 | 单次最多 50 个 | 前端 | 拦截超出部分，提示「最多上传 50 个文件」 |
| 单文件大小 | ≤ 50MB | 前端 | 拦截该文件，提示「文件超过 50MB 限制」 |
| 格式白名单 | pdf、doc、docx、txt、md、xlsx、xls、csv | 前端 | 拦截该文件，提示支持格式列表 |
| 空文件（0 字节） | 不允许 | 前端 | 拦截该文件，标注「空文件」 |
| 格式伪装 | 扩展名与文件头不匹配 | 服务端 | 上传完成后标记「上传失败」 |
| 加密文件 | 文件已加密无法解析 | 服务端 | 解析阶段标记「处理失败」 |

> 前端校验顺序：扩展名 → 文件大小 → 空文件。逐项校验，首个不通过的项即拦截并提示。

| XLS | `.xls` | ✅ | ✅ 提取单元格文本 | ✅ HTML 表格渲染 | ✅ Sheet 名称列表 | P0 |

### 3.1.6 跨模块异常处理通用规则

每个功能模块的异常处理均须覆盖以下五类场景（模块内可补充特有异常）：

| 异常类型 | 通用处理 |
| --- | --- |
| 网络断连重试 | 请求失败自动重试，仍失败提示用户并保留当前状态 |
| 数据为空状态 | 展示空态提示与引导操作，不展示空面板 |
| 加载中骨架屏 | 列表/面板/预览加载先展示骨架屏或占位动效 |
| 输入非法字符 | 空内容禁止提交；超长截断并提示；特殊字符按模块规则拦截 |
| 文件产物类型 | AI 生成文件产物支持 md / docx / xlsx / pptx / pdf 五种格式，均可预览和下载 |
| 并发操作冲突 | 快速反复操作以最后一次状态为准；生成中再次发送被忽略或排队 |

### 3.1.7 搜索规则

| 规则项 | 说明 |
| --- | --- |
| 触发方式 | 输入后 300ms 防抖触发搜索，不依赖 Enter 键 |
| 匹配逻辑 | 左右模糊匹配（包含关键词即可），不区分大小写 |
| 搜索范围 | 历史会话：按会话标题匹配；会话内不支持消息正文全文搜索（见 5.2 Non-goals） |

### 3.4.2 模型管理

> 模型管理为智能体提供「思考能力」——管理员在后台注册模型端点、配置降级链和配额，智能体运行时通过网关调用模型。

#### ① 功能需求描述

| EARS 模式 | 需求描述 |
| --- | --- |
| 普遍型 | 系统应支持管理员在后台注册多个模型端点，配置路由策略与降级规则 |
| 状态驱动型 | 当主模型端点不可用时，系统应自动降级到备用端点并记录告警日志 |
| 事件驱动型 | 当智能体请求模型时，系统应按路由策略选择端点发起请求 |
| 不良行为型 | 当所有端点均不可用时，系统应返回降级提示而非直接报错；API Key 过期或配额耗尽时自动降级并触发告警 |

#### ② 业务主流程图及说明

模型生命周期状态机（草稿 → 已启用 → 已禁用 → 已归档）：

```mermaid
stateDiagram-v2
    [*] --> 草稿
    草稿 --> 已启用 : 启用（必填完整 + 连通性测试通过）
    草稿 --> (已删除) : 删除（仅草稿，输入显示名二次确认）
    已启用 --> 已禁用 : 禁用（影响分析 + 原因）
    已禁用 --> 已启用 : 启用（自动重测连通性）
    已禁用 --> 已归档 : 归档（影响分析 + 原因）
    已归档 --> 草稿 : 恢复为草稿（仅平台管理员 + 原因）
    (已删除) --> [*]
    已归档 --> [*]
```

**状态转换规则**：

| 转换 | 触发操作 | 前置条件 | 校验失败提示 | 后置行为 |
|------|---------|---------|------------|---------|
| 草稿 → 已启用 | 启用 | 必填项完整 + 连通性测试通过 | "必填项未填写完整：{字段列表}"；"连通性测试失败：{错误信息}" | 加入智能体可引用列表 |
| 草稿 → 已删除 | 删除 | 输入显示名二次确认匹配 | "请正确输入模型显示名" | 物理删除，不可恢复 |
| 已启用 → 已禁用 | 禁用 | 展示被引用智能体列表 + 填写禁用原因（5-200字）+ 勾选"已通知负责人" | "请填写禁用原因"；"请确认已通知以上负责人" | 引用智能体自动走降级链 |
| 已禁用 → 已启用 | 启用 | 自动重测连通性 | "连通性测试失败：{错误信息}" | 恢复可用 |
| 已禁用 → 已归档 | 归档 | 展示被引用方 + 填写归档原因（5-200字） | "请填写归档原因" | 从可引用列表移除；引用方详情页标红"7天内迁移" |
| 已归档 → 草稿 | 恢复为草稿 | 仅平台管理员 + 填写恢复原因（5-200字） | "无权限操作"；"请填写恢复原因" | 恢复为草稿，需重新启用才能上线 |

**连通性状态**（独立于启用状态，由定时探测维护）：

- 在线：最近 ping 成功
- 离线：连续 3 次 ping 失败
- 未知：从未 ping 过

#### ③ 界面原型

> MVP 不设计独立前端页面，模型管理通过统一管理后台入口完成。此处仅说明操作逻辑，UI 设计另见管理后台 PRD。

- 管理员可在后台注册模型，填写提供方、模型 ID、API Key、成本中心、能力声明等配置
- 管理员可对模型执行启用/禁用/归档/恢复/删除操作
- 禁用/归档时系统强制展示引用该模型的智能体列表，管理员须填写原因并确认已通知负责人
- 管理员可查看模型调用日志（含降级轨迹）和成本报表
- 管理员可配置模型的降级链（主备两段式）和配额（QPS/日 Token/月 Token）
- 管理员可执行连通性测试，查看历史 ping 记录

#### ⑤ 业务规则和约束条件

**场景假设**：

| 假设 | 说明 | 复盘点 |
|------|------|--------|
| 单网关 | 所有模型调用必经网关 | 特殊场景需旁路时重构 |
| 密钥加密 | API Key 保存时加密 | 合规要求更高需密钥管理服务 |
| 配额硬超限 | 100% 阻断，返回配额耗尽错误 | 用户接受度低可改软告警 |
| 成本中心必填 | 注册时必填成本中心 | 无成本中心体系需调整 |
| 缓存仅确定性请求 | 仅 temperature=0 缓存 | 需语义缓存时引入向量 |
| 模型负责人=创建人 | 创建人即负责人，MVP 不支持转移 | 未来需角色矩阵 |
| 仅草稿可删 | 已启用模型只能禁用/归档 | 防止误删历史 |

**CRUD 规则**：

| 操作 | 可见性 | 规则 | 校验要点 | 错误提示 |

| 启用（草稿→已启用） | 前置：必填项完整 + 连通性测试通过；成功后自动更新连通性状态 |
| 启用（已禁用→已启用） | 前置：自动重测连通性 |
| 禁用（已启用→已禁用） | **强制展示被引用智能体列表**（名称/版本/负责人/24h调用数）+ 填写原因（5-200字）+ **必勾选**"已通知负责人"；确认后引用方自动走降级链 |
| 归档（已禁用→已归档） | 同禁用弹窗（措辞改为归档）；归档后从所有智能体工具选择器移除；引用方详情页标红"7天内迁移" |
| 恢复（已归档→草稿） | **仅平台管理员**；填写恢复原因（5-200字）；恢复后状态=草稿，需重新启用 |
| 批量操作 | 仅平台管理员可批量；支持批量启用/禁用/归档/删除（仅草稿）；弹窗说明"将对{N}个模型执行此操作" |

**降级链规则**：

| 规则项 | 说明 |
|------|------|
| 范围 | MVP 仅支持主备两段式，每个模型最多 1 个备选 |
| 触发条件 | 5xx 错误 / 超时 / 429 限流 / 余额不足 |
| 不触发条件 | 4xx 错误、上下文超长、内容审查拦截 |
| 备选也失败 | 返回"主备模型均失败"错误 |
| 切换延迟 | 100-10000ms 可配置 |

**连通性规则**：

| 规则项 | 说明 |
|------|------|
| 测试触发 | 仅在"保存并启用"或详情页"重新探测"时触发；草稿保存不触发 |
| 测试超时 | ≤5 秒 |
| 连通性独立 | 在线/离线/未知独立于启用状态；离线不影响已启用状态展示 |
| 状态变更审计 | 所有启用/禁用/归档/恢复/删除须记录操作人、时间、原因 |

#### 3.4.2.2 Prompt 管理

##### 功能需求描述

Prompt 是输入给 LLM 的指令文本，分两类：

- **System Prompt（系统提示词）**：角色约束、工具调用规则、输出格式、安全约束。属于 Agent 配置项，随 Agent 生命周期管理（详见 3.4.5 与《智能体管理》）；平台另提供「Prompt 模板库」作为可复用资产，支持独立注册/发布/归档。
- **User Prompt（用户提示词）**：用户在前端输入框中下发的业务任务（如「帮我分析上周的销售数据」）。它是用户自由输入的内容，平台不进入后台治理、无法也不应对其内容做限制，仅做输入端的安全检测（模型自带敏感词检测 / Prompt 注入拦截，见 3.1.2）。

| EARS 模式 | 需求描述 |
| --- | --- |
| 普遍型 | 系统应支持管理员在后台为每个 Agent 配置 System Prompt（含角色定义、工具调用规则、安全约束），并提供 Prompt 模板库作为可复用资产；User Prompt 由用户在前端输入，前端不可见 System Prompt 原文。 |
| 状态驱动型 | 当 Agent 发布时，系统应将绑定的 System Prompt 加载到引擎。 |
| 事件驱动型 | 当用户发送消息时，系统应将 System Prompt + User Prompt 组合送入 LLM 推理。 |
| 不良行为型 | 系统不应向普通员工暴露 System Prompt 原文；Prompt 注入检测命中时拦截并拒绝。 |

##### 业务主流程图及说明

System Prompt 模板库状态机（草稿 → 已发布 → 已归档）：

```mermaid
stateDiagram-v2
    [*] --> 草稿
    草稿 --> 已发布 : 发布（校验变量占位符闭合）
    草稿 --> (已删除) : 删除（仅草稿，二次确认）
    已发布 --> 草稿 : 编辑（生成新草稿）
    已发布 --> 已归档 : 归档
    已归档 --> 草稿 : 恢复为草稿（仅管理员）
    (已删除) --> [*]
    已归档 --> [*]
```

说明：User Prompt 无状态机（用户自由输入，不治理）；Agent 内 System Prompt 随 Agent 生命周期（草稿→已发布→已归档）管理，不单独建状态。

##### 界面原型

无独立界面（普通员工前端不可见）；管理后台可对已启用工具的调用规范做注册与查看（可选）。

##### 数据说明（业务实体）

| 实体 | 关键字段 | 说明 |
| --- | --- | --- |
| AgentSystemPrompt | AgentID/角色定义/工具调用规则/安全约束/指令列表 | 随 Agent 配置存储 |
| PromptTemplate | 名称/类型(System·User·片段)/内容/适用模型/标签/状态 | 平台可复用模板库 |

##### 业务规则和约束条件

| 规则项 | 说明 |
| --- | --- |
| System Prompt 治理 | 随 Agent 生命周期管理；模板库独立 CRUD（仅草稿可删） |
| User Prompt 不治理 | 用户输入内容不进入后台、无法限制；仅做输入安全检测 |
| 变量占位符 | 保存时校验 `{{变量}}` 引用合法性；发布前校验闭合 |
| 可见性 | 普通员工前端不可见 System Prompt 原文 |

##### 接口说明

| 接口 | 说明 |
| --- | --- |
| listPromptTemplates / createPromptTemplate / updatePromptTemplate | 模板列表/创建/编辑 |
| publishPromptTemplate / archivePromptTemplate / deletePromptTemplate | 发布/归档/删除 |
| copyPromptToAgent | 复制到 Agent 配置 |

#### 3.4.2.3 工具调用

##### 功能需求描述

工具调用是 LLM 在 Prompt 约束下输出的标准化 JSON 调用指令（含工具名称、入参），是决策层的产出物而非执行框架。模型只输出调用意图，本身不执行代码、网络请求、文件操作；实际执行由 MCP 完成。

| EARS 模式 | 需求描述 |
| --- | --- |
| 普遍型 | LLM 应在 Prompt 约束下输出标准 JSON 格式的工具调用指令（工具名+入参）。 |
| 状态驱动型 | 当工具不可用时，Agent 调度器应跳过该工具调用并提示。 |
| 事件驱动型 | Agent 调度器接收工具调用指令后，按 Skill 类型（只读/写入）决定是否需人工确认，再通过 MCP 执行。 |
| 不良行为型 | 越权调用应拒绝执行并记录安全告警。 |

##### 业务主流程图及说明

工具调用运行时契约流程（非实体，无状态机）：

```mermaid
flowchart TD
    A["LLM 输出工具调用意图<br/>标准 JSON：工具名 + 入参"] --> B{"入参 Schema 校验"}
    B -->|"不通过"| C["拒绝并返回错误<br/>提示参数不符合规范"]
    B -->|"通过"| D{"越权判定<br/>可执行 / 需确认 / 禁止"}
    D -->|"禁止"| E["拒绝执行 + 安全告警"]
    D -->|"需确认"| F["走安全审批三段式<br/>沙箱模拟→预览→确认"]
    D -->|"可执行"| G["经 MCP 执行"]
    G --> H["记录 ToolCallLog（审计）"]
```

说明：工具调用不是可实例化的实体资产，而是「调用契约」。其治理对象为**工具调用规范（ToolCall Spec）**——每个被授权调用的工具，其入参 Schema、必填项、越权判定规则在后台注册并可审计；运行时对 LLM 输出的调用意图做 Schema 校验与越权拦截。规范注册为可选治理增强，MVP 可仅做运行时校验。

##### 界面原型

无独立界面（普通员工前端不可见）；管理后台可对已启用工具的调用规范做注册与查看（可选）。

##### 数据说明（业务实体）

| 实体 | 关键字段 | 说明 |
| --- | --- | --- |
| ToolCallSpec | 绑定工具/入参Schema/必填参数/越权判定规则/示例调用/状态 | 调用规范（可选治理） |
| ToolCallLog | 工具名/入参摘要/Schema校验结果/越权判定/执行结果/耗时 | 每次调用意图运行时落库，供审计与评估 |

##### 业务规则和约束条件

| 规则项 | 说明 |
| --- | --- |
| 仅输出意图 | 模型只输出 JSON 调用意图，不执行；执行由 MCP 完成 |
| Schema 校验 | 运行时对入参做 Schema 校验，不通过则拒绝 |
| 越权拦截 | 按工具声明（可执行/需确认/禁止）判定；需确认走安全审批；禁止项拒绝并记录安全告警 |
| 不可用跳过 | 工具不可用时调度器跳过并提示 |
| 审计 | 每次调用意图落 ToolCallLog |

##### 接口说明

| 接口 | 说明 |
| --- | --- |
| registerToolCallSpec / updateToolCallSpec | 注册/更新调用规范 |
| validateToolCall | 运行时入参校验与越权判定 |
| listToolCallSpecs / offlineToolCallSpec | 规范列表/下线（工具禁用时级联） |
| getToolCallLog | 调用日志查询 |

##### 补充说明

示例：`{"name":"git_commit","arguments":{"message":"新增100MB文件校验"}}`——仅为调用意图，实际执行由 MCP 完成。

#### 3.4.2.4 思维链（CoT）

### 3.4.3 MCP Server

> MCP Server 为智能体提供「外部服务接入能力」——通过标准协议接入外部服务，将外部能力封装为 Tool 供智能体调用。管理员注册后需经连接探测方可启用。

#### ① 功能需求描述

MCP Server 通过标准协议接入，对外暴露原子 Tool。管理员注册后需经连接探测（连通性 + 协议兼容 + 至少声明 1 个 Tool）方可启用。

| EARS 模式 | 需求描述 |
| --- | --- |
| 普遍型 | 系统应支持管理员注册 MCP Server，将其 Tool 接口注册到工具调用框架 |
| 状态驱动型 | 当 MCP Server 连接异常时，标记该 Server 的 Tool 为不可用并记录告警 |
| 事件驱动型 | 当智能体调用 Tool 时，经工具调用框架统一调度 MCP Server 执行 |
| 不良行为型 | MCP Server 返回异常数据时拦截并降级处理，不传递给用户 |

#### ② 业务主流程图及说明

MCP Server 生命周期状态机：

```mermaid
stateDiagram-v2
    [*] --> 草稿
    草稿 --> 已启用 : 启用（必填完整 + 连接探测成功）
    草稿 --> (已删除) : 删除（仅草稿，输入 slug 二次确认）
    已启用 --> 已禁用 : 禁用（强制展示被引用方 + 填原因）
    已禁用 --> 已启用 : 启用
    已禁用 --> 已归档 : 归档（强制展示被引用方 + 填原因）
    已归档 --> 草稿 : 恢复为草稿（仅平台管理员 + 填原因）
    (已删除) --> [*]
    已归档 --> [*]
```

**状态转换规则**：

| 转换 | 触发操作 | 前置条件 | 校验失败提示 | 后置行为 |
|------|---------|---------|------------|---------|
| 草稿 → 已启用 | 启用 | 必填项完整 + 连接探测成功 | "连接探测失败：{错误信息}" | 加入智能体工具选择器 |
| 草稿 → 已删除 | 删除 | 输入 slug 二次确认匹配 | "请正确输入 slug" | 物理删除 |
| 已启用 → 已禁用 | 禁用 | 强制展示被引用方 + 填写禁用原因（5-200字） | "请填写禁用原因" | 引用智能体调用报错"工具已禁用" |
| 已禁用 → 已启用 | 启用 | — | — | 恢复可用 |
| 已禁用 → 已归档 | 归档 | 强制展示被引用方 + 填写归档原因（5-200字） | "请填写归档原因" | 从工具选择器移除 |
| 已归档 → 草稿 | 恢复为草稿 | 仅平台管理员 + 填写恢复原因（5-200字） | "无权限操作" | 恢复为草稿，需重新启用 |

**探测规则**：
- 探测时机：仅在"保存并启用"或详情页"重新探测"时触发；草稿保存不探测
- 探测内容：连接可达性 + 协议兼容性 + 至少声明 1 个 Tool
- 探测超时：≤5 秒
- 错误分类：CONNECTION_FAILED / INVALID_SPEC / NO_TOOLS_DECLARED / AUTH_FAILED

#### ③ 界面原型

> MVP 不设计独立前端页面，MCP Server 通过统一管理后台入口完成。此处仅说明操作逻辑。

- 管理员可在后台注册 MCP Server，填写 slug、名称、传输方式（stdio/sse/streamable-http）、连接配置
- 管理员可对 MCP Server 执行启用/禁用/归档/恢复/删除操作
- 注册时"保存并启用"触发连接探测，探测失败自动保存为草稿
- 禁用/归档时系统强制展示引用该 Server 的智能体列表
- 管理员可在详情页查看其声明的 Tools/Resources/Prompts

### 3.4.4 原子 Tool

> 原子 Tool 为智能体提供「最小执行单元」——一个 Tool 只做单一动作（读文件、计算哈希、语义检索等）。内置工具由平台代码自带，管理员通过发现页纳管；远程 API 类 Tool 随 MCP Server 注册自动纳管。

#### ① 功能需求描述

Tool 是最小粒度执行单元，两种实现：① 本地函数（平台代码自带，内置工具）② 远程 API 调用（经 MCP）。所有 Tool 统一注册在工具调用框架中，按 `tool.type` 区分 builtin / mcp / skill。

| EARS 模式 | 需求描述 |
| --- | --- |
| 普遍型 | 系统应以 Tool 为最小粒度执行单元，支持本地函数与远程 API 两类实现，统一在工具调用框架注册与调度 |
| 状态驱动型 | 当 Tool 连接异常时，标记该 Tool 为不可用并记录告警 |
| 事件驱动型 | 当智能体调用 Tool 时，经工具调用框架统一调度执行 |
| 不良行为型 | Tool 返回异常数据时拦截并降级处理，不传递给用户 |

### 3.4.5 Skill

> Skill 为智能体提供「业务编排能力」——由多个 Tool + 条件判断 + 业务流程编排而成，以标准化 .skillpkg 包交付。Skill 分只读（自动执行）和写入（需三段式安全审批）两类。

#### ① 功能需求描述

**只读 Skill 与写入 Skill**：

| 类型 | 定义 | 示例 | 执行方式 |
|------|------|------|---------|
| 只读 Skill | 查询、读取、预览类操作，不产生副作用 | 知识库问答、文件搜索、数据报表查询 | Agent 自动调用，无需人工确认 |
| 写入 Skill | 修改、创建、删除类操作，产生持久化变更 | 文件入库、Git 提交、钉钉待办创建 | 必须「沙箱模拟 → 预览 → 确认 → 正式执行」三段式 |

**Skill 包规范（.skillpkg）**：
```
{skill-name}.skillpkg
├── manifest.json    # 元数据：name/slug/version/description/capabilities
├── code/            # 执行逻辑
├── resources/       # 模板/规则文件
└── README.md        # 使用说明
```
- 文件大小 ≤ 50MB
- manifest.json 中的 slug 全局唯一，版本号由包内定义不可手动修改

| EARS 模式 | 需求描述 |
| --- | --- |
| 普遍型 | 系统应支持管理员上传/创建 Skill（Tool 编排 + 安全策略配置 + 版本管理）；专家与快捷指令通过绑定 Skill 获得能力 |
| 状态驱动型 | 当 Skill 绑定的 Tool/MCP 不可用时，标记该 Skill 为降级状态 |
| 事件驱动型 | 写入 Skill 执行时强制走三段式审批流；只读 Skill 直接执行 |
| 不良行为型 | 不向普通员工暴露 Skill 配置细节（Tool 编排逻辑、安全策略） |

### 3.4.6 智能体 Agent

> 智能体是前面所有能力模块（模型、Prompt、工具、知识库、记忆）的编排组合。Agent 配置即是对这些能力的消费——选择模型、绑定工具、编写系统提示词、挂载知识库，最终发布为面向用户的可用服务。

#### ① 功能需求描述

**Agent 完整公式**：`Agent = LLM + Prompt 配置 + 记忆体系 + 工具调用调度 + MCP 工具池 + 沙箱环境 + 安全审批控制器`

**记忆体系**（MVP 落地前两层，长期为后续迭代）：

| 记忆类型 | 定位 | 载体 | 阶段 |
|------|------|------|------|
| 瞬时记忆 | 当前 Session 上下文窗口，受 memoryWindow 约束（默认 5 轮） | LLM Token 窗口 | MVP |
| 短期记忆 | 跨会话语义召回：会话结束→摘要→文本切片+向量嵌入→LanceDB→新会话语义匹配召回 | LanceDB 向量库 | MVP |
| 长期记忆 | 跨会话实体关系：存储实体、关系、项目约束，支持多跳推理 | Graphiti 图谱 | 后续迭代 |

**沙箱环境**：Agent 执行手脚的隔离环境。写入类 Skill 先在沙箱模拟执行，人工确认后再正式执行。

| EARS 模式 | 需求描述 |
| --- | --- |
| 普遍型 | 系统应支持管理员创建 Agent，配置模型/Prompt/工具/知识库/记忆窗口，按三态生命周期管理。Agent 对普通员工不可见，员工仅通过「专家」「快捷指令」间接使用。 |
| 状态驱动型 | 草稿/已归档状态对前端不可调用；已发布 Agent 详情页展示评估趋势与调用统计。 |
| 事件驱动型 | Agent 发布后刷新前端可调用列表；归档后终端不可调用。 |
| 不良行为型 | 不向普通员工暴露 Agent 后台配置（Prompt 原文/工具绑定/知识库）；引用模型/工具被禁用时阻断发布。 |

#### ② 业务主流程图及说明

Agent 生命周期状态机：

```mermaid
stateDiagram-v2
    [*] --> 草稿
    草稿 --> 已发布 : 发布（生成新版本号）
    草稿 --> (已删除) : 删除（仅草稿）
    已发布 --> 已发布 : 回滚（选历史版本，生成新版本号）
    已发布 --> 已归档 : 归档
    已归档 --> 草稿 : 恢复为草稿（仅平台管理员）
    (已删除) --> [*]
    已归档 --> [*]
```

**状态转换规则**：

| 转换 | 触发操作 | 前置条件 | 校验失败提示 | 后置行为 |
|------|---------|---------|------------|---------|
| 草稿 → 已发布 | 发布 | 必填项完整 + 主模型已启用 + 所有绑定工具已启用 + 填写变更说明（5-200字） | "必填项未填写完整：{字段列表}"；"模型{名称}已禁用，请更换"；"工具{名称}已禁用，请先启用或移除"；"请输入变更说明（5-200字）" | 生成新版本号（minor+1），旧已发布版本自动归档，异步通知引擎加载 |
| 草稿 → 已删除 | 删除 | 输入名称二次确认匹配 | "请正确输入智能体名称" | 物理删除，不可恢复 |
| 已发布 → 已发布（回滚） | 回滚 | 选历史版本 + 填写回滚原因（5-200字） | "目标版本不存在"；"请填写回滚原因（5-200字）" | 生成新版本号（minor+1），格式"v{x.y}（回滚自 v{目标版本}）"；异步通知引擎加载；目标版本中模型/工具已禁用时警告但不阻断 |
| 已发布 → 已归档 | 归档 | 勾选确认 | — | 终端不可调用 |
| 已归档 → 草稿 | 恢复为草稿 | 仅平台管理员 + 填写恢复原因（5-200字） | "无权限操作" | 创建新草稿，版本显示为"原版本+0.1-draft"，需重新发布才能上线 |

#### ③ 界面原型

> MVP 不设计独立前端页面，智能体 Agent 通过统一管理后台入口完成。此处仅说明操作逻辑，UI 设计另见管理后台 PRD。

- 管理员可在后台创建 Agent，填写名称/分类/角色/模型/系统提示词/工具/知识库等配置
- 管理员可编辑 Agent（草稿直接编辑；已发布编辑→生成新草稿，原版本继续可用）
- 管理员可发布 Agent（校验必填项、模型启用状态、工具启用状态），发布时填写变更说明
- 管理员可回滚 Agent 到历史版本（选目标版本→填写原因→生成新版本号）
- 管理员可归档/删除/恢复 Agent（归档后终端不可调用；仅草稿可删；仅管理员可恢复）
- 管理员可在草稿状态下试运行调试（与正式调用隔离）
- 管理员可查看 Agent 调用统计（24h 调用量/成功率/平均延迟/预估成本）

### 3.4.7 智能评估

> 智能评估为智能体提供「质量保障」——管理员创建评估数据集、发起评估任务、查看报告，在发布前获取客观质量数据。

#### ① 功能需求描述

智能评估是跨层质量保障能力，对模型质量、Tool 可用性、Agent 端到端表现提供统一的数据集、评估任务与报告反馈。

| 概念 | 说明 |
|------|------|
| 评估数据集 | 一组「输入-期望输出-评分标准」的测试用例集合，支持草稿/已发布/已归档三态 |
| 评估指标 | 7 维度：准确性、有用性、安全性、格式合规、延迟、成本、引文准确 |
| 评估任务 | 指定评估对象（Agent/模型/Tool）+ 数据集 + 指标 → 异步执行 → 生成报告 |
| 评估报告 | 整体得分 + 各维度得分 + 样本详情 + 与历史对比 |

| EARS 模式 | 需求描述 |
| --- | --- |
| 普遍型 | 系统应支持管理员创建评估数据集、配置评估指标、对评估对象发起评估任务并生成报告 |
| 状态驱动型 | 当 Agent 已发布时，详情页展示评估趋势；当评估任务执行中，展示进度 |
| 事件驱动型 | Agent 发布前推荐执行评估（不强制阻断）；评估完成后更新报告并通知 |
| 不良行为型 | 评估任务失败不影响评估对象的正常调用 |

### 3.4.8 额度管理与成本归因

> 额度管理为智能体提供「成本可控」保障——防止单用户/单 Agent 过度消耗导致成本失控。**MVP 聚焦个人级配额**，部门级和企业级为后续迭代。

#### ① 功能需求描述

| 模式 | 描述 |
| --- | --- |
| 普遍型 | 系统应支持管理员为每个用户配置金币日额度、金币月额度、单任务金币上限、请求限速和 Token 安全天花板；系统应记录每笔模型调用的 Token 消耗、金币变动与成本（含峰谷）。 |
| 状态驱动型 | 当用户配额消耗达 70%/90% 时，系统应发送对应级别告警；当消耗达 100% 时，系统应拦截调用并返回配额耗尽错误。 |
| 事件驱动型 | 每次模型调用完成后，系统应更新用户配额计数器；每日/每月 0:00 自动重置对应周期配额。 |
| 不良行为型 | 配额统计数据延迟不超过 5 秒；重置操作失败时保留当前计数器不变并告警。 |

#### ② 业务主流程图及说明

额度消耗流程：用户使用智能体 → 模型调用完成 → 扣除金币 → 更新配额计数器 → 检查是否超限。

**预警与超限行为**：

| 用量区间 | 行为 | 告警方式 |
|------|------|---------|
| 0–70% | 正常调用 | 无 |
| 70–90% | 正常调用 | 站内信黄色告警 |
| 90–100% | 正常调用 | 站内信 + 邮件红色告警 |
| >100% | **硬超限**：调用被拦截 | 返回配额耗尽错误 |

**日重置规则**：每日 0:00 自动重置日额度计数器；每月 0:00 重置月额度计数器。

#### ③ 界面原型

> MVP 不设计独立前端页面，额度管理通过统一管理后台入口完成。此处仅说明操作逻辑，UI 设计另见管理后台 PRD。

- 管理员可在后台查看用户配额用量（日/月金币额度、Token 消耗）
- 管理员可为用户配置金币日额度、月额度、单任务上限、请求限速
- 管理员可查看成本报表（按用户/Agent/日期维度汇总与趋势）
- 系统自动发送告警（70% 黄色站内信、90% 红色站内信+邮件、100% 拦截）

#### ④ 竞品分析（设计参考）

主流企业级 AI 平台普遍以「积分 / Credits」作为统一计量抽象层并锚定现金，核心做法如下表：

| 平台 | 兑换比例（积分 : 现金） | 额度管理要点 | 来源 |
| --- | --- | --- | --- |
| 扣子（Coze）企业版 | 1000 : 1（元） | 积分不足自动从现金账户扣款；按成员/角色/工作空间/组织多维度限额 | 扣子企业版计费文档 |
| 腾讯云（ClawPro / Token Plan） | 100 : 1（元，内部） | 「漏斗型」三级：企业总控 → 部门池 → 个人；同套餐 API Key 共享池 + 独占配额 | 腾讯云内部资料（未独立验证） |
| 阿里云百炼 Token Plan | 按模型固定积分扣减比例 | ⚠️ ToS 限定「仅交互式工具，不可用于后端自动化/应用后端」——我方后端多租户平台须走按量付费/资源包 | 阿里云百炼 Token Plan 文档 |
| Microsoft Copilot Studio | $200 = 25,000 Credits（≈0.008 $/Credit） | 套餐内含额度 + 按量付费 | Microsoft 官方文档 |
| GitLab Credits | 1 Credit = $1 | 组织在全局池化，自动抵消重/轻用户 | GitLab 官方文档 |
| Evol 团队版 | 1000 积分 ≈ $1（内部草案） | 团队共享积分池 + 成员独立日配额，用完从团队池补充 | 草案（未独立验证） |
| Warp | 每次交互 ≥1 积分，复杂交互多积分 | 按 LLM 模型、工具调用数、上下文量差异化扣减 | Warp 官方文档 |

**结论**
- **三级配额漏斗**：企业总池 → 部门/项目池 → 个人配额，任一达顶即拦（腾讯云 ClawPro、OpenAI ChatGPT Enterprise 均支持工作区/群组/个人月度限额）。
- **超额三模式**：① 自动扣款续费（扣子）② 拦截消耗（阿里云 STAROps）③ 等待下月重置（阿里云 Hermes Agent）。
- **共享池 + 个人独占**：团队共享积分池 + 个人独立（或独占）配额（Evol、腾讯云 Token Plan、百度千帆「席位制 + 企业共享包」）。
- **差异化计量**：按模型类型、任务复杂度、工具调用次数差异化扣减，而非单一线性比例。
- **工程层**：令牌桶 / 漏桶限速 + 突发允许（Burst Allowance）+ 多级时间窗配额 + 429 透明响应 + 成本熔断 + 滥用检测。

**启示**
1. MVP 只做**个人级**配额（部门/企业级后续），与行业三级漏斗的「个人」一层对齐；
2. 业务配额主单位用**金币**（锚定 10:1 现金）而非平铺「Token → 金币比例」——Token 成本跨模型差百倍且峰谷 ×2，平铺比例会系统性错估；
3. 采用「共享池 + 个人独占」同构思路，但 MVP 仅个人，共享池留后续；
4. 工程层（令牌桶多时间窗 + 429 透明响应 + 成本熔断）作为后端实现要求单列；
5. 🔴 **选型红线**：阿里百炼 Token Plan 团队版 ToS 禁后端调用；DeepSeek V4 正式版（7 月中旬）高峰 9:00–12:00、14:00–18:00 价格 ×2，金币扣减须感知峰谷或按峰时价保守锚定。

#### ⑤ 业务规则和约束条件

**配额说明**

| 配额类型 | 说明 | MVP 默认值 | 可配置 |
| --- | --- | --- | --- |
| 金币日额度 | 单用户每日登陆可领取金币数量（业务配额主单位），额度每月重制，未使用清零 | 50 金币（≈¥5） | 管理员后台可调 |

**预警与超限行为**

| 用量区间 | 行为 | 告警方式 |
| --- | --- | --- |
| 0–70% | 正常调用 | 无 |

```

配额类型：个人{日/月}金币额度
上限：{上限值} 金币
已用：{已用值} 金币
重置时间：{下次重置时间}
提示：今日金币额度已用完，请明日 0:00 重置后使用
```

| 规则项 | 说明 |
| --- | --- |
| 成本归属 | 每笔模型调用标记调用方（用户 ID + Agent ID + 会话 ID），用于成本分摊 |
| 消耗记录 | 记录：时间、用户、Agent、会话、模型、输入/输出 Token 数、**是否峰时（峰谷定价 ×2）**、**金币变动**、**金币余额**、成本（元，按实时单价含峰谷） |
| 成本报表 | 管理员后台可按用户/Agent/日期维度查看消耗汇总与趋势 |

#### ⑦ 金币体系（补充说明）

- **每日赠送发放条件**：每日赠送金币**仅在用户登录系统（SSO 登录）时发放**，登录后即时到账；当日有效、次日 0:00 清零；未登录不发放。
- **金币消耗扣减公式（不可配置）**：
  `金币消耗 = 实际 Token × 模型实时单价（含峰谷：高峰 9:00–12:00、14:00–18:00 价格 ×2）× 难度乘数 → 按固定 10 金币=1 元折算 → 四舍五入保留 1 位小数、单次最低扣 0.1 金币`。
  > 反模式提醒：不得平铺「每 1000 Token = X 金币」的可配置比例——Token 成本因模型差百倍且峰谷 ×2，平铺比例会系统性错估成本。10:1 是**金币↔人民币**的固定锚定，不是 token→金币换算。
- **抵扣优先级（MVP）**：① 每日赠送额度（优先，当日有效）→ MVP 暂不支持「金币余额兑换 token」，**用尽即拦截并提示明日登陆领取金币，或联系系统管理员**；「金币兑换 token」作为后续阶段能力预留接口。

### 3.5.3 对话输入区

### 3.5.5 会话详情

#### 功能需求描述

会话详情是中间区的核心消息画布，负责展示用户与助手的对话全过程。日常办公模式下展示流式回答、CoT 折叠摘要、来源标注与文件卡片；专家模式下展示 Plan 步骤清单、Execute 逐步执行状态与中间结果。消息按时间顺序自下而上滚动，支持流式逐字展示与停止控件联动。

| EARS 模式 | 需求描述 |
| --- | --- |
| 普遍型 | 系统应在中间区展示当前会话的消息流（用户消息 + 助手回答）；系统应支持流式逐字展示；系统应展示 CoT 折叠摘要与文件卡片。 |
| 状态驱动型 | 当正在生成时，系统应展示流式逐字内容与思考中动效；当专家模式 Plan 生成后，系统应展示步骤清单供用户查看；当 Execute 执行中时，系统应展示每步状态（执行中/完成/失败）。 |
| 事件驱动型 | 当用户发送消息时，系统应将消息追加至画布底部并触发生成；当用户点击 CoT 摘要时，系统应展开完整推理过程；当用户点击文件卡片时，系统应触发右栏预览。 |
| 不良行为型 | 当生成超时（>30s）时，系统应展示超时提示；当网络异常时，系统应展示重试入口并保留草稿；当 CoT 生成失败时，系统应仅展示回答不展示 CoT。 |

### 3.5.7 日常办公模式（web-search + RAG + 钉钉）

#### 功能需求描述

日常办公模式以 web-search + RAG 为核心，并接入钉钉基础能力。用户输入问题后，系统先判断是否需检索：对时效性/公开信息走 web-search 实时联网检索；对企业私有知识（钉钉文档、知识库、业务系统）走 RAG 检索；再结合上下文生成答案。结果可进一步落地为钉钉侧动作（生成待办、查询审批/日程、发送通知）。

| EARS 模式 | 需求描述 |
| --- | --- |
| 普遍型 | 系统应在日常办公模式下，对用户问题先做检索路由：对公开/时效信息调用 web-search，对企业知识调用 RAG；系统应结合上下文生成答案；系统应支持将结果转化为钉钉动作（待办/审批查询/通知）。 |
| 状态驱动型 | 当检索/生成无结果时，系统应给出引导建议而非报错；当问题涉及企业知识时，系统应优先走 RAG 而非纯模型生成。 |
| 事件驱动型 | 当用户发送问题时，系统应执行「路由→检索→生成→（可选）钉钉动作」链路；当用户确认生成钉钉待办时，系统应调用钉钉接口创建。 |
| 不良行为型 | 当 web-search 或 RAG 失败时，系统应降级（仅模型生成并提示来源缺失）；当钉钉调用失败，系统应提示并保留结果不直接丢失。 |

### 3.5.8 专家模式框架（plan and execute）

#### 功能需求描述

专家模式以 plan-and-execute 为核心范式。用户从专家卡片选择某位专家后进入专属协作；专家先就任务做步骤规划（Plan，向用户展示计划），再逐步调用工具/函数/MCP（含 web-search、RAG、业务系统对接）执行（Execute），过程中产出中间结果，最终汇总为结构化交付物。

专家卡片交互区分：悬停（Hover）自动展开显示该专家的具体介绍（能力描述/适用场景等）；点击（Click）跳转到该专家的案例卡片列表。案例卡片与日常办公模式类似——仅有 prompt 文本，点击回写到输入框，无推荐回答。引导用户通过 prompt 开始与专家协作。专家模式下必须先选择一位专家才能发送消息，未选择时发送按钮置灰不可点击。MVP 预置 10 位专家，完整清单见附录 6.1。

| EARS 模式 | 需求描述 |
| --- | --- |
| 普遍型 | 系统应在专家模式下以卡片展示可用专家（MVP 预置 10 位，见附录 6.1）；系统应支持用户选择专家后进入该专家专属协作（plan-and-execute）。 |
| 状态驱动型 | 当专家状态为草稿/已归档时，系统应置灰不可选；当 plan 生成后，系统应先展示计划再进入执行。 |
| 事件驱动型 | 当用户悬停专家卡片时，系统应仅显示文字介绍/履历摘要；当用户点击卡片时，系统应展开专家详情（含提示词案例库）并进入协作；Plan 生成后直接进入 Execute 逐步执行。 |
| 不良行为型 | 系统不应在 MVP 暴露创建智能体向导（仅开发者可用，见 Non-goals）；当工具调用越权时系统应拒绝执行。 |
