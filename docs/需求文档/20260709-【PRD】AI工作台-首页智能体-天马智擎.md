# 2. 产品概述

## 2.1 产品定位
AI 工作门户首页智能体是面向企业普通员工的一站式 AI 协作入口。用户进入首页后，可在「日常办公模式」下通过 web-search + RAG 快速获取答案并落地为钉钉动作，或在「专家模式」下选择预置专家进行 plan-and-execute 结构化协作。产品以三栏布局为骨架（输入框为焦点，左右栏默认收起），先做功能闭环、再逐步增强。

## 2.2 产品目标

1. **降低 AI 使用门槛**：普通员工无需了解模型/函数/MCP 等底层概念，即可通过自然语言完成日常工作与专家协作。
2. **打通"问→答→落地"闭环**：日常办公模式从检索到生成到钉钉动作落地，形成端到端可用链路。
3. **专家能力开箱即用**：预置 10 位专家覆盖选品/导购/履约/营销/售后/数据/B2B/直播/投放/竞对场景，用户选择即协作。

## 2.3 用户角色

| 角色 | 说明 | MVP 范围 |
| --- | --- | --- |
| 普通员工 | 通过 SSO 登录使用首页智能体的企业员工，可使用日常办公模式与专家模式 | ✅ 唯一角色 |
| 管理员 | 在后台配置模型/函数/MCP/技能的管理人员，不通过前端首页操作 | 后台界面不在本 PRD 范围 |

### 2.4.1 竞品参考

| 分类 | 竞品 | 核心特征 | 与我方的关系 |
| --- | --- | --- | --- |
| 企业协作平台型 | 钉钉 AI 助理 | 工作台嵌入式 AI 入口，全面接入 DeepSeek + 通义千问，支持自定义助理与工作流自动化 | 同为企业内 AI 入口，直接对标 |

| 通用 AI 助手型 | Kimi（月之暗面） | 200 万字超长上下文，13 个场景提示词 + 19 套常用语模板，Kimi+ 智能体侧边栏选择 | 提示词策略与专家展示参考 |

### 2.4.2 差异化定位

| 差异化机会 | 行业现状 | 我方设计 |
| --- | --- | --- |
| 两模式统一入口 | 各产品要么单一模式、要么多 Agent 分散 | 日常办公 + 专家模式在同一首页 Tab 切换 |
| AI-first 工 | 钉钉/飞书 AI 为附属功能，Kimi 为纯对话页 | 首页以 AI 智能体为核心，输入框为焦点 |
| 专家 Hover/C | 各产品专家/智能体均为单一交互 | Hover 看简介，Click 展开提示词案例库进入协作（详见 3.5.8） |
| web-search | Kimi 有联网搜索，钉钉有知识库，但少有融合 | 检索路由自动判断公开/时效信息走 web-search，企业私有知识走 RAG |
| 钉钉动作落地 | 钉钉 AI 助理原生支持，其他产品不具备 | 日常办公模式答案可落地为钉钉待办/审批/通知 |

### 2.4.3 竞品调研结论

**MVP 阶段定位**：对标钉钉 AI 助理的能力覆盖度（日常办公 + 专家协作），参考飞书智能伙伴的入口设计（顶部输入框为焦点），借鉴 Coze 的项目式多 Agent 协作能力（plan-and-execute 专家编排）。核心差异化策略：① 两模式统一入口（日常+专家在同一首页 Tab 切换）；② web-search + RAG 融合检索；③ 答案落地为钉钉动作（待办/审批/通知）；④ 专家 Hover/Click 区分交互。合规警示：避免过度拟人化（参考《人工智能拟人化互动服务管理暂行办法》对通义千问/豆包 C 端智能体的下线影响）。

## 3.1 全局通用规则

本节定义跨模块的通用行为规范，各功能模块默认遵循此约定，特殊场景在模块内单独说明。

### 3.1.1 模式切换

| 规则项 | 说明 |
| --- | --- |
| 可选模式 | 日常办公模式 / 专家模式 |
| 默认模式 | 日常办公模式 |
| 模式与会话绑定 | 一个会话绑定一种模式，创建后不可变更；切换模式 = 切换到对应模式的最近活跃会话（无则新建一个绑定该模式的空白会话） |
| 会话创建默认 | 新建会话继承当前选中的模式（默认日常办公）（默认联网） |
| 切换方式 | 用户手动切换，不做自动意图识别与模式自动路由 |

### 3.1.2 对话交互规范

| 规则项 | 说明 |
| --- | --- |
| 输入方式 | 多行输入，Enter 发送 / Shift+Enter 换行 |
| 发送控件 | 有内容时高亮可点击，无内容时置灰；生成中替换为停止控件 |
| 附件上传 | 输入区内提供附件上传入口，格式与大小约束见 3.1.4 |

| 安全检测 | 对话输入做敏感词与 Prompt 注入检测，命中即拦截 |

### 3.1.3 加载态 / 空态 / 错误态

| 场景 | 状态 | 处理方式 |
| --- | --- | --- |
| 会话列表加载 | 加载中 | 骨架屏占位 |

### 3.1.4 文件上传约束

| 约束项 | 限制值 | 校验位置 | 拦截行为 |
| --- | --- | --- | --- |
| 文件数量上限 | 单次最多 50 个 | 前端 | 拦截超出部分，提示「最多上传 50 个文件」 |
| 单文件大小 | ≤ 50MB | 前端 | 拦截该文件，提示「文件超过 50MB 限制」 |
| 格式白名单 | pdf、doc、docx、txt、md、xlsx、xls、csv | 前端 | 拦截该文件，提示支持格式列表 |
| 空文件（0 字节） | 不允许 | 前端 | 拦截该文件，标注「空文件」 |
| 格式伪装 | 扩展名与文件头不匹配 | 服务端 | 上传完成后标记「上传失败」 |
| 加密文件 | 文件已加密无法解析 | 服务端 | 解析阶段标记「处理失败」 |

> 前端校验顺序：扩展名 → 文件大小 → 空文件。逐项校验，首个不通过的项即拦截并提示。

| XLS | `.xls` | ✅ | ✅ 提取单元格文本 | ✅ HTML 表格渲染 | ✅ Sheet 名称列表 | P0 |

### 3.1.6 跨模块异常处理通用规则

每个功能模块的异常处理均须覆盖以下五类场景（模块内可补充特有异常）：

| 异常类型 | 通用处理 |
| --- | --- |
| 网络断连重试 | 请求失败自动重试，仍失败提示用户并保留当前状态 |
| 数据为空状态 | 展示空态提示与引导操作，不展示空面板 |
| 加载中骨架屏 | 列表/面板/预览加载先展示骨架屏或占位动效 |
| 输入非法字符 | 空内容禁止提交；超长截断并提示；特殊字符按模块规则拦截 |
| 文件产物类型 | AI 生成文件产物支持 md / docx / xlsx / pptx / pdf 五种格式，均可预览和下载 |
| 并发操作冲突 | 快速反复操作以最后一次状态为准；生成中再次发送被忽略或排队 |

### 3.1.7 搜索规则

| 规则项 | 说明 |
| --- | --- |
| 触发方式 | 输入后 300ms 防抖触发搜索，不依赖 Enter 键 |
| 匹配逻辑 | 左右模糊匹配（包含关键词即可），不区分大小写 |
| 搜索范围 | 历史会话：按会话标题匹配；会话内不支持消息正文全文搜索（见 5.2 Non-goals） |
| 结果展示 | 按更新时间倒序排列 |

### 3.4.2 模型管理

> 模型管理为智能体提供「思考能力」——管理员在后台注册模型端点、配置降级链和配额，智能体运行时通过网关调用模型。

#### ① 功能需求描述

| EARS 模式 | 需求描述 |
| --- | --- |
| 普遍型 | 系统应支持管理员在后台注册多个模型端点，配置路由策略与降级规则 |
| 状态驱动型 | 当主模型端点不可用时，系统应自动降级到备用端点并记录告警日志 |
| 事件驱动型 | 当智能体请求模型时，系统应按路由策略选择端点发起请求 |

**System Prompt（系统提示词）管理**：System Prompt 属于智能体 Agent 的配置项——定义角色约束、工具调用规则、输出格式、安全约束。字段定义与校验规则见本 PRD 3.4.6 智能体 Agent「④ 数据说明」中「模型与提示词」字段表。System Prompt 随 Agent 生命周期（草稿→已发布→已归档）统一管理，不单独建状态。

User Prompt（用户提示词）由用户在前端自由输入，平台不进入后台治理，仅做输入端的安全检测（敏感词检测 / Prompt 注入拦截，见 3.1.2）。

**提示词模板库**（可选治理）：平台提供独立的 Prompt 模板库作为可复用资产，支持管理员独立注册/发布/归档。


**工具调用说明**：LLM 在 Prompt 约束下输出标准化 JSON 格式的工具调用指令（工具名+入参），由 Agent 调度器接收后按 Skill 类型（只读/写入）决定是否需人工确认，再通过 MCP 执行。工具调用本身不是可管理的实体资产，而是运行时契约。其治理对象为可选的**工具调用规范（ToolCall Spec）**——管理员可注册已启用工具的入参 Schema 与越权判定规则，审计调用日志。工具不可用时调度器自动跳过并提示。

**思维链（CoT）说明**：CoT 是前端展示特性，用于向用户透明展示智能体推理过程——思考中详细展示推理步骤，开始输出回复时自动折叠为单行摘要。CoT 不暴露后台模型名称、工具调用细节与 MCP 配置信息。详细展示规则（折叠时机/展开交互/降级行为等）见本 PRD 3.5.x（思维链展示规则）。管理员可在后台配置 CoT 的全局默认展示策略（可选治理项）。

### 3.4.3 MCP Server

> MCP Server 为智能体提供「外部服务接入能力」——通过标准协议接入外部服务，将外部能力封装为 Tool 供智能体调用。管理员注册后需经连接探测方可启用。

#### ① 功能需求描述

MCP Server 通过标准协议接入，对外暴露原子 Tool。管理员注册后需经连接探测（连通性 + 协议兼容 + 至少声明 1 个 Tool）方可启用。

| EARS 模式 | 需求描述 |
| --- | --- |
| 普遍型 | 系统应支持管理员注册 MCP Server，将其 Tool 接口注册到工具调用框架 |
| 状态驱动型 | 当 MCP Server 连接异常时，标记该 Server 的 Tool 为不可用并记录告警 |
| 事件驱动型 | 当智能体调用 Tool 时，经工具调用框架统一调度 MCP Server 执行 |
| 不良行为型 | MCP Server 返回异常数据时拦截并降级处理，不传递给用户 |

#### ② 业务主流程图及说明

MCP Server 生命周期：管理员填写配置 → 保存为草稿 → 启用（连接探测） → 变为可用。

```mermaid
stateDiagram-v2
    [*] --> 草稿
    草稿 --> 已启用 : 启用（必填完整 + 连接探测成功）
    草稿 --> (已删除) : 删除（仅草稿，输入 slug 二次确认）
    已启用 --> [*]
```

**状态转换规则**：

| 转换 | 触发操作 | 前置条件 | 校验失败提示 | 后置行为 |
|------|---------|---------|------------|---------|
| 草稿 → 已启用 | 启用 | 必填项完整 + 连接探测成功 | "连接探测失败：{错误信息}" | 加入智能体工具选择器 |
| 草稿 → 已删除 | 删除 | 输入 slug 二次确认匹配 | "请正确输入 slug" | 物理删除 |

**探测规则**：
- 探测时机：仅在"保存并启用"或详情页"重新探测"时触发；草稿保存不探测
- 探测内容：连接可达性 + 协议兼容性 + 至少声明 1 个 Tool
- 探测超时：≤5 秒
- 错误分类：CONNECTION_FAILED / INVALID_SPEC / NO_TOOLS_DECLARED / AUTH_FAILED

#### ③ 界面原型

> MVP 不设计独立前端页面，MCP Server 通过统一管理后台入口完成。此处仅说明操作逻辑。

- 管理员可在后台注册 MCP Server，填写 slug、名称、传输方式（stdio/sse/streamable-http）、连接配置
- 管理员可对 MCP Server 执行启用/删除操作（仅草稿可删）
- 注册时"保存并启用"触发连接探测，探测失败自动保存为草稿

### 3.4.4 原子 Tool

### 3.4.5 Skill

> Skill 为智能体提供「业务编排能力」——由多个 Tool + 条件判断 + 业务流程编排而成，以标准化 .skillpkg 包交付。Skill 分只读（自动执行）和写入（需三段式安全审批）两类。

#### ① 功能需求描述

**只读 Skill 与写入 Skill**：

| 类型 | 定义 | 示例 | 执行方式 |
|------|------|------|---------|
| 只读 Skill | 查询、读取、预览类操作，不产生副作用 | 知识库问答、文件搜索、数据报表查询 | Agent 自动调用，无需人工确认 |
| 写入 Skill | 修改、创建、删除类操作，产生持久化变更 | 文件入库、Git 提交、钉钉待办创建 | 必须「沙箱模拟 → 预览 → 确认 → 正式执行」三段式 |

**Skill 包规范（.skillpkg）**：
```
{skill-name}.skillpkg
├── manifest.json    # 元数据：name/slug/version/description/capabilities
├── code/            # 执行逻辑
├── resources/       # 模板/规则文件
└── README.md        # 使用说明
```
- 文件大小 ≤ 50MB
- manifest.json 中的 slug 全局唯一，版本号由包内定义不可手动修改

| EARS 模式 | 需求描述 |
| --- | --- |
| 普遍型 | 系统应支持管理员上传/创建 Skill（Tool 编排 + 安全策略配置 + 版本管理）；专家与快捷指令通过绑定 Skill 获得能力 |
| 状态驱动型 | 当 Skill 绑定的 Tool/MCP 不可用时，标记该 Skill 为降级状态 |
| 事件驱动型 | 写入 Skill 执行时强制走三段式审批流；只读 Skill 直接执行 |
| 不良行为型 | 不向普通员工暴露 Skill 配置细节（Tool 编排逻辑、安全策略） |

#### ② 业务主流程图及说明

Skill 生命周期：上传 .skillpkg 包 → 自动解析 → 保存为草稿 → 启用 → 可用。MVP 不设审核流。

```mermaid
stateDiagram-v2
    [*] --> 草稿
    草稿 --> 已启用 : 启用（至少绑定 1 个已启用 Tool）
    草稿 --> (已删除) : 删除（仅草稿，输入 slug 二次确认）
    已启用 --> [*]
```

**状态转换规则**：

| 转换 | 触发操作 | 前置条件 | 校验失败提示 | 后置行为 |
|------|---------|---------|------------|---------|
| 草稿 → 已启用 | 启用 | 至少绑定 1 个已启用 Tool | "至少绑定 1 个已启用 Tool" | 加入智能体可引用列表 |
| 草稿 → 已删除 | 删除 | 输入 slug 二次确认 | "请正确输入 slug" | 物理删除 |

**安全审批（写入 Skill 三段式）**：

```mermaid
stateDiagram-v2
    [*] --> 待确认
    待确认 --> 已确认 : 用户确认（展示变更预览后）
    待确认 --> 已取消 : 用户取消
    待确认 --> 已拒绝 : 高危拦截 / 超时
    已确认 --> 已执行 : 正式执行变更
    已执行 --> [*]
    已取消 --> [*]
    已拒绝 --> [*]
```

| 规则 | 说明 |
|------|------|
| 适用范围 | 所有写入类 Skill |
| 三段式执行 | ① 沙箱模拟执行 → ② 展示变更预览（diff/变更清单）→ ③ 用户确认后正式执行 |
| 只读豁免 | 查询、读取、预览类 Skill 无需人工确认 |
| 高危拦截 | 删除文件、强制覆盖、修改系统配置等操作强制二次确认 |
| 超时拒绝 | 待确认超时自动拒绝 |

#### ③ 界面原型

> MVP 不设计独立前端页面，Skill 通过统一管理后台入口完成。此处仅说明操作逻辑。

- 管理员可在后台上传 .skillpkg 包（自动解析元数据）或手动创建 Skill
- 管理员可对 Skill 执行启用/删除操作（仅草稿可删），MVP 不设审核流
- 写入 Skill 执行时走安全审批三段式（运行时规则，不在此模块定义）

### 3.4.6 智能体 Agent

> 智能体是前面所有能力模块（模型、Prompt、工具、知识库、记忆）的编排组合。Agent 配置即是对这些能力的消费——选择模型、绑定工具、编写系统提示词、挂载知识库，最终发布为面向用户的可用服务。

#### ① 功能需求描述

**Agent 完整公式**：`Agent = LLM + Prompt 配置 + 记忆体系 + 工具调用调度 + MCP 工具池 + 沙箱环境 + 安全审批控制器`

**记忆体系**（MVP 落地前两层，长期为后续迭代）：

| 记忆类型 | 定位 | 载体 | 阶段 |
|------|------|------|------|
| 瞬时记忆 | 当前 Session 上下文窗口，受 memoryWindow 约束（默认 5 轮） | LLM Token 窗口 | MVP |
| 短期记忆 | 跨会话语义召回：会话结束→摘要→文本切片+向量嵌入→LanceDB→新会话语义匹配召回 | LanceDB 向量库 | MVP |
| 长期记忆 | 跨会话实体关系：存储实体、关系、项目约束，支持多跳推理 | Graphiti 图谱 | 后续迭代 |

**沙箱环境**：Agent 执行手脚的隔离环境。写入类 Skill 先在沙箱模拟执行，人工确认后再正式执行。

| EARS 模式 | 需求描述 |
| --- | --- |
| 普遍型 | 系统应支持管理员创建 Agent，配置模型/Prompt/工具/知识库/记忆窗口，按三态生命周期管理。Agent 对普通员工不可见，员工仅通过「专家」「快捷指令」间接使用。 |
| 状态驱动型 | 草稿/已归档状态对前端不可调用；已发布 Agent 详情页展示评估趋势与调用统计。 |
| 事件驱动型 | Agent 发布后刷新前端可调用列表；归档后终端不可调用。 |
| 不良行为型 | 不向普通员工暴露 Agent 后台配置（Prompt 原文/工具绑定/知识库）；引用模型/工具被禁用时阻断发布。 |

### 3.4.7 额度管理与成本归因

> 额度管理为智能体提供「成本可控」保障——防止单用户/单 Agent 过度消耗导致成本失控。**MVP 聚焦个人级配额**，部门级和企业级为后续迭代。

#### ① 功能需求描述

| 模式 | 描述 |
| --- | --- |
| 普遍型 | 系统应支持管理员为每个用户配置金币日额度、金币月额度、单任务金币上限、请求限速和 Token 安全天花板；系统应记录每笔模型调用的 Token 消耗、金币变动与成本（含峰谷）。 |
| 状态驱动型 | 当用户配额消耗达 70%/90% 时，系统应发送对应级别告警；当消耗达 100% 时，系统应拦截调用并返回配额耗尽错误。 |
| 事件驱动型 | 每次模型调用完成后，系统应更新用户配额计数器；每日/每月 0:00 自动重置对应周期配额。 |
| 不良行为型 | 配额统计数据延迟不超过 5 秒；重置操作失败时保留当前计数器不变并告警。 |

#### ② 业务主流程图及说明

额度消耗流程：用户使用智能体 → 模型调用完成 → 扣除金币 → 更新配额计数器 → 检查是否超限。

**预警与超限行为**：

| 用量区间 | 行为 | 告警方式 |
|------|------|---------|
| 0–70% | 正常调用 | 无 |
| 70–90% | 正常调用 | 站内信黄色告警 |
| 90–100% | 正常调用 | 站内信 + 邮件红色告警 |
| >100% | **硬超限**：调用被拦截 | 返回配额耗尽错误 |

**日重置规则**：每日 0:00 自动重置日额度计数器；每月 0:00 重置月额度计数器。

#### ③ 界面原型

> MVP 不设计独立前端页面，额度管理通过统一管理后台入口完成。此处仅说明操作逻辑，UI 设计另见管理后台 PRD。

- 管理员可在后台查看用户配额用量（日/月金币额度、Token 消耗）
- 管理员可为用户配置金币日额度、月额度、单任务上限、请求限速
- 系统自动发送告警（70% 黄色站内信、90% 红色站内信+邮件、100% 拦截）

#### ④ 业务规则和约束条件

**场景假设**：

| 假设 | 说明 | 复盘点 |
|------|------|--------|
| 单网关 | 所有模型调用必经网关 | 特殊场景需旁路时重构 |
| 配额硬超限 | 100% 阻断 | 用户接受度低可改软告警 |
| 成本中心必填 | 模型注册时必填成本中心 | 无成本中心体系需调整 |
| 缓存仅确定性请求 | 仅 temperature=0 缓存 | 需语义缓存时引入向量 |

**配额说明**

> MVP 仅做**用户个人级**配额；部门级 / 企业级为后续迭代。业务配额主单位统一为**金币**（1 金币 = 0.1 元，固定锚定不可配置）；Token 上限降为后端「安全天花板」，与金币额度并存、任一达顶即拦截。

**配额说明**

| 配额类型 | 说明 | MVP 默认值 | 可配置 |
| --- | --- | --- | --- |
| 金币日额度 | 单用户每日登陆可领取金币数量（业务配额主单位），额度每月重制，未使用清零 | 50 金币（≈¥5） | 管理员后台可调 |
| 金币月额度 | 单用户每月累计可消耗金币上限 | 1500 金币（≈¥150） | 管理员后台可调 |
| 单任务金币上限 | 单次 Agent 调用最大金币消耗，防失控 | 500 金币 | 管理员后台可调 |
| 请求限速 | 日常模式 60 req/min；专家模式 planExecute 10 req/min；令牌桶允许短时突发（峰值 10 QPS） | 60 req/min | 管理员后台可调 |
| Token 安全天花板 | 后端防失控硬上限，与金币额度并存、任一达顶即拦截 | 日 100 万 / 月 3000 万 / 单任务 50 万 | 管理员后台可调 |

**预警与超限行为**

| 用量区间 | 行为 | 告警方式 |
| --- | --- | --- |
| 0–70% | 正常调用 | 无 |
| 70–90% | 正常调用 | 站内信黄色告警：「您的{日/月}金币额度已使用 {百分比}%」 |
| 90–100% | 正常调用 | 站内信 + 邮件红色告警：「金币额度即将耗尽，建议联系管理员」 |
| >100% | **硬超限**：调用被拦截 | 返回配额耗尽错误（格式见下方） |

**超限错误响应**（MVP 暂不支持金币兑换 token，用尽即拦截并提示）：

```
调用失败：{日/月} 金币额度已用尽
配额类型：个人{日/月}金币额度
上限：{上限值} 金币
已用：{已用值} 金币
重置时间：{下次重置时间}
提示：今日金币额度已用完，请明日 0:00 重置后使用
```

#### ⑥ 补充说明

- 当前 MVP 不做金币体系，仅做用户级 Token 上限 + 告警
- 消耗记录在调用日志中按用户/Agent/会话/模型维度记录，供后续成本分析

### 3.5.3 对话输入区

#### 功能需求描述

输入区位于中间区中部，默认以顶部输入框为入口，进入对话后聚焦输入区。支持多行输入、附件上传（本地文件 + 知识库文件）和联网查询开关。详细交互规则见界面原型，约束条件见业务规则。

| EARS 模式 | 需求描述 |
| --- | --- |
| 普遍型 | 系统应在中间区底部提供输入区，支持多行输入（最多 8 行）、Enter 发送 / Shift+Enter 换行、最大 10000 字符；系统应提供附件上传入口（本地文件 + 知识库文件）；系统应在上传中展示状态标识；系统应提供联网查询开关。 |

### 3.5.5 会话详情

#### 功能需求描述

会话详情是中间区的核心消息画布，负责展示用户与助手的对话全过程。日常办公模式下展示流式回答、CoT 折叠摘要、来源标注与文件卡片；专家模式下展示 Plan 步骤清单、Execute 逐步执行状态与中间结果。消息按时间顺序自下而上滚动，支持流式逐字展示与停止控件联动。

| EARS 模式 | 需求描述 |
| --- | --- |
| 普遍型 | 系统应在中间区展示当前会话的消息流（用户消息 + 助手回答）；系统应支持流式逐字展示；系统应展示 CoT 折叠摘要与文件卡片。 |
| 状态驱动型 | 当正在生成时，系统应展示流式逐字内容与思考中动效；当专家模式 Plan 生成后，系统应展示步骤清单供用户查看；当 Execute 执行中时，系统应展示每步状态（执行中/完成/失败）。 |

| 不良行为型 | 当生成超时（>30s）时，系统应展示超时提示；当网络异常时，系统应展示重试入口并保留草稿；当 CoT 生成失败时，系统应仅展示回答不展示 CoT。 |

### 3.5.6 右栏文件预览面板

#### 功能需求描述

右栏 MVP 唯一功能为文件预览。AI 生成文件后，于对话消息中展示文件卡片，用户点击卡片即在右栏打开预览；系统展示文件大纲导航，支持点击跳转到对应章节。默认收起，仅点击文件卡片时展开。

| EARS 模式 | 需求描述 |
| --- | --- |
| 普遍型 | 系统应在右侧栏提供文件预览面板（MVP 仅此一项功能）；系统应在 AI 生成文件后，于对话消息中展示文件卡片，用户点击卡片即在右栏打开预览；系统应展示文件大纲导航，支持点击跳转章节。 |
| 状态驱动型 | 当右栏无预览文件时，系统应保持收起（图标态）；当被预览文件被删除时，系统应自动关闭该预览。 |

### 3.5.7 日常办公模式（web-search + RAG + 钉钉）

#### 功能需求描述

日常办公模式以 web-search + RAG 为核心，并接入钉钉基础能力。用户输入问题后，系统先判断是否需检索：对时效性/公开信息走 web-search 实时联网检索；对企业私有知识（钉钉文档、知识库、业务系统）走 RAG 检索；再结合上下文生成答案。结果可进一步落地为钉钉侧动作（生成待办、查询审批/日程、发送通知）。

| EARS 模式 | 需求描述 |
| --- | --- |
| 普遍型 | 系统应在日常办公模式下，对用户问题先做检索路由：对公开/时效信息调用 web-search，对企业知识调用 RAG；系统应结合上下文生成答案；系统应支持将结果转化为钉钉动作（待办/审批查询/通知）。 |
| 状态驱动型 | 当检索/生成无结果时，系统应给出引导建议而非报错；当问题涉及企业知识时，系统应优先走 RAG 而非纯模型生成。 |
| 事件驱动型 | 当用户发送问题时，系统应执行「路由→检索→生成→（可选）钉钉动作」链路；当用户确认生成钉钉待办时，系统应调用钉钉接口创建。 |
| 不良行为型 | 当 web-search 或 RAG 失败时，系统应降级（仅模型生成并提示来源缺失）；当钉钉调用失败，系统应提示并保留结果不直接丢失。 |

### 3.5.8 专家模式框架（plan and execute）

#### 功能需求描述

专家模式以 plan-and-execute 为核心范式。用户从专家卡片选择某位专家后进入专属协作；专家先就任务做步骤规划（Plan，向用户展示计划），再逐步调用工具/函数/MCP（含 web-search、RAG、业务系统对接）执行（Execute），过程中产出中间结果，最终汇总为结构化交付物。

专家卡片交互区分：悬停（Hover）自动展开显示该专家的具体介绍（能力描述/适用场景等）；点击（Click）跳转到该专家的案例卡片列表。案例卡片与日常办公模式类似——仅有 prompt 文本，点击回写到输入框，无推荐回答。引导用户通过 prompt 开始与专家协作。专家模式下必须先选择一位专家才能发送消息，未选择时发送按钮置灰不可点击。MVP 预置 10 位专家，完整清单见附录 6.1。

| EARS 模式 | 需求描述 |
| --- | --- |
| 普遍型 | 系统应在专家模式下以卡片展示可用专家（MVP 预置 10 位，见附录 6.1）；系统应支持用户选择专家后进入该专家专属协作（plan-and-execute）。 |
| 状态驱动型 | 当专家状态为草稿/已归档时，系统应置灰不可选；当 plan 生成后，系统应先展示计划再进入执行。 |
| 事件驱动型 | 当用户悬停专家卡片时，系统应仅显示文字介绍/履历摘要；当用户点击卡片时，系统应展开专家详情（含提示词案例库）并进入协作；Plan 生成后直接进入 Execute 逐步执行。 |
| 不良行为型 | 系统不应在 MVP 暴露创建智能体向导（仅开发者可用，见 Non-goals）；当工具调用越权时系统应拒绝执行。 |
