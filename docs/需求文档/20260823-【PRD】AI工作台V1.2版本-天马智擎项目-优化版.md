# 产品概述

## 产品概述

天马智擎V1.2聚焦三类体验优化：① 首页会话能力增强，包括多模态附件、文件规格、ReAct轮次、历史会话、澄清卡和个人知识库检索；② 沿用现有设置页面，补齐智能体表单限制和联网查询设置；③ 完善知识中心的下载权限、细粒度权限和文件树同步，并通过dws丰富钉钉协同能力。

## 产品目标

1.  支持图片、大表格及更多办公格式作为会话附件使用；单次附件由3个提升至10个。
2.  附件解析后，短内容直接进入上下文，长内容自动进入沙箱处理。
3.  日常办公模式ReAct单执行段上限调整为20轮。
4.  历史会话支持整组折叠、最近5条/查看全部、任务数量及标题吸顶。
5.  澄清卡一次性收集必要信息，必填不可跳过、非必填可跳过。
6.  首页默认同时检索用户有权访问的公共知识库和个人知识库。
7.  沿用现有智能体设置页面，补齐字段规则并增加联网查询设置。
8.  会话产物和知识中心文件支持独立下载权限。
9.  知识库、文件夹、文件支持继承、例外授权和黑名单。
10.  通过dws支持按群选人创建日程，并接入消息、待办、文档和知识库能力。
11.  知识中心右侧文件操作完成后，左侧文件树实时保持一致。

## 功能详情

### M1-多模态理解

#### 功能需求描述

本期多模态理解仅支持PNG、JPG、JPEG图片。图片先上传至OSS，用户进入会话详情并发起任务后，当前会话全量切换至DeepSeek官方视觉模型`deepseek-v4-flash-vision-exp`，由同一模型统一处理会话文本与图片，不再使用多模态子Agent。

#### 用户角色与用户故事

作为一名普通用户，我希望直接上传图片并基于图片内容提问，无需先手工描述图片。

#### 业务主流程图及说明

流程图采用纵向 Draw.io XML：[M1-图片全量视觉模型.xml](assets/20260823-v1.2流程图XML/M1-图片全量视觉模型.xml)。

复制入口：[全部Draw.io XML代码](assets/20260823-v1.2流程图XML/天马智擎V1.2-纵向流程图XML代码.md)；整体导入：[多页XML](assets/20260823-v1.2流程图XML/天马智擎V1.2-纵向流程图-多页.xml)。

用户操作 / 系统反馈：

1.  用户在首页选择PNG、JPG或JPEG图片，图片上传至OSS；此时只完成文件存储，不启动内容理解。
2.  用户进入会话详情并发送任务，系统按文件真实内容校验图片格式、大小和尺寸。
3.  当前会话直接使用`deepseek-v4-flash-vision-exp`处理本轮及后续对话，保证图片上下文连续。
4.  系统向视觉模型提交用户问题、会话上下文和图片。
5.  视觉模型直接生成回答或继续调用会话已有工具，不再把图片先转换为子Agent文本结果。
6.  系统记录图片数量、视觉Token、文本Token、耗时和调用成本；用户侧沿用正常会话状态。

#### 分支流程（异常流程）

*   后缀、MIME和文件真实内容不一致，或图片损坏、无法解码时，拒绝对应文件并说明原因。
*   单图超过50MB、单次模型请求图片累计超过200MB或单边超过8192像素时，不进入模型调用。
*   视觉模型不可用时按正常任务失败逻辑结束，不使用文本模型猜测图片内容，也不增加独立附件解析状态。
*   用户离开会话不改变已启动任务；再次进入时恢复会话真实执行结果。

### M2-文件大小/格式

#### 功能需求描述

将单次会话附件数量由3个扩展至10个，并同步扩展知识中心的文件类型与解析能力。正式环境当前会话附件为最多3个、单文件10MB；正式和测试环境知识库为最多100个、单文件50MB。本期图片仅支持PNG、JPG、JPEG，单图≤50MB、单次模型请求图片累计≤200MB；本期不支持视频。

#### 用户角色与用户故事

作为一名普通用户，我希望一次上传完整的一组办公资料，并让系统自动选择合适的处理方式。

#### 业务主流程图及说明

流程图采用纵向 Draw.io XML：[M2-文件上传与格式路由.xml](assets/20260823-v1.2流程图XML/M2-文件上传与格式路由.xml)。

复制入口：[全部Draw.io XML代码](assets/20260823-v1.2流程图XML/天马智擎V1.2-纵向流程图XML代码.md)；整体导入：[多页XML](assets/20260823-v1.2流程图XML/天马智擎V1.2-纵向流程图-多页.xml)。

用户操作 / 系统反馈：

1.  用户一次选择多个本地文件，系统先校验当前会话附件总数是否超过10个。
2.  系统逐个校验后缀、MIME、文件头、单文件大小和类型特殊限制；不合法文件不影响其他文件。
3.  合法文件独立上传至OSS并展示各自进度。
4.  图片使当前会话全量切换至DeepSeek视觉模型；其他办公文件进入文档工具链，处理结果较短时进入上下文，过长时进入沙箱。
5.  知识库文件完成解析、清洗、切片、向量化和索引；索引完成后状态变为“可检索”。

#### 分支流程（异常流程）

*   超过10个时保留前10个合法文件，提示“最多上传10个，已忽略N个”；用户移除后可继续添加。
*   会话批次累计超过1GB时停止接收后续文件，并显示还可上传的剩余容量。
*   知识库单批累计超过2GB时停止接收后续文件。
*   单图超过50MB、单次请求图片累计超过200MB或单个普通办公文件超过50MB时，仅拒绝对应文件。
*   文件后缀、MIME或文件头不一致时拒绝上传，避免通过改后缀绕过格式限制。
*   上传中断可仅重试失败文件；已成功写入OSS的附件不得重复上传。

### M3-ReAct轮次

#### 功能需求描述

调研中，日常办公模式有25%的用户遇到过执行轮次不足，因此将该模式单执行段上限调整至20轮；专家模式仅10%的用户遇到，影响占比较低，本期保持现有配置不变。

#### 用户角色与用户故事

作为一名普通用户，我希望日常办公中的复杂任务有足够轮次完成，并在达到上限后保留成果继续执行。

#### 业务主流程图及说明

本模块仅调整日常办公模式的执行轮次参数，无需单独绘制流程图。

用户操作 / 系统反馈：

1.  系统根据会话模式读取轮次上限：日常办公为20，专家模式沿用现值。
2.  每轮包含一次模型决策及其对应工具结果；同一决策内并行调用多个工具仍计1轮。
3.  任务完成后立即结束，不要求运行满上限。
4.  用户主动停止或命中循环保护时，不再发起新调用并保留已有结果。
5.  日常办公达到20轮仍未完成时，展示已完成、失败和未完成事项，并提供【继续执行】。
6.  用户继续后创建新执行段，复用原会话、附件、工具结果和产物。

#### 分支流程（异常流程）

*   连续重复相同工具与参数、或连续多轮没有新增有效结果时，提前触发循环保护。
*   工具内部自动重试属于同一轮，不额外增加ReAct轮次。
*   用户点击停止后，已返回的结果继续保留，尚未发起的工具调用全部取消。
*   专家模式达到原有上限时继续沿用现有终止和反馈逻辑，不套用20轮规则。

### M4-历史会话展示

#### 功能需求描述

参考WorkBuddy优化左侧历史会话区。系统分组与项目文件夹同时存在，每组独立支持“整组折叠/展开”和“最近5条/查看全部”两级状态；滚动时只保留距离当前视口最近的上一分组标题，避免标题层层堆叠。

#### 用户角色与用户故事

作为一名普通用户，我希望历史任务较多时能快速收起无关分组、查看某组全部任务，并在滚动中始终知道当前所在分组。

用户操作 / 系统反馈：

1.  左侧加载日常办公、专家模式等系统分组及项目文件夹；每组展示标题、任务总数和最近5条任务。
2.  点击分组标题前的小三角，仅切换当前分组的整组折叠状态；折叠后只保留标题和总数。

*   加载全部任务失败时保留最近5条、标题和总数，入口变为【重试】。
*   新任务、删除或移动任务后实时修正所属分组总数和“剩余N条”；总数降至5时自动移除查看更多入口。
*   当前会话被删除时优先选中同组相邻会话；同组为空时选择下一个可见分组的首条任务。
*   项目文件夹删除或权限收回后，移除对应分组并清理其本地展示偏好。

### M5-澄清卡优化

#### 功能需求描述

Agent需要补充信息时，一张澄清卡一次展示当前可确定的全部字段。mustClarify=true时不可整体跳过；必填字段始终不可跳过；非必填字段按字段配置保留跳过能力。提交后卡片转为只读摘要，已回答字段不再重复询问。

#### 用户角色与用户故事

作为一名普通用户，我希望一次补齐当前任务需要的信息，并在填写错误时保留已有内容，而不是被连续多张卡片反复打断。

#### 业务主流程图及说明

流程图采用纵向 Draw.io XML：[M5-澄清卡.xml](assets/20260823-v1.2流程图XML/M5-澄清卡.xml)。

复制入口：[全部Draw.io XML代码](assets/20260823-v1.2流程图XML/天马智擎V1.2-纵向流程图XML代码.md)；整体导入：[多页XML](assets/20260823-v1.2流程图XML/天马智擎V1.2-纵向流程图-多页.xml)。

用户操作 / 系统反馈：

1.  Agent判断当前任务是否缺少必要信息；无需澄清时直接继续执行。
2.  需要澄清时，一次生成当前上下文中可确定的全部字段，包括文本、单选、多选、日期时间、人员和文件等类型。
3.  卡片标识必填/非必填和可跳过规则，并在输入过程中自动保存草稿。
4.  用户点击【确认并继续】后统一校验全部字段；校验通过才提交答案并恢复Agent执行。
5.  提交成功后卡片转为只读摘要，流式回答在卡片之后继续，不覆盖原卡片。
6.  后续仅当工具结果或新上下文产生无法提前获知的新信息时，才为新增未知项生成下一张卡。

#### 分支流程（异常流程）

*   mustClarify=true时不展示整卡【跳过】；mustClarify=false时可按已有信息继续。
*   必填字段不展示单项跳过；非必填且allowSkip=true时展示【跳过此项】，跳过后仍保留字段标签及“已跳过”状态。
*   提交校验失败时滚动并聚焦第一个错误字段，同时保留所有字段值、跳过状态和附件选择。
*   提交请求失败时卡片恢复可编辑状态，防止重复提交，并保留服务端幂等标识。
*   刷新、切换会话或网络重连后恢复草稿；已提交卡片只读，不重新弹出。
*   等待澄清期间，Agent流式事件只能追加到卡片之后，不得覆盖、撤回或重复创建当前卡片。

| **动作** | **显示** | **类型** | **描述** |

| 文件移动 | 文件移动后在同一操作中更新目录关系、继承权限和索引元数据，任一步失败不得形成跨目录越权 |

### M11-文件树同步

#### 功能需求描述

知识中心右侧区域完成新建文件夹、上传、重命名、移动或删除后，左侧文件树即时反映服务端真实结果；文件解析和索引状态变化也同步更新，无需手动刷新。

#### 用户角色与用户故事

作为一名普通用户，我希望左右两侧始终展示同一份文件结构，连续操作时不会误判文件位置。

#### 业务主流程图及说明

本模块为同一页面状态同步，交互和异常处理已在下文说明，无需单独绘制流程图。

用户操作 / 系统反馈：

1.  用户在右侧列表执行文件操作。
2.  操作成功后，通过统一页面状态更新对应树节点。
3.  新增节点插入正确父节点并短暂高亮；重命名、移动和删除同步更新。
4.  上传后的文件显示“处理中”，解析和索引完成后更新为“可检索”；失败时显示失败阶段并支持重新处理。
5.  左侧保持当前展开、选中和滚动状态，服务端最新节点和索引状态作为最终结果。

#### 分支流程（异常流程）

*   文件操作失败时不修改文件树，或回滚已做的临时展示。
*   树更新失败但文件操作成功时，提示同步失败并自动拉取受影响父节点。
*   当前选中节点被删除时，选中其父节点并刷新右侧内容。

#### 界面原型

| **动作** | **显示** | **类型** | **描述** |
| --- | --- | --- | --- |
| 新建文件夹/上传 | 新节点插入并高亮 | 文件树 | 自动展开直接父节点 |
| 重命名 | 节点名称原位更新 | 文件树 | 不改变展开和选中状态 |
| 移动 | 原位置移除、目标位置插入 | 文件树 | 目标父节点可自动展开 |
| 删除 | 节点移除 | 文件树 | 当前节点删除时回到父级 |
| 解析/索引状态变化 | 处理中、可检索或失败 | 列表/文件树 | 图片和大文件在任务中心展示当前处理阶段 |

#### 数据说明（业务实体）

| --- | --- | --- | --- | --- | --- |
| 节点名称 | 字符 | ≤255 | — | 是 | 与右侧列表保持一致 |
| 所在文件夹 | 字符 | ≤255 | 根目录 | 是 | 移动后立即更新 |

| **规则项** | **说明** |

# 跨模块影响

## 统一文件规则

| **场景** | **数量与容量** | **处理结果** |
| --- | --- | --- |
| 会话附件 | 最多10个；办公文件≤50MB；图片仅png/jpg/jpeg、单图≤50MB且图片累计≤200MB；单批≤1GB | 上传OSS；图片使当前会话全量切换至DeepSeek视觉模型，其他文件按长度进入上下文或沙箱，默认不向量化 |
| 知识库上传 | 最多100个；单文件规则与会话一致；单批≤2GB、上传并发≤5 | 上传OSS后异步解析、切片、向量化和索引，完成后才可检索 |
| 知识库文件作为会话资料 | 不重复上传原文件 | 仅可选择“可检索”且当前用户有查看权限的文件 |

首页与知识库上传入口的支持格式、单文件限制和错误文案保持一致；数量和批次限制按各自场景展示。

## 知识库解析与向量化

| **文件类型** | **入库处理** | **引用定位** |
| --- | --- | --- |
| 文档/PDF | 提取正文、标题、段落和表格，按结构切片并向量化 | 页码、标题、段落 |
| 表格 | 保留工作表、表头和行组；计算类问题转入沙箱或数据工具 | 工作表、单元格范围 |
| 图片 | DeepSeek视觉模型输出OCR文字、图片描述和区域信息，合并为结构化文本后使用现有Embedding模型向量化 | 图片及区域坐标 |
| HTML | 禁用脚本和外部请求，提取正文、标题层级、表格和链接 | 标题路径、原始链接 |
| PPT/PPTX | 按页提取标题、正文和备注；复杂页面渲染后补充OCR/视觉描述 | 幻灯片页码 |
| EMMX | 提取主题层级、节点、备注和链接；结构不稳定时先转换后入库 | 节点路径 |

知识库图片不直接使用原图生成向量，而是先识别图片文字、内容描述和区域信息，再按文本方式进入现有知识检索。前端只展示“处理中、可检索、处理失败”，不展示切片或向量参数。

## 索引、权限和数据一致性

| **变更** | **联动要求** |
| --- | --- |
| 文件上传 | OSS成功不等于可检索；必须在解析、切片、向量化和索引均完成后置为ready |
| 图片重新处理 | 图片识别方式调整后，历史图片可重新处理；完成前继续使用原有可检索内容 |
| 权限或黑名单变化 | 立即更新片段权限并清除检索缓存，不要求重新生成向量 |
| 文件移动 | 同步更新目录、继承权限和索引元数据 |
| 文件删除 | 立即停止检索，异步清理原文件及切片、向量、缩略图和视觉解析结果等衍生数据 |

## 用量与运行影响

会话图片理解与知识库图片入库分别统计用量，知识库图片被多次检索时不重复计算入库处理用量。

任务中心统一展示“处理中/可检索/失败”，并在处理中显示扫描、视觉解析、切片、向量化或索引阶段。
