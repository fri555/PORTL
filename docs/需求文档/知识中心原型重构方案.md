## 三、重构原则

1. **只做 PRD 定义的 MVP-1 功能**，不提前做二期/增强版
   - 不强加：右键菜单、密级、标签、回收站恢复、四种 QA 模式
2. **mock 数据与组件逻辑分离**
   - 所有 mock 数据放在 `mock-data.ts`，组件只引用不定义
3. **删除的评审决议功能不留痕迹**
   - 不注释掉，不 `v-if="false"`，直接不写
4. **组件单一职责**
   - 每个组件只负责一个区域/弹窗
5. **权限判断前置**
   - 在 `KnowledgeIndex.vue` 中维护一个 `userRole` mock，向下传递
6. **状态变量精简**
   - 当前原型约 80+ 个响应式变量，目标控制在 40 个以内

## 五、Git 操作方案

### 建议流程

为了节省本地空间同时保留代码历史：

**1. 将当前 frontend-mvp 推送到 GitHub**

```bash
# 检查当前远程
git remote -v

# 如果已有 origin 指向 GitHub，直接推送
git add frontend-mvp/
git commit -m "chore: 存档 KnowledgeBaseView 原版原型（重构前快照）"
git push

# 或创建新分支存档
git checkout -b archive/prototype-v1
git push origin archive/prototype-v1
```

**2. 删除本地不需要的目录释放空间**

```bash
# 查看各目录大小
du -sh frontend-mvp/node_modules
du -sh frontend-mvp/dist
du -sh docs/需求文档/screenshots-v2  # 原型图片较大

# 删除可恢复的
rm -rf frontend-mvp/node_modules     # 可重新 npm install
rm -rf frontend-mvp/dist             # 可重新 build
```

**3. 在新目录开始工作**

直接在 `frontend-mvp/src/views/knowledge/` 目录下新建组件，`KnowledgeBaseView.vue` 原文件保留（只读参考），不删除但标记为 deprecated。

### 空间估算

| 目录 | 当前大小 | 操作 |
|------|---------|------|
| `frontend-mvp/node_modules` | ~200-400MB | `rm -rf` 后省最大空间 |
| `frontend-mvp/dist` | ~5-20MB | `rm -rf` |
| `docs/需求文档/screenshots-v2` | 24张图 ~3-4MB | 推送后 `rm -rf` |
| **合计可释放** | **~300-500MB** | |
