# 2. 产品概述

## 2.1 产品定位

AI 工作台「系统入口」是面向集团员工的统一业务系统导航。它将分散在不同域名、App、小程序和线下获取方式中的系统入口集中呈现，默认展示当前用户有权查看的全部系统，支持按系统名称搜索，并通过统一 SSO 完成免登访问。

本功能只负责「发现系统 → 判断可访问性 → 发起访问 → 记录结果」的入口闭环，不承载目标系统内部业务流程。系统入口是工作台中的独立功能模块，不包含常用工作助手、日历、日程、任务或 AI 对话能力。

## 2.2 产品目标

1. **统一入口**：集中管理集团业务系统入口，减少员工查找网址、保存个人书签和反复确认访问方式的成本。
2. **按权展示**：根据用户身份、部门和角色展示可用系统，避免无权限入口造成干扰或越权访问。
3. **一次登录**：已接入 SSO 的系统支持免登跳转，未接入系统明确展示原始登录方式。
4. **快速搜索**：支持按系统名称左右模糊匹配，帮助用户在全部系统中快速定位目标入口。
5. **统一标识**：支持上传和更换系统 Logo，提升系统辨识度；无 Logo 时使用默认图标兜底。
6. **多形态统一**：网页、App、小程序、待开启系统和后端服务使用统一卡片承载，并采用与入口形态匹配的交互。

## 2.3 用户角色

| 角色 | 说明 | MVP 范围 |
| --- | --- | --- |
| 普通员工 | 通过门户 SSO 登录，根据权限查看、搜索并访问系统入口 | ✅ 核心角色 |
| 系统入口维护人员 | 在系统入口页面上传或更换系统 Logo；其他系统配置不在本 PRD 展开 | ✅ Logo 维护角色 |

### 用户故事地图

用户在系统入口中的核心活动主线：**进入工作台 → 搜索系统 → 访问系统 → 处理结果**。

| 用户活动 | 用户任务 | 用户故事 | 优先级 |
| --- | --- | --- | --- |
| **进入工作台** | 身份校验 | 作为员工，我希望系统识别我的登录身份，以便只看到有权使用的系统 | MVP |
| | 加载入口 | 作为员工，我希望进入页面后看到全部有权限的系统，以便开始工作 | MVP |
| **查找系统** | 搜索系统 | 作为员工，我希望输入系统名称中的任意关键词，以便快速找到目标入口 | MVP |
| | 识别系统 | 作为员工，我希望看到系统名称、使用部门、架构和访问方式，以便确认是否为目标系统 | MVP |
| **访问系统** | 网页访问 | 作为员工，我希望网页系统在新标签页打开，以便保留工作台页面 | MVP |
| | 免登访问 | 作为员工，我希望访问已接入 SSO 的系统时无需二次登录 | MVP |
| | 查看非网页入口 | 作为员工，我希望系统明确告诉我 App、小程序或安装包的获取方式 | MVP |
| **处理结果** | 获取失败原因 | 作为员工，我希望跳转失败时看到明确原因和处理建议，以便继续工作 | MVP |
| | 重新访问 | 作为员工，我希望网络或凭证异常后可以重试，以便恢复访问 | MVP |
| **维护标识** | 上传 Logo | 作为维护人员，我希望为缺少标识的系统上传 Logo，以便员工快速识别 | MVP |
| | 更换 Logo | 作为维护人员，我希望替换已有 Logo，以便标识变更后及时更新 | MVP |

## 2.4 方案对比

### 2.4.1 方案参考

| 方案 | 核心特征 | 优点 | 局限 |
| --- | --- | --- | --- |
| 浏览器收藏夹 | 用户自行保存网址 | 使用简单、无需建设 | 无统一权限、无入口状态、无法集中维护、跨设备与组织管理弱 |
| 静态系统导航页 | 固定展示系统链接 | 集中展示、建设成本较低 | 系统较多时查找困难，无按权展示、SSO 与异常处理能力有限 |
| 本方案：统一系统入口 | 全部系统 + 模糊搜索 + Logo + 权限 + SSO + 多入口形态 | 形成发现、识别和访问闭环 | 依赖既有系统管理和统一 SSO 能力 |

### 2.4.2 差异化定位

| 差异化机会 | 常见问题 | 本方案设计 |
| --- | --- | --- |
| 统一入口 | 系统入口散落在群消息、文档和个人收藏夹 | 在工作台集中展示 78 条首批入口 |
| 快速查找 | 系统数量较多时逐个浏览效率低 | 按系统名称左右模糊匹配 |
| 统一标识 | 系统缺少 Logo 或标识不统一 | 缺失时默认图标兜底，支持上传和更换 Logo |
| 按权展示 | 所有人看到同一入口集合 | 按用户、部门、角色和组织范围过滤 |
| 多形态入口 | App、小程序和网页混在同一链接列表 | 按入口形态提供跳转、提示或禁用行为 |
| SSO 闭环 | 用户进入目标系统后仍需重复登录 | 已接入系统生成 SSO 跳转地址，未接入系统明确标识 |
| 状态透明 | 待开启、开发中或地址缺失的入口仍可能造成无响应点击 | 卡片展示状态，不可访问时阻止无效跳转 |

### 2.4.3 方案结论

MVP 采用「全部系统 + 左右模糊搜索 + Logo + 按权展示 + SSO 跳转 + 多入口形态」方案。系统清单以附录 6.1 的 78 条原始数据为基线；页面不提供分类、标签或常用能力；所有网页型入口默认在新标签页打开。

# 3. 功能需求

## 3.1 全局通用规则

本节定义系统入口模块的通用行为规范，各子功能默认遵循此约定，特殊场景在模块内单独说明。

### 3.1.1 系统范围

| 规则项 | 说明 |
| --- | --- |
| 首版系统范围 | 以附录 6.1 的 78 条系统清单为准 |
| 数据真实性 | 系统名称、网址、使用部门和归属架构按原始清单展示；缺失项显示「—」，不得由前端自行补值 |
| 同名系统 | 同名但网址不同的系统作为独立入口保留，通过使用部门和访问地址区分 |
| 展示前提 | 系统未被停用，且当前用户命中可见范围；待开启/开发中的系统允许展示状态但不可访问 |
| 目标系统职责 | 工作台只负责入口展示、权限判断和发起访问，不承载目标系统内部业务 |

### 3.1.2 列表与搜索规则

| 规则项 | 说明 |
| --- | --- |
| 默认列表 | 进入页面后直接展示当前用户全部可见且未停用的系统入口 |
| 排序 | 复用既有系统顺序；搜索只过滤结果，不改变相对顺序 |
| 搜索范围 | 仅匹配系统名称，不匹配网址、使用部门、架构或访问说明 |
| 匹配方式 | 左右模糊匹配，即系统名称包含搜索词即可命中 |
| 大小写 | 英文不区分大小写 |
| 空格处理 | 自动去除搜索词首尾空格；仅输入空格等同于清空搜索 |
| 触发方式 | 输入后 300ms 防抖触发，无需按 Enter |
| 清空搜索 | 点击搜索框清除按钮或删除全部文字后，恢复全部系统 |
| 无结果 | 展示「未找到匹配的系统」和「清空搜索」按钮 |
| 去重 | 列表按 systemId 去重 |

### 3.1.3 系统归属架构规则

| 规则项 | 说明 |
| --- | --- |
| 可选值 | B2C、B2B、中台、对外、— |
| 数据来源 | 以系统清单或既有系统管理模块返回的数据为准 |
| 对外含义 | 「对外」仅代表系统归属架构，不决定浏览器打开方式 |
| 缺失处理 | 原始清单未提供时显示「—」，由系统负责人后续补录 |
| 展示方式 | 作为系统卡片的架构标签展示，可用于识别但不作为访问权限依据 |

### 3.1.4 入口形态、状态与打开规则

| 入口形态 | 判断依据 | 点击行为 |
| --- | --- | --- |
| 网页系统 | 配置有效 HTTP/HTTPS 地址 | 完成权限与状态校验后，在新标签页打开 |
| App 下载页 | 配置 App Store 或下载地址 | 在新标签页打开下载页；其他平台说明以弹窗展示 |
| 微信小程序 | 配置小程序名称，无网页地址 | 弹窗展示「请在微信中搜索：{小程序名称}」 |
| 安装包获取 | 配置联系人或获取说明 | 弹窗展示获取方式，不执行网页跳转 |
| 状态覆盖：待开启/开发中 | 任意入口的状态为待开启或开发中 | 忽略入口形态的默认行为，卡片置灰，点击展示状态说明 |
| 后端服务 | 入口类型为后端服务 | 不面向普通员工跳转，点击展示「该系统为后端服务，无前台访问入口」 |
| 地址缺失 | 无网址且无其他访问说明 | 卡片置灰，点击展示「访问方式未配置」 |

### 3.1.5 SSO 与权限规则

| 规则项 | 说明 |
| --- | --- |
| 门户认证 | 用户必须先通过统一 SSO 登录门户 |
| 展示权限 | 系统列表按用户、部门、角色或组织范围过滤 |
| 二次校验 | 点击系统入口时，服务端必须再次校验身份、权限和系统状态 |
| 已接入 SSO | 服务端生成 SSO 跳转地址，目标系统完成免登 |
| 未接入 SSO | 打开系统原始地址，并在卡片展示「需登录」状态 |
| 凭证过期 | 静默刷新后自动重试一次；仍失败则提示重新登录 |
| 协议复用 | 具体 IAM、OAuth2、JWT 生命周期和验签方式以统一 SSO PRD 为准 |
| 安全边界 | 前端不得自行修改目标地址、拼接越权参数或绕过服务端访问校验 |

### 3.1.6 加载态 / 空态 / 错误态

| 场景 | 状态 | 处理方式 |
| --- | --- | --- |
| 系统列表加载 | 加载中 | 展示系统卡片骨架屏 |
| 系统列表加载 | 加载失败 | 展示错误提示和「重新加载」按钮 |
| 当前用户无可见系统 | 空 | 展示「暂无可访问的系统，请联系管理员开通」 |
| 搜索 | 无结果 | 展示「未找到匹配的系统」和「清空搜索」按钮 |
| Logo 上传 | 上传中 | Logo 区展示上传进度，禁止重复提交 |
| Logo 上传 | 失败 | 保留原 Logo，提示失败原因并允许重新选择文件 |
| 系统访问 | 权限不足 | 阻止跳转，提示「暂无该系统访问权限」 |
| 系统访问 | 系统停用 | 阻止跳转，提示「该系统已停用」 |
| 系统访问 | SSO 失败 | 提示「免登失败，请重新登录或联系管理员」 |
| 系统访问 | 地址无效 | 阻止跳转，提示「系统地址无效，请联系管理员」 |
| 系统访问 | 浏览器拦截新窗口 | 提示「新窗口被浏览器拦截，请允许后重试」 |
| 全局网络 | 断连 | 页面顶部展示 Banner：「网络连接已断开，请检查网络」 |

### 3.1.7 并发与防重复规则

| 规则项 | 说明 |
| --- | --- |
| 搜索输入 | 300ms 防抖；连续输入以最后一次搜索词为准 |
| Logo 上传 | 同一系统上传请求未完成前禁止重复提交 |
| 系统访问 | 1 秒内同一用户对同一系统的重复点击只发起一次访问请求 |
| 新标签页 | 每次有效访问只打开一个新标签页 |
| 数据刷新 | Logo 上传成功后只更新目标卡片，不重新加载整页 |

### 3.4.1 系统卡片与入口形态

#### 功能需求描述

系统卡片用于帮助用户识别系统、判断访问方式并发起访问。卡片展示系统 Logo、系统名称、使用业务部门、归属架构、入口形态、访问状态和免登状态。

| EARS 模式 | 需求描述 |
| --- | --- |
| 普遍型 | 系统应在卡片中展示 Logo、名称、部门、架构标签、入口形态、访问状态和免登状态。 |
| 状态驱动型 | 当系统不可访问时，卡片应置灰并展示原因；当字段缺失时显示「—」。 |
| 事件驱动型 | 当用户点击可访问卡片时，系统应根据入口形态执行跳转或展示说明。 |
| 不良行为型 | 系统不应对待开启、开发中、后端服务或地址缺失的卡片执行网页跳转。 |

#### 业务主流程图及说明

~~~mermaid

    B -->|可访问| C["展示正常卡片"]
    B -->|待开启/开发中| D["展示置灰状态"]
    C --> E{"入口形态"}
    E -->|网页/App| F["显示跳转箭头"]
    E -->|小程序/安装包| G["显示说明图标"]
    E -->|后端服务/地址缺失| D
~~~

说明：归属架构只作为信息标签；打开行为由 entryType、status 和访问服务结果共同决定。

### 3.4.2 系统搜索

#### 功能需求描述

系统搜索用于在全部可见系统中快速定位目标入口。用户输入系统名称中的任意连续字符后，前端按左右模糊匹配过滤当前列表；搜索只改变展示结果，不改变系统原有顺序。

| EARS 模式 | 需求描述 |
| --- | --- |
| 普遍型 | 系统应在系统列表上方提供搜索框，并仅按系统名称执行左右模糊匹配。 |
| 状态驱动型 | 当搜索词为空时，系统应展示全部可见系统；当无匹配结果时，应展示无结果空态。 |
| 事件驱动型 | 当用户输入内容后停止 300ms 时，系统应自动过滤列表；当用户清空搜索时，应恢复全部系统。 |
| 不良行为型 | 系统不应匹配网址、使用部门、架构或访问说明；搜索不应改变系统相对顺序。 |

#### 业务主流程图及说明

~~~mermaid
flowchart TD

    B --> C["去除首尾空格"]
    C --> D{"搜索词是否为空"}
    D -->|是| E["展示全部可见系统"]
    D -->|否| F["按系统名称判断是否包含搜索词"]
    F -->|有结果| G["按原顺序展示匹配系统"]
    F -->|无结果| H["展示无结果空态<br/>提供清空搜索"]
~~~

说明：例如输入「库存」，可匹配「自营第三方库存系统」和「大库存查询系统」。

#### 界面原型

| 动作 | 显示 | 类型 | 描述 | 截图示例 |
|------|------|------|------|---------|
| 【搜索框】输入 | 300ms 后过滤系统卡片 | 输入框 | · Placeholder「搜索系统名称」· 左右模糊匹配 · 英文不区分大小写 | — |
| 【搜索框】输入首尾空格 | 自动去除首尾空格后匹配 | 输入框 | · 仅输入空格等同于清空搜索 | — |
| 【清除图标】点击 | 清空关键词并恢复全部系统 | 图标 | · 有搜索内容时显示 | — |
| 【搜索无结果】出现 | 展示无结果说明 | 空态 | · 文案「未找到匹配的系统」· 提供「清空搜索」按钮 | — |

#### 数据说明（业务实体）

| 字段名 | 数据类型 | 长度 | 默认值 | 必需 | 约束说明 |
|--------|---------|------|--------|------|---------|
| searchKeyword | 字符 | ≤100 | 空 | N | · 用户输入的原始搜索词 |

| resultCount | 整数 | — | 全部可见系统数量 | Y | · 当前匹配结果数 |
| isSearching | 布尔 | — | false | Y | · 是否存在有效搜索词 |

| 规则项 | 说明 |
| --- | --- |
| 搜索范围 | 仅系统名称 |
| 匹配逻辑 | 系统名称包含完整搜索词即命中 |
| 中文匹配 | 按输入的连续汉字进行包含匹配，不做拼音或同义词扩展 |
| 英文匹配 | 不区分大小写 |
| 防抖 | 300ms |
| 排序 | 保持原系统列表相对顺序 |
| 数据范围 | 仅搜索当前用户有权限查看的系统 |
| 空搜索 | 恢复全部系统 |
| 无结果 | 展示空态，不自动推荐其他系统 |

| --- | --- |

### 3.4.3 Logo 上传

#### 功能需求描述

Logo 上传用于为系统卡片补充或更新图形标识。普通员工仅查看 Logo；具有系统入口维护权限的用户可在 Logo 区域上传或更换图片。其他系统字段仍由既有系统管理模块维护，本 PRD 不展开。

| EARS 模式 | 需求描述 |
| --- | --- |
| 普遍型 | 系统应展示已上传的系统 Logo；无 Logo 或加载失败时展示统一默认图标。 |
| 状态驱动型 | 当当前用户具有 Logo 维护权限时，Logo 区域 Hover 应显示「上传 Logo」或「更换 Logo」操作。 |
| 事件驱动型 | 当维护人员选择合法图片并确认上传时，系统应保存 Logo，并立即更新目标系统卡片。 |
| 不良行为型 | 普通员工不应看到上传操作；点击上传区域不应触发系统跳转；非法文件不应上传。 |

#### 业务主流程图及说明

~~~mermaid
flowchart TD
    A["维护人员 Hover Logo 区域"] --> B{"是否已有 Logo"}
    B -->|否| C["显示：上传 Logo"]
    B -->|是| D["显示：更换 Logo"]
    C --> E["选择本地图片"]
    D --> E
    E --> F["校验格式与大小"]
    F -->|不通过| G["阻止上传并提示原因"]
    F -->|通过| H["预览图片并确认"]
    H --> I["上传文件"]
    I -->|成功| J["更新卡片 Logo"]
    I -->|失败| K["保留原 Logo 并允许重试"]
~~~

说明：Logo 上传操作与卡片访问操作相互隔离；普通员工不会看到上传入口。

| 动作 | 显示 | 类型 | 描述 | 截图示例 |

| 【Logo 区域】维护人员 Hover | 「上传 Logo」或「更换 Logo」蒙层 | 图片操作 | · 普通员工不展示 · 点击不触发系统跳转 | — |

| 【确认上传】点击 | 展示上传进度 | 按钮 | · 上传中禁止重复提交 | — |
| 【上传成功】完成 | 卡片立即显示新 Logo | 图片 | · Toast「Logo 已更新」 | — |
| 【上传失败】发生 | 保留原 Logo | 错误提示 | · 展示失败原因 · 可重新选择文件 | — |

| fileType | 枚举 | — | — | Y | · png/jpg/jpeg/webp |

| 规则项 | 说明 |
| --- | --- |
| 操作权限 | 仅具有 system_logo_edit 权限的用户可上传或更换 |
| 文件数量 | 单次仅上传 1 个文件 |
| 支持格式 | png、jpg、jpeg、webp；不支持 svg、gif |

### 3.4.4 系统访问与 SSO

#### 功能需求描述

系统访问负责在用户点击卡片后完成二次权限校验、系统状态校验、入口形态判断和跳转结果返回。已接入 SSO 的网页系统免登访问；未接入系统打开原始地址并允许目标系统自行登录。

| EARS 模式 | 需求描述 |
| --- | --- |
| 普遍型 | 系统应在每次点击访问时校验用户、权限、系统状态和入口配置，并记录访问结果。 |
| 状态驱动型 | 当凭证过期时系统应静默刷新并重试一次；当 SSO 未接入时返回原始地址。 |
| 事件驱动型 | 当访问校验通过时，网页/App 下载页应在新标签页打开；小程序等应展示访问说明。 |
| 不良行为型 | 系统不应在无权限、停用或配置无效时生成可访问地址。 |

#### 业务主流程图及说明

~~~mermaid
flowchart TD
    A["点击系统卡片"] --> B["防重复点击"]
    B --> C["调用访问接口"]
    C --> D{"校验结果"}
    D -->|无权限/停用/无效| E["阻止访问并提示原因"]
    D -->|通过| F{"返回动作"}
    F -->|open_new_tab| G["新标签页打开"]
    F -->|show_instruction| H["弹窗展示访问说明"]
    F -->|blocked| E
    G --> I["记录访问成功/失败"]
~~~

## 4.2 安全要求

| 维度 | 要求 |
| --- | --- |
| 身份认证 | 统一 SSO（公司 IAM）；具体 Token 有效期和续期策略遵循统一 SSO PRD |
| 权限控制 | 列表查询与访问请求均由服务端执行用户/部门/角色/组织权限校验 |
| 跳转地址 | 前端仅使用访问服务返回地址，不自行拼接长期凭证或共享密钥 |
| 传输加密 | 门户与服务端使用 HTTPS；HTTP 目标地址需展示风险标识并推动升级 |
| 地址安全 | 访问服务校验 URL 协议，禁止 javascript、data 等可执行协议 |
| 防开放重定向 | 目标域名必须来自既有系统数据，访问接口不得接受前端任意 redirectUrl |
| 凭证保护 | 日志不得记录完整 Token、SSO Ticket 或敏感查询参数 |
| 数据最小化 | 系统入口只记录访问审计，不采集用户在目标系统内的业务数据 |
| Logo 文件安全 | 仅允许 png/jpg/jpeg/webp，单文件 ≤2MB；服务端校验 MIME、文件头和大小 |
| Logo 权限 | 仅 system_logo_edit 权限可上传或更换 Logo |
| 操作审计 | 记录搜索、Logo 上传、访问校验和跳转结果 |
