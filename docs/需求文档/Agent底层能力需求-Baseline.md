# Agent 底层能力需求 - Baseline

## 版本记录

| 版本 | 日期 | 更新摘要 |
|------|------|---------|
| v1 | 2026-07-13 | 初始版本 |

## 一、需求概述

为首页智能体（日常办公模式 + 专家模式）提供底层能力支撑——模型、工具、Skill、额度等统一管理。管理员在后台配置，对普通员工不可见。

## 二、业务术语表

| 术语 | 说明 |
|------|------|
| 智能体（Agent） | 基于 LLM 的可配置应用单元，是底层能力的编排产物 |
| 模型管理 | 注册 LLM 端点、配置降级链，为智能体提供推理能力 |
| MCP Server | 通过标准协议接入的外部服务，对外暴露原子 Tool |
| 原子 Tool | 最小粒度执行单元，一个 Tool 只做单一动作 |
| Skill | 业务编排能力，多个 Tool + 条件判断编排而成 |
| 草稿 | 已保存但未启用的状态 |
| 已启用 | 配置完成可被智能体引用的状态 |
| 额度管理 | 用户级 Token 消耗上限 + 告警机制 |

## 三、功能架构

```
通用能力层（被所有场景共享）
├── 模型管理 — 提供 LLM 推理能力
├── MCP Server — 提供外部服务标准化接入
├── 原子 Tool — 提供原子执行单元
├── Skill — 提供业务编排能力
├── 额度管理 — 提供成本控制
└── [P1] 智能评估 — 质量保障

业务场景层（消费通用能力）
├── 日常办公模式（web-search + RAG + 钉钉动作落地）
└── 专家模式（plan-and-execute + 预置专家）

实现载体
└── 智能体 Agent — 编排通用能力，发布为面向用户的可用服务
```

**能力引用矩阵**：

| 能力 | 日常办公模式 | 专家模式 | 说明 |
|------|------------|---------|------|
| 模型管理 | ✅ | ✅ | 两模式都需要 LLM 推理 |
| 原子 Tool | ✅ | ✅ | 两模式都需要执行工具 |
| MCP Server | ✅ | ✅ | 两模式都可能调用外部服务 |
| Skill | ✅ | ✅ | 快捷指令→Skill；专家模式→Skill |
| 额度管理 | ✅ | ✅ | 两模式消耗都计入额度 |
| 智能评估 | ❌(P1) | ❌(P1) | MVP 不做 |

## 四、系统架构与职责

| 组成部分 | 职责 | 说明 |
|---------|------|------|
| 管理员后台 | 模型/MCP/Tool/Skill 的注册和配置；智能体创建和管理；额度设置 | 对普通员工不可见 |
| 智能体引擎 | 运行时路由：根据配置调用模型、执行 Tool、编排 Skill | 后端服务 |
| 前端门户 | 员工通过日常办公/专家模式间接使用智能体能力 | 不对员工暴露后台配置 |

## 五、模块核心规则

### 通用规则（所有模块适用）

所有可管理资源（模型、MCP Server、原子 Tool、Skill、智能体 Agent）统一生命周期：

```
填写配置 → 保存为草稿 → 启用 → 变为可用
```

- **草稿**：已保存但未启用，不可被智能体引用
- **已启用**：校验通过后变为可用，可被智能体引用
- **删除**：仅草稿可删，删除前二次确认
- **编辑**：草稿直接编辑

### 模型管理

| 规则项 | 说明 |
|--------|------|
| 创建方式 | 管理员填写表单注册（需预留 DeepSeek V4 Flash + Pro 快捷入口） |
| 启用校验 | 连通性探测（连接可达 + 协议兼容） |
| 字段要求 | 见参考文档《模型管理》字段表，每字段明确类型、必填、校验 |
| 降级链 | 主模型报错时自动切到备选（MVP 主备两段式） |
| 可扩展性 | 支持接入任意提供方（通过提供方枚举 + 自定义扩展） |

### MCP Server

| 规则项 | 说明 |
|--------|------|
| 创建方式 | 管理员填写连接配置 |
| 启用校验 | 连接探测（可达性 + 协议兼容 + 至少声明 1 个 Tool） |
| 传输方式 | stdio / sse / streamable-http |
| 字段要求 | 见参考文档《工具管理》MCP Server 字段表 |
| 可扩展性 | 支持标准 MCP 协议接入任意外部服务 |

### 原子 Tool

| 规则项 | 说明 |
|--------|------|
| 内置工具 | 代码自带，系统自动发现纳管，无需手动创建 |
| 手动创建 | 预留手动注册入口（名称/slug/入参Schema/分类/描述），支持后续新增 |
| 启用校验 | 内置工具免探测；手动创建的远程类随 MCP 探测 |
| 字段要求 | 见参考文档《工具管理》原子 Tool 字段表 |

### Skill

| 规则项 | 说明 |
|--------|------|
| 创建方式 | 上传 .skillpkg 包 → 自动解析 manifest.json 元数据 → 保存为草稿 |
| 启用校验 | 绑定至少 1 个已启用 Tool（MVP 不设审核流） |
| 安全审批 | 写入类 Skill 强制三段式（沙箱模拟→预览→确认）作为运行时不在此处定义 |
| 字段要求 | 见参考文档《工具管理》Skill 字段表 |
| 可扩展性 | .skillpkg 标准化包格式，支持任意 Tool 编排 |

### 智能体 Agent

| 规则项 | 说明 |
|--------|------|
| 创建方式 | 填写配置表单（基础信息 → 模型与提示词 → 能力配置） |
| 启用（发布） | 校验必填项 + 引用模型已启用 + 引用工具已启用 → 生成版本号 → 变为可用 |
| 编辑 | 草稿直接编辑；已发布编辑→生成新草稿 |
| 字段要求 | 见参考文档《智能体管理》字段表，每字段明确类型、必填、校验 |
| 可扩展性 | 模型、工具、Prompt 均为配置化，新增能力只需在后台注册即可被 Agent 引用 |

### 额度管理

| 规则项 | 说明 |
|--------|------|
| 控制维度 | 用户级（每个用户独立配额） |
| 设置方式 | 管理员基于全局可用额度为用户配置日上限 |
| 告警机制 | 70% 黄色告警（站内信）/ 90% 红色告警（站内信+邮件）/ 100% 拦截 |
| MVP 范围 | 只做上限+告警，不做金币体系 |

## 六、上线风险与兼容性

| 风险 | 说明 | 缓解措施 |
|------|------|---------|
| 模型新增影响现有 Agent | 添加新模型可能导致已有 Agent 行为变化 | Agent 发布时校验模型状态 |
| 工具禁用影响 Agent | 禁用 MCP/Tool 时已引用该工具的 Agent 会受影响 | 禁用前强制展示引用方列表 |
| 额度拦截影响用户体验 | 用户额度耗尽时无法使用智能体 | 多级告警提前通知 |
