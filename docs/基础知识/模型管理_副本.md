# 模型管理

## 一、需求背景

### 1. 价值与目的

**价值**：把企业内部所有 LLM 模型调用统一纳入治理后台，形成"注册 → 测试 → 启用 → 调用 → 监控 → 禁用"完整闭环，并补齐配额、成本归因、降级链基础能力。

**目的**：解决现有模型管理缺乏网关层、配额、成本归因、降级链可视化的问题。

### 2. 最痛 case

OpenAI API 余额用尽，所有用 GPT-4 的智能体同时报错。平台管理员花了 2 小时定位，影响 1000+ 用户。如果有降级链，应自动切到 DeepSeek。

### 3. PR release

*   **MVP**：CRUD（按状态区分） + 连通性测试 + 启用/禁用 + 配额 + 成本归因 + 调用日志 + 能力矩阵 + 降级链基础版（手动配置主备）+ 排序/搜索/筛选/批量/导入/导出/复制；
    
*   P1：降级链可视化 + 模拟测试、自动降级、异常告警；
    
*   P2：跨区域路由、AB 实验、动态定价。
    

## 二、场景假设

| 假设        | 说明                 | 复盘点           |
| --------- | ------------------ | ------------- |
| 单网关       | 所有模型调用必经网关         | 特殊场景需旁路时重构    |
| 密钥加密      | 沿用现有加密机制           | 合规要求更高需密钥管理服务 |
| 配额硬超限     | 100% 阻断            | 用户接受度低可改软告警   |
| 成本中心必填    | 模型注册时必填成本中心        | 无成本中心体系需调整    |
| 缓存仅确定性请求  | 仅 temperature=0 缓存 | 需语义缓存时引入向量    |
| 模型负责人=创建人 | 多人协作通过协作成员         | 未来需角色矩阵       |
| 仅草稿可删     | 已启用模型只能禁用          | 防止误删历史        |

## 五、产品方案

### 1. 考虑的方案

| 方案 | 描述 | 优点 | 缺点 | 决定 |
| --- | --- | --- | --- | --- |
| A：轻量网关 | 在模型调用前加网关层 | 复用基座，开发快 | 与业务耦合 | ✅ 采用 |
| B：独立网关服务 | 部署独立服务 | 隔离干净 | 运维成本高 | ❌ 弃用 |
| C：接入 SaaS 网关 | 使用商业服务 | 开箱即用 | 数据外泄风险 | ❌ 弃用 |

### 2. 长期方案

| 维度 | MVP | P1 | P2 |
| --- | --- | --- | --- |
| 网关部署 | 与后台同进程 | 独立网关 | 多区域 |
| 路由策略 | 显式模型绑定 | 优先级 + 能力 | 成本/延迟优化 |
| 缓存 | 仅确定性请求 | 语义缓存 | 智能缓存 |
| 配额 | 三类（智能体/用户/模型） | 部门级 | 动态调整 |

### 3. 返工风险

| 返工点 | 风险 | 缓解 |
| --- | --- | --- |
| 独立网关拆分 | 高 | MVP 同进程，预留边界 |
| 语义缓存 | 中 | 预留扩展 |
| 部门级配额 | 中 | 预留部门字段 |

### 3. 模型状态机

```plaintext
   草稿 ──启用──▶ 已启用 ──禁用──▶ 已禁用 ──归档──▶ 已归档
       │              │                │                │
       │ 删除         │ 编辑(生成新草稿)  │ 启用(归档不可)  │ 恢复(仅管理员)
       ▼              └──────────────┐  │             ▼
   (已删除)                       草稿(新)         草稿
```

**转换规则**：

*   草稿 → 已启用：用户点"启用"，需通过连通性测试；
    
*   已启用 → 已禁用：用户点"禁用"，需通过影响分析确认；
    
*   已禁用 → 已启用：用户点"启用"，自动重测连通性；
    
*   已禁用 → 已归档：用户点"归档"，需通过影响分析确认；
    
*   已归档 → 草稿：仅平台管理员可"恢复为草稿"；
    
*   草稿 → 删除：仅草稿可删（输入显示名二次确认）。
    

**连通性状态**（独立于启用状态）：

*   在线：最近 ping 成功；
    
*   离线：连续 3 次 ping 失败；
    
*   未知：从未 ping 过。

#### 4.6 导入

**入口**：列表页右上角"导入"按钮。

**流程**：

1.  下载模板（CSV / JSON 二选一，列说明在模板内）；
    
2.  上传文件（≤ 5MB，校验文件类型与表头）；
    
3.  解析校验（实时显示每行校验结果：✅ / ⚠️ 警告 / ❌ 错误）；
    
4.  选择冲突处理策略：跳过 / 覆盖 / 创建副本（仅针对显示名冲突）；
    
5.  确认导入 → 进度条 → 结果汇总（成功 N / 失败 M / 跳过 K）。
    

**校验规则**（与单条创建一致）：必填项、长度限制、URL 格式、Azure API 版本等。 **错误处理**：错误行可下载"错误明细文件"（CSV 标注行号与错误原因）。 **注意**：API Key 导入为可选字段，未填写时导入后状态为"草稿"且连通性未知。

#### 4.7 导出

**入口**：列表页右上角"导出"按钮。

**弹窗**：

| 字段 | 选项 | 默认 |
| --- | --- | --- |
| 范围 | 当前筛选结果 / 选中项（多选时） | 当前筛选结果 |
| 字段 | 多选：显示名/提供方/模型ID/档位/状态/连通性/24h 调用/24h 成本/P95 延迟/创建时间/描述 | 全部 |
| 格式 | CSV / Excel | CSV |

**生成**：≤ 1000 行实时生成，> 1000 行异步生成，完成后发站内信并出现在"导出历史"（保留 30 天）。 **注意**：API Key 字段不出现在导出中（仅供运维审计使用）。
