# 天马智擎外部集成与知识图谱调研结论

## 一、结论摘要

本轮调研覆盖企业微信 CLI、企业知识图谱和钉钉知识库接入。三项均具备继续推进的基础，但成熟度和进入版本的条件不同。

| 调研项 | 可行性 | 当前最大风险 | 建议 |
|---|---|---|---|
| 企业微信 CLI | 高 | CLI 不能单独承担完整双向聊天；版本变化较快 | V1.2 做限定范围试点 |
| 企业知识图谱 | 中高 | 抽取准确率、更新失效、权限过滤和成本均需自建治理 | V1.2 做验证，V1.3 再评估正式上线 |
| 钉钉知识库 | 中 | 正文导出、附件、权限变化和文档事件覆盖需企业租户验证 | V1.2 完成技术验证，满足门槛后进入 V1.3 |

三项不建议进入 V1.1.0 主开发。V1.1.0 应继续聚焦已确认的五个产品功能。

## 二、关键判断

### 1. 企业微信确实存在官方 CLI

企业微信官方团队 WecomTeam 已维护 wecom-cli，覆盖消息、文档、日程、会议、待办、微盘和通讯录等能力。CLI 支持 Windows、Linux 和 macOS，当前公开变更日志显示版本已到 1.2.1。[^1][^2]

但 CLI 的消息能力主要是调用和主动通知。要让员工在企微中直接与天马对话，仍需企业微信智能机器人或自建应用的消息接收通道。官方插件也将 Bot WebSocket、HTTP Webhook 和 Agent 回调作为聊天通道，再把 wecom-cli 作为业务能力层。[^3]

因此推荐结构是：

    企业微信机器人/应用回调负责收发对话
      → 天马智擎负责身份、对话、权限、额度和审计
      → wecom-cli 负责文档、日程、待办等企微办公动作

### 2. 知识图谱不会随着源文件自动更新

Microsoft GraphRAG 将建图定义为显式索引流程，并单独提供 update 命令；更新结果默认写入独立输出位置。其增量代码会比较当前输入和历史文档，识别新增与删除输入。[^4][^5][^6]

Neo4j 的知识图谱构建流程同样包含加载、切分、实体关系抽取、写入和实体消歧等多个明确步骤。Neo4j 的 MERGE 可用于重复执行时匹配或创建，但官方也明确指出：只有配合唯一性或键约束，才能避免并发或异常数据产生重复节点。[^7][^8]

因此“自动更新”必须由天马的同步和任务系统完成：

    检测源变化
      → 判断新增、修改、删除或失权
      → 触发抽取或立即失效
      → 使用稳定标识写入
      → 新版本成功后切换

### 3. 钉钉知识库可接，但不能先承诺完整实时同步

钉钉开放平台提供知识库开放能力，并有知识库、文档、目录节点相关权限体系。钉钉权限分为委托权限和应用权限：委托权限只能访问授权用户本身可访问的资源，应用权限范围更大，但必须由组织管理员授权且管控更严格。[^9][^10]

钉钉 Stream 支持事件订阅和重试，但公开资料没有充分证明所有知识库文档类型都具备完整的新增、修改、删除和权限变更事件。[^11] 因此首期应采用“每日对账拉取为主，事件仅作加速”的方式，不能只依赖事件。

## 三、三项之间的关系

钉钉知识库接入解决“外部知识从哪里来”，知识图谱解决“进入天马后的知识如何形成关系”。两项必须共享来源标识、版本、权限和失效状态：

    钉钉知识库
      → 同步目录、文档、附件和权限
      → 进入现有知识入库与 RAG
      → 触发未来图谱抽取
      → 删除或失权时同时使向量与图谱来源失效

企业微信 CLI 与知识链路相对独立，但如果未来允许企微用户查询天马知识，仍必须复用天马的账号映射、知识权限和额度校验。

## 四、建议版本路线

### V1.1.0

- 不上线三项调研功能。
- 固化知识来源、失效和后台任务口径，为后续接入留出一致规则。

### V1.2

- 企业微信：选择 20–50 名内部用户，验证机器人聊天、身份映射、主动通知和 2–3 个高频 CLI 动作。
- 知识图谱：用 50–200 份脱敏文档验证抽取质量、来源追溯、修改切换和失权过滤。
- 钉钉：用一个指定知识库验证目录、正文、附件、权限和增量检测。

### V1.3

- 企微试点达到稳定性与安全标准后扩大范围。
- 知识图谱达到准确率、成本和权限验收线后，考虑正式上线文件/知识库两级图谱。
- 钉钉只有在正文与权限门槛全部通过后，才进入生产同步。

## 五、粗略投入比较

以下为产品规划级估算，不是研发排期承诺；包含需求细化、后端集成、管理配置、状态展示、测试和上线观察。

| 范围 | 估算 |
|---|---:|
| 企微限定试点 | 15–25 人日 |
| 企微扩大到多办公能力 | 30–50 人日 |
| 知识图谱验证 | 15–25 人日 |
| 知识图谱产品化一期 | 50–80 人日 |
| 钉钉单知识库验证 | 8–15 人日 |
| 钉钉指定知识库生产同步 | 25–45 人日 |

若钉钉无法直接取得正文或权限，只能增加渲染导出、逐用户授权或复杂对账，投入会明显增加，且可能不适合生产接入。

## 六、决策门槛

### 企业微信进入开发的条件

- 明确一期是“企微聊天”还是“办公动作调用”，不把二者混成一个需求。
- 企业管理员同意机器人或应用所需权限。
- 完成凭证托管、调用审计、指令白名单和高风险动作确认方案。

### 知识图谱进入产品化的条件

- 合成样本和真实脱敏样本的实体、关系准确率达到业务可接受范围。
- 修改、删除、失权和多来源失效均能正确处理。
- 单文档抽取成本、全量重建成本和查询性能可接受。

### 钉钉进入生产开发的条件

- 能通过官方能力完整取得目标文档正文和所需附件。
- 能取得或可靠重建目录与权限范围。
- 删除和失权可以在约定时间内从天马搜索、RAG 和图谱中排除。
