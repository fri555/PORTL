# 会话搜索产品调研

## 一、结论

天马需要的不是“搜索会话标题”，而是用户私有历史中的关键词检索：标题和消息正文都参与搜索，结果应展示命中片段，点击后打开原会话并定位到具体消息。

默认只查近 3 个月，每次由用户主动向前再扩展 3 个月。这个规则是天马为兼顾性能和可理解性制定的范围策略，不必强行寻找完全相同的竞品。

## 三、竞品共性

### 1. 搜索入口靠近会话列表

ChatGPT 在左侧边栏提供放大镜入口，并支持 `Ctrl+K`/`Cmd+K`。结果点击后打开原会话，可继续阅读和发送消息。[^1] 天马可复用相同心智：搜索属于历史会话管理，而不是首页全局搜索。

### 2. 标题和正文是不同命中对象

仅搜索标题会漏掉大量历史信息。ChatGPT 官方说明使用用户记得的关键词或短语查找历史会话，并可搜索归档会话。[^1] 天马应明确结果是“会话命中”还是“消息命中”，消息命中要展示命中词前后片段。

### 3. 时间过滤比一次性加载全部更可控

Slack 支持按日期范围缩小消息结果，并可继续加入发送者、位置等条件。[^2] 天马首期无需复杂筛选，但可以把时间范围作为固定渐进式加载：近 3 个月 → 更早 3 个月。

### 4. 删除与权限变化必须影响索引

ChatGPT 明确说明，删除会话后也会从搜索索引删除。[^1] 天马同样不能出现“页面已删除但搜索还能看到片段”的情况；用户退出、账号禁用或会话归属变化也必须在数据层阻止访问。

## 四、推荐结果结构

每条结果包含：

- 会话标题；
- 命中消息的角色（我/AI）；
- 命中词高亮及前后文本；
- 消息时间；
- 所属智能体或模式（如果用户能够识别）；
- 点击区域。

同一会话多条消息命中时，可以分条展示或按会话折叠，但点击必须能定位到对应消息，不应只打开会话顶部。

## 五、推荐查询流程

    用户打开会话搜索
      → 输入关键词
      → 默认搜索近 3 个月的本人会话标题和消息正文
          ├─有结果：按相关性和时间展示
          └─无结果：提示可查看更早时间
      → 页面底部显示“查看更早 3 个月”
      → 点击后追加前一个 3 个月区间
      → 点击具体结果
      → 打开原会话并定位、高亮目标消息

“更早 3 个月”是追加查询，不应清空已展示的近 3 个月结果。页面同时显示当前已经覆盖的日期范围。

## 六、搜索规则

- 首期只做关键词搜索，不做语义搜索；
- 默认同时查标题、用户消息和 AI 回答；
- 不搜索系统提示、隐藏推理、工具内部参数和已失效消息；
- 空格和常见标点不应造成明显漏搜；
- 中文关键词至少支持连续文字包含匹配；
- 大小写是否敏感必须统一，建议英文不区分大小写；
- 结果中明确高亮命中词；
- 用户只能搜索自己的会话；超级管理员也不因为角色而默认搜索他人私人会话。

## 七、状态与边界

| 场景 | 产品处理 |
|---|---|
| 未输入关键词 | 展示搜索说明或最近搜索，不发起全量查询 |
| 查询中 | 保留输入内容并显示加载状态 |
| 当前 3 个月无结果 | 提示无结果，并提供“查看更早 3 个月” |
| 已查到最早记录 | 底部显示“已显示全部可搜索记录” |
| 原消息已删除 | 不展示；若索引延迟导致点击失败，提示内容已不存在并刷新结果 |
| 原会话无权访问 | 不展示，直接地址也无法打开 |
| 定位消息较早 | 打开后自动加载到目标附近，而不是要求用户手动滚动 |

## 八、对 V1.1.0 的决策

1. 标题与消息正文都搜索。
2. 默认近 3 个月，每次向前扩展 3 个月。
3. 结果展示命中片段并精确定位原消息。
4. 仅关键词搜索，不做语义检索。
5. 严格遵守会话归属，超级管理员也不获得私人会话搜索特权。
