# 天马智擎 V1.1.0 十一项需求中的九项调研与前端参考

## 一、调研结论总览

V1.1.0 共包含十一项需求。第一项“本名花名规范化”和第二项“操作审计日志”依据公司内部规则及现有系统能力形成需求，不开展竞品调研；其余九项均已完成产品模式、业务边界和前端参考调研。其中六项可按已澄清范围进入 V1.1.0 产品评审，后三项不建议直接在 V1.1.0 正式上线，分别进入后续版本试点或技术验证。

## 二、前端参考使用方式

参考页面不是为了整页照抄，而是用于确认特定产品问题。

### 1. 用量计费明细

重点看 OpenAI 的月份、项目和费用筛选，以及 Langfuse 的用户、模型、会话和成本下钻。天马额外增加部门、模式和智能体，不采用普通用户可见的个人账单。

### 2. 观远运营看板

重点看 Metabase 的应用内嵌、筛选、只读模式和点击下钻。天马界面只保留“仪表盘—AI 运营看板”入口，图表本身由观远搭建。

### 3. 上下文主动建议

重点看 Teams 动画中的回答下方按钮、点击即回传消息，以及 Genie 的上下文建议。天马固定三条，只允许最新一组继续点击。

### 4. 快捷提示语

重点看 Microsoft Copilot 将所选提示插入消息输入框、允许修改后发送，以及“你的提示”仅本人可见；TypingMind 用于参考自建提示语的名称、正文和个人列表。采用用户截图中的“分类—提示语”二级结构：分类非必填，未分类内容进入“未分组”；每人最多 100 条，名称最多 20 个字符，正文最多 10000 个字符。

### 5. 会话搜索优化

重点看 ChatGPT 左侧搜索入口和点击回会话，以及 Slack 的消息片段、高亮和时间筛选。天马新增明确的 3 个月分段加载文案。

### 6. 特殊文档解析

重点参考 Azure 的结构化解析结果，以及 Dify 的来源、处理进度和失败反馈。天马先区分本地文件与在线文档：本地 Excel 使用结构保留解析，PPT/PPTX 自动转 PDF 后解析；在线文档按来源节点类型处理，不设置人工解析勾选框。

### 7. 企业微信CLI

重点看企业微信管理后台机器人创建、连接方式、授权凭据和聊天效果。天马后台需要单独显示连接状态、授权状态、最近成功时间和错误，不把命令行作为最终产品界面。

### 8. 知识图谱

重点看 Neo4j KG Builder 的上传—抽取—图谱—问答—来源链路，以及 Bloom 的搜索、展开、图例和详情卡。普通用户界面与管理员治理界面必须分开。

### 9. 钉钉知识库打通

重点看 Soiawork 的应用创建与权限配置、用户截图中的账号绑定和目录树多选、FastGPT 的知识库/文件夹/文档选择及同步，以及钉钉 AI 助理的学习进度。天马将其转成“凭证授权—选择范围—选择保存位置—持续同步—状态与失败处理”，不采用一次性复制到个人文件空间的语义，并复用现有知识中心与 RAG。

## 五、统一产品关系

    统一人员身份
      ├─本名、当前花名 → 同一用户 ID
      └─人员搜索、展示、统计、授权和跨渠道映射共同使用

    统一操作审计
      ├─MCP、工具、Skill、模型、供应商和智能体变更
      ├─知识库、文件夹和文档变更
      └─追加式脱敏记录 → 设置中的审计日志

    用户成功对话
      ├─实际结算 → 用量计费明细
      ├─有效轮次 → 运营数据集 → 观远看板
      ├─回答正文 → 上下文主动建议
      ├─个人快捷提示语 → 插入输入框 → 用户确认发送
      └─会话消息 → 会话搜索优化

    知识来源
      ├─本地 Excel → 结构保留解析
      ├─本地 PPT/PPTX → 转 PDF → PDF 版面解析
      ├─在线文档 → 按来源节点类型处理
      ├─未来钉钉知识库打通 → 定时同步与失效
      └─统一知识中心与 RAG
          └─未来知识图谱作为派生索引

    外部使用渠道
      └─企业微信机器人/应用 → 天马账号、权限、额度和知识能力

这些链路共享统一身份、权限、状态、操作追踪和来源标识。任何后续设计都不应为观远、钉钉、企业微信或知识图谱分别建立互不兼容的账号、审计与知识体系。
