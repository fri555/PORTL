# 企业微信 CLI 集成可行性调研

## 一、研究结论

企业微信 CLI 接入可行，建议进入 V1.2 小范围试点，但不能把“CLI 接入”等同于“企微聊天接入”。

推荐方案：

    企业微信智能机器人或自建应用
      → 负责用户消息进入、回复和主动通知
      → 天马智擎负责账号映射、对话、权限、额度与审计
      → wecom-cli 作为受控办公能力层
      → 调用文档、待办、日程、会议、微盘和通讯录

## 二、官方能力现状

企业微信官方团队 WecomTeam 已提供 wecom-cli。公开 README 显示它覆盖消息、邮件、文档、文档管理、在线表格、智能表格、智能文档、待办、日程、会议、微盘和通讯录，支持 Windows、Linux 和 macOS，依赖 Node.js 18 及以上。[^1]

截至 2026-09-11，公开变更日志最新版本为 1.2.1。1.1.0 曾发生鉴权命令、凭据文件、命令模型和服务名称的集中调整，说明产品仍处于快速演进期，集成时必须锁定版本并设置升级验证，不能长期跟随 latest。[^2]

CLI 可通过扫码或 Bot ID、Secret 完成授权；凭据默认使用 AES-256-GCM 加密，文件权限为 0600，加密密钥优先放系统 keyring。服务目录和方法定义在线获取，查看帮助和实际调用都需要凭据与网络。[^3]

## 三、消息能力边界

### 主动通知

CLI 支持向最近与机器人互动过的单聊或群聊发送 Markdown、图片、文件、语音和视频。[^1] 这意味着它适合：

- 任务完成通知；
- 审批或待办提醒；
- 定时报表和异常提醒；
- 用户在企微触发任务后的异步结果返回。

“最近互动过”是重要边界，不能直接理解为可以向任意群或任意员工无限制主动推送。

### 双向聊天

CLI 本身是命令调用工具，不负责持续接收所有企微用户消息。企业微信自建应用可配置接收消息，回调需要 URL、Token 和 EncodingAESKey，并进行签名校验与消息解密。官方资料说明，回调超时会重试，消息应使用 msgid 或事件组合键排重。[^4]

企业微信官方 OpenClaw 插件进一步展示了两类聊天入口：智能机器人可使用 WebSocket 或 HTTP Webhook，自建应用使用加密 HTTP 回调；插件同时支持单聊、群聊、流式回复和主动消息，再内置 wecom-cli 执行业务动作。[^5]

因此：

- 只做通知：可以用 CLI 或现有应用消息能力。
- 要在企微里直接问天马：必须建设机器人/应用消息通道，CLI 只做工具层。
- 要执行高风险办公动作：必须增加确认、白名单和审计，不能让模型自由调用全部 CLI 命令。

## 四、建议的一期范围

一期限定 20–50 名内部用户，只开放四类能力：

1. 在企微单聊机器人向天马提问。
2. 接收天马任务完成或失败通知。
3. 查询本人日程或创建待办。
4. 搜索或读取本人已有权限的企业微信文档。

暂不开放：

- 代表用户群发消息；
- 删除文档、日程或待办；
- 修改文档权限；
- 读取大范围通讯录；
- 自动执行会议邀请、批量写入和其他高影响操作。

## 五、身份与权限

### 账号映射

以企业微信企业 ID 加成员 UserID 作为外部身份，与天马账号一一绑定。不能只按姓名或手机号匹配。

### 权限原则

- 企微用户触发天马时，先通过天马账号状态、产品开通和额度检查。
- CLI 查询文档、日程等内容时，仍受企业微信侧授权范围约束。
- 天马不能因为持有企业级 Bot 凭据，就默认向所有用户开放全部企业信息。
- 超级管理员负责启停企业微信集成和查看审计，不直接代替普通用户的内容权限。

### 凭证

生产环境不建议依赖个人电脑上的默认配置目录。应使用独立服务账号或企业机器人，将配置目录隔离到服务器受控路径，并由密钥管理能力保护解密密钥。

## 六、完整数据流

### 用户提问

    用户在企微向机器人发消息
      → 企业微信消息通道推送给天马
      → 校验签名、解密并按消息 ID 排重
      → 映射天马账号并检查启用状态与额度
      → 创建天马会话或续接原会话
      → AI 回答
      → 回复企微并记录审计

### 调用办公动作

    AI 判断需要企微工具
      → 检查动作是否在白名单
      → 高影响动作要求用户确认
      → 调用锁定版本的 wecom-cli
      → 解析结构化结果
      → 成功则回复用户
      → 失败则按错误类型重试或提示人工处理

## 七、可靠性和安全风险

| 风险 | 影响 | 建议 |
|---|---|---|
| CLI 快速迭代并发生破坏性变更 | 命令和返回格式失效 | 锁定版本；升级前跑回归 |
| 在线发现服务与方法 | 无网络或凭据时帮助和调用都不可用 | 缓存可用目录；设置健康检查 |
| 消息重复推送 | 重复回答或重复执行动作 | 使用消息 ID 幂等 |
| 高风险写操作 | 错发、误删或越权 | 白名单、二次确认、审计 |
| 凭据落地 | 服务器凭据泄露 | 独立账号、受控目录、密钥托管 |
| 默认遥测 | 调用 Agent 程序名和调用链回传企业微信云端 | 安全评审后决定是否从源码关闭 |

wecom-cli 官方数据收集说明显示，预编译版本默认启用 call-chain，会回传调用它的 Agent 程序名称及调用链路，用于问题定位；如不希望回传，需要从源码关闭该编译特性。[^6] 这应作为安全评审项，而不是上线后再处理。

## 八、版本与投入建议

### 版本建议

- V1.1.0：只保留调研结论。
- V1.2：限定用户、限定动作试点。
- 试点稳定后：再评估扩大用户和办公能力。

### 粗略投入

| 范围 | 估算 |
|---|---:|
| 消息通道与账号映射验证 | 5–8 人日 |
| 限定范围试点完整交付 | 15–25 人日 |
| 增加文档、日程、待办等多能力 | 30–50 人日 |

估算包含产品细化、企业应用配置、消息通道、身份映射、CLI 封装、权限确认、审计、错误重试、测试和试点观察，不包含企业内部安全审批等待时间。

## 九、试点验收门槛

- 企微消息可以稳定进入天马并正确回复。
- 重复回调不会重复发送或重复执行动作。
- 停用或未开通账号无法使用。
- 企微与天马账号映射可审计、可解绑。
- CLI 版本固定，升级失败可回退。
- 高风险动作没有确认时不能执行。
- 凭证、消息正文和用户隐私不出现在普通日志中。
