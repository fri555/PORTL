# 关于本文档

## 内容说明

本文档用于描述AI工作台功能的产品需求定义。本功能为对话交互增强套件：在用户与智能体的对话流程中，提供文件沉淀、知识库回存、内容引用、收藏管理、对外分享等能力，解决「对话中产生的有价值内容无法复用与流转」的核心痛点。

文档覆盖六个核心模块：

*   **可见与沉淀**：右侧会话文件面板、意图识别保存+澄清卡
    

*   **内容复用**：文件引用、引用追问
    

*   **内容协作**：消息收藏、批量分享
    

文档涵盖功能描述、处理逻辑规则、界面定义、数据模型、提示词定义等方面，是本功能唯一的全面需求定义文档。产品经理随功能变化及时修订，阅读时请从文档管理系统获取最新版本。

# 产品概述

## 产品概述

「对话增强」是AI工作台 V1.1 的对话交互增强套件。当前对话流程中，用户在长对话里产生的文件、结论、可复用内容存在三个问题：

1.  **难追溯**——Agent 产出的报告、脚本、数据表散落在消息流中，无法快速定位
    
2.  **难沉淀**——对话中的高价值内容需要手动复制到知识库，路径长、损耗大
    
3.  **难流转**——想把对话片段分享给同事时，只能截图或复制粘贴，没有原生通道
    

本功能提供从「内容产出 → 沉淀 → 复用 → 协作」的完整闭环，让 AI 对话从「一次性问答」升级为「可沉淀的协作起点」。

核心定位：**让对话内容可被检索、可被引用、可被分享、可被沉淀**。

## 产品范围

**本期范围内：**

*   右侧会话文件面板（280px 抽屉 + 文件夹分组 + 搜索）
    

*   对话输入框文件引用（FileCard hover + PromptBox + 拓展）
    

*   单条对话引用追问（hover 操作栏 + 引用块渲染）
    

*   消息收藏 + 全屏选择器 + 卡片化收藏夹
    

*   批量分享（链接生成 / 发送钉钉，含密码保护）
    

*   意图识别「保存到知识库」+ 内联澄清卡（手动 / 意图双入口）
    

## 产品目标

*   **业务目标**：让 AI 对话中产生的有价值内容（文件、结论、复用素材）能顺畅沉淀到团队知识库；让团队成员之间能高效分享 AI 给出的方案与脚本
    
*   **模型目标**：~~意图识别能稳定命中「保存到知识库」类自然语言指令，覆盖常见表达；~~同组分享复用的密码与链接保持一致
    
*   **效率目标**：让用户在新一次提问中能快速复用之前的文件与对话片段，无需切换窗口查找；让单条对话内容具备被多次引用的能力

### 会话文件面板

#### 功能需求描述

在对话页面右侧新增抽屉面板，展示当前会话中 Agent 产生的所有文件，支持文件夹分组、搜索、折叠等基础交互。文件格式覆盖所有对话生成文件的格式。

#### 用户角色与用户故事

作为一名AI工作的普通用户，我在与 AI 协作后，希望在对话右侧随时看到本轮产生的报告文件，方便我点击预览或直接引用，无需离开对话窗口，也无需在对话中翻找。

              ↓

              ↓
   用户点击右侧文件面板
              ↓
   右侧文件面板自动打开
              ↓
   用户操作：
     ├── 搜索 → 实时过滤文件名
     ├──
     ├── 点击文件 → 触发预览

```
```

### 文件保存到知识库

#### 功能需求描述

当 Agent 在对话中产生文件后，用户可通过两种入口保存到知识库：

*   **手动入口**：文件hover 显示「保存」按钮 → 触发浮动弹窗（弹窗式澄清卡）
    

*   **意图入口**：用户在对话中描述如「把XX保存到YY知识库的ZZ文件夹」 → 命中意图 → 展示内联澄清卡【本期不做】
    

澄清卡层级选择：知识库（固定个人空间） → 文件夹。知识库和文件夹不存在时提供创建功能，复用原知识库逻辑。

#### 用户角色与用户故事

作为普通用户，我在与 AI 协作后，对话中说「把XX报告保存到集团制度的财务制度文件夹」，希望系统能自动识别我的意图，弹出澄清卡让我确认，无需手动点按钮。或者我可以直接点击文件的保存按钮手动选择保存到知识库。

#### 业务主流程图及说明

手动入口流程：

```plaintext
```
文件鼠标移入展示快捷功能 → 点保存按钮
                ↓
           弹窗显示澄清卡
                ↓
   用户选 知识库（固定个人空间） → 文件夹（可选）
                ↓
   确认保存 → 弹窗关闭 + toast反馈「已保存到 XX空间/XX知识库/XX文件夹」
```
```

#### 分支流程（异常流程）

a) 澄清卡必填字段为空 → 保存按钮禁用。

b) 文件重复保存时，toast反馈「已保存到 XX空间/XX知识库/XX文件夹」。

c) 保存失败 → toast「保存失败，请重试」+ 澄清弹窗保持可编辑。

d) 手动保存时用户点「取消」→ 弹窗关闭，不执行保存，对话不再提示。

e）部分生成文件类型不支持解析，无法保存，点击「保存」后toast提示「该文件类型暂无法解析和保存到知识库，技术推进中」。

3）新增知识库和文件夹沿用现有知识中心的字段校验逻辑与接口。

4）文件保存到知识库后，保留对话中的文件。

### 文件引用

#### 功能需求描述

支持在新提问中引用之前产生的会话文件，作为上下文传给智能体：

# 附录 A EARS 标注说明

本文档需求句遵循 EARS 五种模式，便于开发 / 测试对齐边界：

1.  **普遍型**（Ubiquitous）：无条件全局规则
    
    *   例：操作栏 hover 必须显示按钮名称 Tooltip
        
    *   例：localStorage key 命名以 `tianma_` 前缀
        
2.  **事件驱动型**（Event-driven）：用户操作触发
    
    *   例：当用户点击「收藏」按钮时，打开 BookmarkSelector
        
    *   例：当用户点击「分享」按钮时，打开 ShareConfigDialog
        
3.  **状态驱动型**（State-driven）：系统特定状态下保持行为
    
    *   例：当文件已保存到 KB 时，文件从 sessionFiles 中移除
        
    *   例：当用户已选消息数量 > 0 时，「复制」按钮启用
        
4.  **不良行为型**（Unwanted Behavior）：异常处理
    
    *   例：当意图识别未命中时，不触发 SaveIntentCard
        
    *   例：当 localStorage 写入失败时，不崩溃，仅 console.error
        
5.  **可选型**（Optional）：依赖功能是否开启
    
    *   例：当勾选密码开关时，显示密码输入框
        
    *   例：当用户进入对话时，默认打开文件面板（可被关闭）
