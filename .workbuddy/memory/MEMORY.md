## 钉钉表格 MCP 关键坑（实操踩过，复用）
- 范围字段名不统一：`update_range` / `get_range_as_csv` 用 `rangeAddress`；但 `merge_range` / `unmerge_range` 在 `batch_update` 子操作里用 **`range`**（曾误用 rangeAddress 报 Invalid range notation，整批回滚）。
- `fill_range`(fillType=onlystyle) **不能跨合并单元格**(报 invalid_cmd_autofill_in_mergecells)。实测坑：`unmerge_range` 对含多个合并的区域常清不干净（整片 fill 仍报 mergecells 回滚）。**最稳做法：直接用 `update_range` 写 `backgroundColors` 二维数组——它对合并单元格安全，只写合并区左上角，完全绕开 fill_range**。若坚持用 fill_range：必须 `unmerge_range` 一次覆盖整片数据区(如 `A4:U248`)，刷色后再 `batch_update` 重新合并；调色板辅助单元格记得 `clear_range` 清掉。
- **`fill_range` 会平铺(tiling)**：源比目标小也能刷——已验证 1×5 源→88×5 目标、1×1 源→283×1 目标均成功（按源形状向下/向右重复）。**大批量上色最佳实践**：先在远处调色板(Z列)写好各色 1×N 单元格，再 fill_range 平铺到各目标块，避免手写几百行 backgroundColors 二维数组（易因手抖漏行报错 "data has X but range has Y"）。
- `update_range` 支持 `backgroundColors`/`fontColors`/`fontWeights` 二维数组(外层数组≤1000行)，比 fill_range 灵活但需手写大数组；适合给少数整行上色。
- 大批量写实值用 `set_range_from_csv`(csv 参数，单 chunk ~30KB 稳定)，BOM 用 utf-8 无 BOM；`allowOverwrite=true` 覆盖；range 自动扩容。
- `batch_update` 单次 ≤20 子操作，严格事务(遇错整批回滚)；支持的 toolName 含 merge_range/unmerge_range/fill_range/clear_range/set_range_from_csv 等，但**不含 update_range**(需单独调用)。
