# 用户研究综合报告：AI工作门户首页智能体 MVP

> **项目**：AI工作门户 PRD  
> **模块**：首页智能体（日常办公 / 专家 / 定时任务 三种模式）  
> **研究方法**：用户故事地图综合分析  
> **分析人**：瑞思（Reese），用户研究员  
> **日期**：2026-07-08  
> **数据来源**：5阶段用户故事地图（发现进入 / 尝试使用 / 深度使用 / 沉淀复用 / 反馈建议）

---

## 一、核心用户画像

基于用户故事地图中5个阶段的行为特征和需求分布，推断出以下4类核心用户画像。MVP阶段优先覆盖画像A和画像B（覆盖面最广），画像C和画像D作为后续迭代重点。

### 画像A：日常办公用户 —— "快进快出型"

| 维度 | 描述 |
|------|------|
| **典型角色** | 全体员工（行政、运营、市场、HR等非技术岗） |
| **使用频率** | 高频，每日多次 |
| **核心诉求** | 快速得到答案，完成即走，不想学习复杂操作 |
| **关键场景** | 写邮件/通知、查制度/流程、翻译、格式整理、信息检索 |
| **故事地图映射** | 发现进入（首页搜索框、常用技能区、今日推荐）→ 尝试使用（快速问答、引导示例） |
| **行为特征** | 依赖推荐引导，倾向使用一句话输入；对多轮对话耐心有限；期望"输入即得到结果" |
| **成功标准** | 首页一句话输入 → 3秒内进入对话 → 1-2轮获得满意答案 |

### 画像B：专业领域用户 —— "深度协作型"

| 维度 | 描述 |
|------|------|
| **典型角色** | 产品经理、数据分析师、技术文档工程师、会议组织者 |
| **使用频率** | 中高频，每周3-5次深度使用 |
| **核心诉求** | 需要专业领域Agent辅助完成高质量产出（文档、报告、纪要），期望可引用内部知识 |
| **关键场景** | 撰写PRD/方案、整理会议纪要、生成数据分析报告、产出需求草稿/任务清单 |
| **故事地图映射** | 深度使用（对话式工作台、知识增强、智能体协作、工具调用、产出承接） |
| **行为特征** | 需要上下文连续性；关注产出质量与可引用性；会反复迭代优化；有导出需求 |
| **成功标准** | 选择专家 → 上传资料/提供上下文 → 多轮协作迭代 → 导出可用文档 |

### 画像C：效率自动化用户 —— "一次配置持续受益型"

| 维度 | 描述 |
|------|------|
| **典型角色** | 团队Leader、项目经理、运维人员、行政主管 |
| **使用频率** | 低频配置 + 高频被动消费（每日接收自动产出） |
| **核心诉求** | 将重复性工作自动化，配置一次后持续运行，通过钉钉接收结果 |
| **关键场景** | 自动日报/周报、定时巡检、周期性数据汇总、定期提醒推送 |
| **故事地图映射** | 沉淀复用（自动化任务、定时任务、钉钉提醒、周期报告、任务取消） |
| **行为特征** | 配置门槛敏感（怕配错）；需要任务运行状态可见；期望异常时能及时干预 |
| **成功标准** | 配置定时任务（<5分钟）→ 自动运行 → 钉钉收到结果 → 可随时取消/修改 |

### 画像D：团队管理者 / 需求提出者 —— "治理反馈型"

| 维度 | 描述 |
|------|------|
| **典型角色** | 部门负责人、IT管理员、业务线Owner |
| **使用频率** | 低频，按需 |
| **核心诉求** | 了解团队AI使用情况；提出需求并跟踪流转；评估试用效果 |
| **关键场景** | 查看部门用量/Token消耗、提交业务痛点需求、验收试用功能、查看迭代公告 |
| **故事地图映射** | 沉淀复用（运营治理、团队共享）+ 反馈建议（需求提报、需求流转、试用验收、迭代公示） |
| **行为特征** | 关注ROI与治理；需要可视化看板；期望需求闭环透明可追踪 |
| **成功标准** | 提交需求 → 可追踪状态 → 试用验收 → 收到上线通知 |

> **画像优先级矩阵**（MVP聚焦）
> 
> | 画像 | MVP覆盖度 | 理由 |
> |------|-----------|------|
> | A 日常办公用户 | ★★★★★ 全覆盖 | 用户基数最大，是门户的"流量入口" |
> | B 专业领域用户 | ★★★☆☆ 框架+1-2专家 | 验证专家模式可行性，先搭框架 |
> | C 效率自动化用户 | ★★☆☆☆ 基础定时任务 | 验证自动化闭环，功能可简化 |
> | D 团队管理者 | ★☆☆☆☆ 延后 | 运营治理非MVP核心，后续迭代 |

## 二、用户核心需求分层（按三种模式归类）

> 分层原则：**MVP必须满足** = 功能闭环最小集，缺少则模式不成立；**后续迭代** = 增强体验与扩展能力，可延后。

### 2.1 日常办公模式

| 需求项 | 来源（故事地图阶段） | 优先级 | 说明 |
|--------|---------------------|--------|------|
| 首页一句话任务输入 | 尝试使用-快速问答 | **MVP必须** | 核心入口，一句话→识别意图→进入对话 |
| 回车发起任务 | 尝试使用-快速问答 | **MVP必须** | 最简交互方式 |
| 意图识别与模式联动 | 尝试使用-快速问答 | **MVP必须** | 系统根据输入内容推荐切换到合适模式 |
| 推荐示例/场景提示词 | 尝试使用-引导示例 | **MVP必须** | 降低首次使用门槛，引导用户正确输入 |
| 快捷功能切换 | 尝试使用-快速问答 | **MVP必须** | 三种模式间手动切换（Tab/下拉） |
| 常用技能区展示 | 发现进入-首页认知 | **MVP必须** | 首页可见常用能力，快速触达 |
| 今日推荐/新能力提示 | 发现进入-首页认知 | MVP必须 | 告知用户新能力，提升认知 |
| 多轮上下文对话 | 深度使用-对话式工作台 | MVP必须 | 问答场景需支持追问 |
| 全屏对话工作台 | 深度使用-对话式工作台 | **后续迭代** | PRD已明确首页即工作台，不做全屏页 |
| 历史会话与搜索 | 深度使用-会话连续性 | **后续迭代** | 首期可做简单历史列表 |
| 会话命名与收藏 | 深度使用-会话连续性 | **后续迭代** | 体验增强项 |
| 个性化推荐（岗位/部门/最近使用） | 发现进入-个性化推荐 | **后续迭代** | 需要用户行为数据积累，首期用静态推荐 |
| 全局搜索（技能/智能体/知识库） | 发现进入-全局搜索 | **后续迭代** | MVP阶段首页搜索框聚焦任务发起 |
| 个人模板/快捷入口 | 沉淀复用-个人复用 | **后续迭代** | 沉淀能力，需使用数据支撑 |

## 三、关键用户旅程（按三种模式）

### 3.1 日常办公模式旅程

```
[钉钉/浏览器/SSO入口]
        │
        ▼
[首页加载] ── 看到搜索框 + 常用技能区 + 今日推荐 + 推荐示例
        │
        ▼
[一句话输入任务] ── "帮我写一封项目启动会邀请邮件"
        │                    │
        │                    ├─ (新手) 点击推荐示例 → 自动填充输入
        │                    └─ (熟手) 直接输入 → 回车发起
        │
        ▼
[系统识别意图] ── 判断为"写作辅助"类 → 进入日常办公对话
        │                    │
        │                    └─ (如识别为专家场景) → 提示切换专家模式
        │
        ▼
[对话交互] ── AI返回邮件草稿
        │
        ├─ 满意 → 复制/导出 → 完成（快进快出）
        │
        └─ 需修改 → 追问"加上时间地点和参会人员" → AI修改 → 满意 → 完成
        │
        ▼
[可选] 收藏为常用 / 查看历史会话（后续迭代）
```

**旅程关键指标**：
- 首页加载到首次输入时间：< 5秒
- 输入到首次响应时间：< 3秒
- 单次会话平均轮数：1-3轮
- 任务完成率（用户得到满意答案）：目标 > 80%

### 3.2 专家模式旅程

```
[首页]
        │
        ▼
[切换到专家模式] ── Tab/下拉选择"专家"
        │
        ▼
[专家列表展示] ── 看到可用专家（写作助手、会议纪要整理）
        │                    │
        │                    ├─ 能力卡片：说明每个专家能做什么、适用场景
        │                    └─ 权限状态：是否可用
        │
        ▼
[选择专家] ── 例如选择"会议纪要整理"
        │
        ▼
[提供上下文] ── 输入会议信息 / 粘贴会议记录 / (后续)上传录音文件
        │
        ▼
[专家处理] ── AI按专家能力结构化整理
        │
        ▼
[查看产出] ── 生成结构化会议纪要
        │
        ├─ 满意 → 导出为文档 → 完成
        │
        └─ 需修改 → "补充行动项负责人和截止日期" → AI修改 → 满意 → 导出
        │
        ▼
[可选] 切换其他专家 / 收藏会话 / 保存为模板（后续迭代）
```

**旅程关键指标**：
- 专家模式切换到专家列表加载时间：< 2秒
- 专家选择到首次产出时间：< 10秒
- 产出可用率（用户认为产出可直接使用或微调后可用）：目标 > 70%
- 专家切换频率：反映用户跨领域需求

### 3.3 定时任务模式旅程

```
[首页]
        │
        ▼
[切换到定时任务模式] ── Tab/下拉选择"定时任务"
        │
        ▼
[任务配置入口] ── "创建新任务" 或 选择模板（日报/周报/巡检）
        │
        ▼
[配置任务参数]
        │  ┌─ 触发条件：每天/每周/自定义周期
        │  ├─ 执行时间：如每天18:00
        │  ├─ 任务内容：如"汇总今日项目进展，生成日报"
        │  └─ 推送方式：钉钉消息通知
        │
        ▼
[确认并创建] ── 预览配置 → 确认
        │
        ▼
[任务自动运行] ── 到达触发时间 → 系统自动执行
        │
        ▼
[接收结果] ── 钉钉收到日报推送 + 门户内可查看
        │
        ├─ 满意 → 任务持续运行（一次配置持续受益）
        │
        └─ 需调整 → 修改任务参数 / 取消任务
        │
        ▼
[我的任务列表] ── 查看所有定时任务及运行状态（后续迭代：进度/异常）
```

**旅程关键指标**：
- 任务配置完成时间（从进入到确认）：< 5分钟
- 模板使用率：目标 > 60%（反映模板降低了门槛）
- 任务持续运行率（7天后仍活跃）：目标 > 50%
- 钉钉推送到达率：目标 > 99%

## 四、用户痛点与机会点

### 4.1 痛点提炼

| # | 痛点 | 证据来源（故事地图） | 影响 | 频率 | 痛点指数 |
|---|------|---------------------|------|------|----------|
| P1 | **能力认知摩擦** — 用户不知道门户有什么能力、自己能用什么 | 发现进入：能力说明、权限状态、适用场景均为独立故事项，说明当前认知成本高 | 高 | 高 | ★★★★★ |
| P2 | **模式选择困惑** — 三种模式用户不知如何选择，也不清楚各模式边界 | 设计决策"用户手动选择模式"+ 尝试使用阶段"快捷功能切换"反复出现 | 高 | 高 | ★★★★★ |
| P3 | **首次使用门槛高** — 新用户不知如何输入、输入什么 | 尝试使用：引导示例、场景提示词、任务模板、优秀案例均为独立需求 | 中 | 高 | ★★★★☆ |
| P4 | **上下文断裂** — 多轮对话中上下文丢失，需重复输入 | 深度使用：多轮上下文、历史会话、会话命名——这些需求的存在反推当前体验有断裂 | 高 | 中 | ★★★★☆ |
| P5 | **产出不可直接用** — AI产出需要大量人工二次加工 | 沉淀复用：产出承接（生成文档/PPT/需求草稿/任务清单）——用户期望直接可用格式 | 高 | 中 | ★★★★☆ |
| P6 | **知识不可引用** — 无法引用企业内部知识库，回答缺乏专业性 | 深度使用：知识库引用、资料检索、来源展示、权限控制——需求密集 | 高 | 中 | ★★★★☆ |
| P7 | **自动化配置复杂** — 创建定时任务门槛高，用户怕配错 | 沉淀复用：定时任务、任务取消——用户需要取消功能说明存在配错场景 | 中 | 中 | ★★★☆☆ |
| P8 | **反馈无闭环** — 提交需求/反馈后看不到处理进度和结果 | 反馈建议：需求流转、状态漏斗、流转时间线、当前处理人——需求的存在反推当前无闭环 | 中 | 高 | ★★★★☆ |
| P9 | **外部系统割裂** — AI无法直接调用/跳转外部系统完成任务 | 深度使用：工具调用、MCP能力、外部系统跳转、流程执行 | 中 | 中 | ★★★☆☆ |
| P10 | **团队协作缺失** — 无法共享技能/知识/任务给团队 | 沉淀复用：部门空间、能力市场、安装部署、权限分配 | 中 | 低 | ★★☆☆☆ |

### 4.2 机会点提炼

| # | 对应痛点 | 机会点 | MVP可行性 | 预期价值 |
|---|----------|--------|-----------|----------|
| O1 | P1 能力认知摩擦 | **首页"能力发现层"设计** — 常用技能区 + 今日推荐 + 推荐示例三合一，让用户30秒内理解"这里能做什么" | ✅ 高 | 降低认知成本，提升首次转化 |
| O2 | P2 模式选择困惑 | **模式引导卡片** — 每个模式配一句话说明+典型场景图标，切换时展示"这个模式适合做什么" | ✅ 高 | 减少模式选择犹豫，降低误选率 |
| O3 | P3 首次使用门槛 | **场景化提示词模板** — 按岗位/场景预置提示词，点击即用，消除"空白输入框焦虑" | ✅ 高 | 提升首次任务发起率 |

| O7 | P7 自动化配置复杂 | **定时任务模板化** — 预置日报/周报/巡检模板，用户只需选模板+改参数，不用从零配置 | ✅ 高 | 降低配置门槛，提升任务创建成功率 |
| O8 | P8 反馈无闭环 | **MVP最小反馈入口** — 首页提供"反馈/提需求"入口，提交后展示"已收到"状态。完整流转看板后续迭代 | ✅ 高 | 让用户感受到反馈被听到，建立信任 |
| O9 | P9 外部系统割裂 | 后续迭代 — 通过MCP协议逐步接入外部系统 | ❌ 延后 | 打通工作流 |
| O10 | P10 团队协作缺失 | 后续迭代 — 部门空间与能力市场 | ❌ 延后 | 促进组织级AI能力沉淀 |

## 五、MVP用户研究结论与建议

### 5.1 整体研究结论

**结论一：首页是"认知战场"，不是"功能堆叠"**

用户故事地图中"发现进入"阶段的故事项密度最高（入口触达、首页认知、个性化推荐、能力说明、全局搜索共5个子维度），说明用户在首页最大的挑战是**"发现和理解能力"**，而非使用能力本身。MVP首页设计的核心目标应该是**降低认知摩擦**，让用户在3秒内理解"这里能做什么、我该怎么开始"。

> **建议**：首页布局采用"搜索框为中心 + 模式切换Tab + 常用技能区 + 推荐示例"的四层结构，而非功能列表式排列。搜索框是最宽入口（兼容三种模式），Tab是模式切换的显性入口，常用技能区和推荐示例承担"能力发现"和"降低首次使用门槛"的功能。

**结论二：三种模式的用户心智模型不同，不能强行统一交互**

- **日常办公模式**：用户心智是"问一个问题，得一个答案"——快进快出，交互以搜索框+单轮/少轮对话为主
- **专家模式**：用户心智是"找一个专家，协作完成一个产出"——有明确目标，交互以专家选择+多轮迭代+导出为主
- **定时任务模式**：用户心智是"配一个规则，让它自动跑"——低频配置高频消费，交互以表单配置+模板选择+通知接收为主

> **建议**：三种模式共享首页框架（搜索框+Tab切换），但切换到不同模式后，**下方的交互区域应适配该模式的心智模型**——日常办公展示推荐示例和快捷入口，专家模式展示专家卡片列表，定时任务模式展示任务模板和"我的任务"列表。

**结论三：MVP的成功取决于"闭环完整度"而非"功能数量"**

从故事地图看，5个阶段形成完整闭环：发现→尝试→深度使用→沉淀→反馈。MVP不需要覆盖所有阶段的所有故事，但**每个模式必须形成自己的最小闭环**：

- 日常办公：输入→对话→得到答案（闭环）
- 专家：选专家→提供上下文→得到产出→导出（闭环）
- 定时任务：选模板→配置→自动运行→钉钉通知（闭环）

> **建议**：MVP优先保证三个最小闭环的完整性和流畅度，砍掉非闭环必需的增强功能（如个性化推荐、知识库、运营看板、需求流转看板等）。

### 5.2 日常办公模式专项建议

| 建议 | 依据 | 优先级 |
|------|------|--------|
| 搜索框作为首页第一视觉焦点，支持一句话输入+回车发起 | 故事地图"快速问答"为尝试使用阶段首要故事 | P0 |
| 搜索框下方展示3-5个推荐示例（可轮播），按热门场景排列 | "引导示例"需求表明用户需要输入引导 | P0 |
| 常用技能区放在搜索框下方，展示6-8个高频技能入口 | "常用技能区"在首页认知阶段出现 | P0 |
| 模式切换Tab放在搜索框上方或左侧，默认选中"日常办公" | 设计决策"用户手动选择模式"，默认模式应为最高频的日常办公 | P0 |
| 系统根据输入内容推荐模式切换（非强制） | "推荐示例联动"暗示系统应具备意图识别能力 | P1 |
| 单次会话内支持多轮追问，保持上下文 | "多轮上下文"为深度使用基础需求 | P0 |
| 历史会话简单列表（最近10条），不做搜索和命名 | "历史会话"需求存在但搜索/命名可延后 | P1 |
| 今日推荐/新能力提示以轻量banner形式展示 | "今日推荐""新能力提示"为首页认知需求 | P1 |

### 5.3 专家模式专项建议

| 建议 | 依据 | 优先级 |
|------|------|--------|
| MVP提供2个通用专家：写作助手 + 会议纪要整理 | 产品负责人确认"MVP搭框架+1-2个通用专家" | P0 |
| 每个专家配能力卡片：名称+一句话描述+适用场景+示例产出 | "能力说明"需求：能力卡片、适用场景、示例产出 | P0 |
| 专家选择后进入专属对话界面，界面展示专家身份和能力边界 | "智能体协作"需求：能力上下文 | P0 |
| 专家产出按结构化模板输出（如纪要=议题+讨论+结论+行动项） | "产出承接"需求表明用户期望可直接使用的产出 | P0 |
| 支持一键复制和基础导出（文本/Markdown） | "生成文档"为产出承接核心 | P0 |
| 支持用户粘贴文本作为上下文输入（替代正式知识库） | "知识增强"需求在MVP阶段以低成本方式满足 | P1 |
| 专家框架设计预留扩展接口，后续可快速接入新专家 | "我的智能体""专家团"需求需框架支撑 | P0 |
| 不做专家团多智能体协作、不做技能发布/版本管理 | 复杂度高，明确延后 | — |

### 5.4 定时任务模式专项建议

| 建议 | 依据 | 优先级 |
|------|------|--------|
| MVP预置3个任务模板：日报、周报、定时巡检 | "自动化任务"需求中周期报告为核心场景 | P0 |
| 配置流程表单化：选模板→设频率/时间→填任务描述→选推送方式→确认 | 降低配置门槛，对应痛点P7 | P0 |
| 钉钉消息作为唯一推送通道（MVP阶段） | "钉钉提醒"在自动化任务中出现 | P0 |
| "我的任务"列表展示已创建任务，支持取消/暂停 | "任务取消"为明确需求 | P0 |
| 任务创建后展示"下次执行时间"预览 | 降低用户不确定性，对应痛点P7 | P0 |
| 不做实时执行进度、异常恢复、运行时长分析 | 这些为"任务状态"深度需求，延后 | — |
| 不做运营看板（部门用量/Token消耗） | "运营治理"为管理者需求，非MVP核心 | — |
| 定时任务执行结果在门户内可查看历史产出 | 用户需确认任务执行效果 | P1 |

### 5.5 跨模式通用建议

| 建议 | 依据 | 优先级 |
|------|------|--------|
| 统一入口：钉钉工作台/浏览器/SSO三通道，SSO单点登录 | "入口触达"需求：钉钉入口、浏览器入口、统一SSO | P0 |
| 模式切换全局可用：任何位置可通过Tab/下拉切换三种模式 | "快捷功能切换"需求 | P0 |
| 首页底部或侧边提供"反馈/提需求"入口 | "需求提报"需求：需求表单 | P1 |
| 移动端适配：MVP保证钉钉移动端可访问首页和日常办公模式 | "移动端入口"在入口触达中出现 | P1 |
| 统一视觉风格：三种模式共享同一设计语言，通过色彩/图标区分模式 | 降低用户在不同模式间的认知切换成本 | P0 |
