> **报告日期**：2026-07-08  
> **分析师**：竞析（Compa）  
> **项目**：AI工作门户首页智能体 MVP  
> **调研范围**：钉钉AI助理、飞书智能伙伴、Coze/扣子、Kimi/通义千问、Notion AI、Microsoft Copilot

## 一、调研背景与目标

### 1.1 调研目的

为「AI工作门户首页智能体」MVP版本的PRD撰写提供竞品参考，重点研究以下维度的行业实践：

- 首页布局结构（搜索框位置、推荐区、技能/智能体展示方式）
- 模式/场景切换机制（手动切换 vs 自动识别 vs 混合）
- 对话交互体验（单轮 vs 多轮、上下文管理、历史会话）
- 专家/智能体选择方式（列表/卡片/搜索/推荐）
- 定时任务/自动化能力（是否有、如何创建）
- 引导和提示词策略（场景提示词、任务模板、推荐示例）

### 1.2 我们的MVP核心设计

| 维度 | 设计方案 |
|------|----------|
| 智能体模式 | 日常办公模式 / 专家模式 / 定时任务模式 |
| 模式切换 | 用户手动选择（Tab或下拉切换） |
| 首页定位 | 首页即工作台，不做全屏对话页 |
| PRD范围 | 首页整体布局 + 智能体三种模式交互 |

### 2.2 各竞品速览

#### 钉钉AI助理

- **定位**：企业级智能移动办公平台中的AI入口
- **入口位置**：左侧工具栏「工作台」→「AI助理」
- **核心能力**：智能对话、任务自动化、知识问答、跨应用协同、智能文档、智能表格、智能会议、智能审批、智能知识库、智能机器人开发平台
- **模型**：全面接入DeepSeek系列（DeepSeek-V3为日常首选）+ 通义千问
- **自动化**：支持工作流（定时触发器 → 数据读取 → AI处理 → 结果推送）
- **智能体机制**：支持创建自定义AI助理，通过技能市场一键安装AI技能包

#### 飞书智能伙伴

- **定位**：融合大模型能力的全场景AI办公伙伴
- **入口位置**：顶部「✦」按钮或 `/AI` 命令唤起
- **核心能力**：AI写作、AI会议纪要、AI翻译、AI数据分析、AI知识问答
- **交互模式**：自然语言对话 + 多轮上下文理解 + 跨模块调用（IM/文档/会议/表格/知识库）
- **首页布局**：AI工作台 + 最近会话列表 + 快捷任务入口（写周报/总结PDF/生成图表/翻译会议）
- **智能体机制**：单一智能伙伴，无显式多Agent切换（通过自然语言自动路由能力）

#### Coze/扣子 2.0（字节跳动）

- **定位**：从「对话式AI辅助工具」升级为「主动执行的智能协作伙伴」
- **入口位置**：独立平台，项目式入口
- **核心能力**：AgentSkills（技能封装）、AgentPlan（目标驱动）、AgentOffice（办公集成）、AgentCoding（低代码开发）
- **交互模式**：多Agent协作（一人+多Agent、多人+多Agent）、项目制管理
- **首页布局**：项目列表 + Agent阵容展示 + 输入"/"快速引用技能或文件
- **智能体机制**：多Agent协作编排，支持接入Claude Code/Codex/Openclaw等本地Agent + 扣子自有Agent（行业模板和技能包）
- **自动化**：AgentPlan支持长周期目标自动拆解和执行

#### Kimi（月之暗面）

- **定位**：通用AI助手，超长文本处理能力为差异化
- **入口位置**：独立对话页面
- **核心能力**：200万字超长上下文、联网搜索、文件解析、多轮对话
- **首页布局**：对话框居中 + 左侧历史会话 + Kimi+智能体入口
- **智能体机制**：Kimi+智能体（PPT助手等），左侧边栏按钮选择
- **提示词策略**：官方内置13个常用场景提示词 + 19套结构化「常用语」模板，支持用户保存自定义模板

#### 通义千问/豆包（阿里/字节）

- **定位**：通用AI助手（C端智能体功能已于2026年7月15日下线）
- **现状**：受《人工智能拟人化互动服务管理暂行办法》影响，用户自建智能体功能已下线
- **启示**：合规风险是智能体产品的重要考量因素

#### Notion AI

- **定位**：文档+协作+AI助手的轻量一体化方案
- **入口位置**：Notion工作区内嵌入
- **核心能力**：Notion Agent（Personal Agent + Custom Agent）、AI搜索、AI会议笔记
- **智能体机制**：
  - Personal Agent：个人AI助手，执行即时任务
  - Custom Agent：自定义定时/触发式多步骤代理
- **自动化**：支持时间表触发 + 事件触发（数据库状态变化等），按Credits计费（1000次≈$10）
- **跨平台**：可连接Slack、Google Drive、GitHub等

#### Microsoft Copilot（Microsoft 365）

- **定位**：Office全系列深度集成的AI办公助手
- **入口位置**：嵌入Word/Excel/PowerPoint/Teams/Outlook + 独立Copilot Chat + Windows任务栏Ask Copilot
- **核心能力**：智能体模式（Office应用内）、语音对话、图像文本抓取、Work IQ智能层
- **智能体机制**：
  - 内置智能体：研究助手、分析助手、人员智能体、Sales Development Agent等
  - 自定义智能体：通过Copilot Studio用自然语言创建
  - Work IQ：记忆用户偏好和工作流程，预测下一步行动并推荐智能体
- **自动化**：工作流智能体（按计划或事件自动执行任务），通过Frontier计划提供
- **管理**：Agent 365控制平台（部署、组织、监控、安全管理所有智能体）

## 四、深度分析：关键设计决策的行业实践

### 4.1 模式切换机制分析

**行业实践分为三种模式：**

| 模式 | 代表产品 | 优势 | 劣势 |
|------|---------|------|------|
| **手动切换** | 钉钉（选择不同助理）、Kimi（选择Kimi+）、Notion（选择Agent） | 用户掌控感强、意图明确、实现简单 | 切换成本高、用户可能不知道选哪个 |
| **自动识别** | 飞书（自然语言路由）、Copilot（Work IQ推荐） | 零切换成本、体验流畅 | 准确率依赖模型能力、用户可能困惑 |
| **混合模式** | Coze（项目内多Agent协作+手动选择） | 兼顾灵活与自动 | 架构复杂、学习成本高 |

**对MVP的启示**：我们的「手动Tab/下拉切换」方案属于行业主流实践（钉钉、Kimi、Notion均为手动选择），实现成本低且用户掌控感强。但需注意：
1. 提供清晰的模式说明和引导，降低用户选择困难
2. 可考虑在V2版本引入轻量级自动推荐（如根据用户输入内容推荐模式）
3. 三种模式的入口需视觉差异化，避免用户混淆

### 4.2 首页布局结构分析

**行业实践总结：**

| 布局模式 | 代表产品 | 特征 |
|---------|---------|------|
| **工作台嵌入式** | 钉钉、飞书 | AI入口嵌入已有工作台，与办公功能并列 |
| **独立对话页** | Kimi | 以对话为核心，首页即对话界面 |
| **项目/Agent列表式** | Coze | 以项目为单位组织，Agent作为项目成员 |
| **文档内嵌入** | Notion、Copilot | AI嵌入具体文档/应用中，无独立首页 |

**对MVP的启示**：我们的「首页即工作台」方案与钉钉/飞书的「工作台嵌入式」一致，是企业内部门户的主流选择。关键设计要点：
1. 对话区域不宜占满全屏，应与快捷入口/推荐区共存
2. 最近会话/任务历史是高频访问区域，需显著展示（参考飞书「最近会话」）
3. 智能体/专家展示采用卡片式（参考Coze Agent阵容卡片），降低认知成本

### 4.3 定时任务/自动化能力分析

**行业实践对比：**

| 产品 | 触发方式 | 创建门槛 | 执行能力 | 适用场景 |
|------|---------|---------|---------|---------|
| 钉钉 | 定时触发器 | 中（可视化工作流） | 数据读取→AI处理→推送 | 周报/巡检/预警 |
| Notion | 时间表+事件 | 低（自然语言配置） | 多步骤自动化 | 定期报告/任务分配 |
| Coze | 目标驱动 | 中（AgentPlan设定） | 自动拆解+长周期执行 | 复杂目标管理 |
| Copilot | 计划+事件 | 高（Copilot Studio） | 多步骤工作流 | 销售跟进/流程自动化 |

**对MVP的启示**：我们的「定时任务模式」在行业中有成熟先例。MVP阶段建议：
1. 采用钉钉式的「定时触发器 → AI处理 → 结果推送」简洁模型
2. 创建方式参考Notion的自然语言配置（降低门槛）+ 钉钉的可视化预览（提升信心）
3. MVP先支持周期性定时（日报/周报/巡检），事件触发留到V2
4. 任务模板预置2-3个高频场景（周报、巡检、数据汇总），降低冷启动门槛

### 4.4 专家/智能体选择方式分析

**行业实践趋势：**

```
单一伙伴(飞书)  →  预置智能体(Kimi+/钉钉技能市场)  →  自定义创建(Notion/Coze/Copilot)  →  多Agent协作(Coze)
     简单                    适中                          灵活                           复杂
```

**对MVP的启示**：我们的「专家模式」定位在「预置智能体」阶段是合理的：
1. MVP搭框架 + 1-2个通用专家（写作助手、会议纪要），与Kimi+的策略一致
2. 智能体展示用卡片式（参考Coze），包含名称、简介、适用场景
3. 保留扩展性：框架设计支持未来添加更多专家和用户自定义

### 4.5 提示词与引导策略分析

**行业最佳实践汇总：**

| 策略 | 实践产品 | 具体做法 |
|------|---------|---------|
| **场景分类提示词** | Kimi | 13个场景（办公/创作/学习/创意）+ 19套常用语模板 |
| **快捷任务入口** | 飞书 | 首页直接展示「写周报/总结PDF/生成图表/翻译会议」 |
| **技能包预置** | 钉钉/Coze | 技能市场/技能商店，一键安装 |
| **对话演示引导** | 飞书 | 首页展示AI对话演示，降低使用门槛 |
| **System Prompt调试** | 钉钉 | 创建助理时先调试再上线 |
| **Work IQ推荐** | Copilot | 根据用户行为智能推荐智能体和操作 |

**对MVP的启示**：
1. 首页需展示场景化提示词推荐（参考Kimi的13个场景分类）
2. 每种模式提供2-3个快捷任务入口（参考飞书的「写周报/总结PDF」）
3. 专家模式中每个专家配备使用示例和提示词模板
4. 定时任务模式提供任务模板（周报模板、巡检模板），用户填空即可创建

| 能力维度 | 行业现状 | 差异化机会 |
|---------|---------|-----------|
| **三模式统一入口** | 各产品要么单一模式、要么多Agent分散，缺乏「日常办公+专家+定时任务」三模式统一入口 | 我们的三模式Tab切换是差异化设计，将三种高频需求统一在一个首页 |
| **首页即工作台** | 钉钉/飞书是AI嵌入已有工作台，Kimi是纯对话页，缺乏「AI-first的工作台」 | 我们以AI为首页核心，工作台围绕AI智能体组织，而非AI作为附属功能 |
| **模式间上下文传递** | 各产品的模式/Agent之间通常是独立的，上下文不传递 | 可设计模式切换时保留上下文（如日常办公中发现的写作需求可平滑切换到专家模式） |
| **定时任务与专家结合** | 钉钉定时任务是独立的，Notion Custom Agent与Personal Agent分离 | 可设计「定时任务调用专家能力」的组合（如定时让写作助手生成周报） |
| **轻量化定时任务** | 钉钉需配置完整工作流，Notion需Business版+Credits，门槛较高 | 可提供极简的定时任务创建（选模板→选时间→选推送目标），降低使用门槛 |

### 5.2 可借鉴的竞品亮点

| 竞品 | 亮点 | 借鉴方向 |
|------|------|---------|
| **飞书** | 顶部✦按钮 + `/AI`命令快速唤起 | 提供快捷唤起方式，降低AI使用门槛 |
| **飞书** | 首页快捷任务入口（写周报/总结PDF/生成图表/翻译会议） | 每种模式提供2-3个一键任务入口 |
| **飞书** | 对话演示引导 | 首页展示智能体能力演示，降低新用户门槛 |
| **Kimi** | 场景分类提示词（13个场景+19套常用语） | 为日常办公模式提供场景化提示词推荐 |
| **Kimi** | 「常用语」保存功能 | 允许用户保存常用提示词，快速复用 |
| **钉钉** | 工作流可视化预览（右侧实时预览） | 定时任务创建时提供预览效果 |
| **钉钉** | System Prompt调试后再上线 | 专家模式允许用户试调后再正式使用 |
| **Coze** | 项目式管理 + Agent资产沉淀 | 定时任务模式可按项目管理，沉淀历史产出 |
| **Coze** | 技能商店（300+预设技能） | 专家模式预留技能扩展市场 |
| **Notion** | 时间表+事件双触发 | 定时任务V2可引入事件触发（如数据变化时） |
| **Notion** | 自然语言配置Agent | 定时任务用自然语言描述即可创建 |
| **Copilot** | Work IQ智能推荐 | V2可引入基于用户行为的智能体推荐 |
| **Copilot** | 语音对话 | 移动端可考虑语音输入 |

### 5.3 需规避的竞品陷阱

| 陷阱 | 来源 | 规避策略 |
|------|------|---------|
| **合规风险** | 通义千问/豆包智能体功能因《人工智能拟人化互动服务管理暂行办法》下线 | 专家模式避免过度拟人化，明确标注「AI助手」身份 |
| **模式过多导致选择困难** | Coze的多Agent编排对普通用户门槛高 | MVP严格控制在3种模式，不做更多模式拆分 |
| **自动化配置过重** | 钉钉工作流配置节点较多，非技术用户有门槛 | 定时任务MVP极简化：选模板→填参数→选时间 |
| **AI入口过深** | 钉钉AI助理需从工作台二级进入 | AI智能体应作为首页核心区域，而非二级入口 |
| **独立对话页割裂** | Kimi的纯对话页与办公场景割裂 | 坚持首页即工作台，对话嵌入首页而非独立页面 |

## 六、对MVP的设计启示总结

### 6.1 首页布局建议

```
┌─────────────────────────────────────────────────────────┐
│                    AI工作门户首页                          │
├─────────────────────────────────────────────────────────┤
│  [日常办公模式] [专家模式] [定时任务模式]    ← Tab切换     │
├──────────────────────────┬──────────────────────────────┤
│                          │  最近会话/任务                 │
│   ┌──────────────────┐   │  ┌────────────────────────┐  │
│   │  对话/任务输入框   │   │  │ 💬 周报草稿 - 2小时前   │  │
│   │  「问飞书AI...」   │   │  │ 💬 会议纪要 - 昨天      │  │
│   └──────────────────┘   │  │ ⏰ 日报任务 - 运行中    │  │
│                          │  └────────────────────────┘  │
│   快捷任务入口             │                              │
│   ┌────┐┌────┐┌────┐     │  推荐提示词                   │
│   │写周报││纪要 ││翻译 │    │  ┌────────────────────────┐  │
│   └────┘└────┘└────┘     │  │ 📝 帮我总结今天的会议     │  │
│                          │  │ 📊 分析本周销售数据       │  │
│                          │  │ 📋 起草项目进度汇报       │  │
│                          │  └────────────────────────┘  │
└──────────────────────────┴──────────────────────────────┘
```

**设计要点：**
1. 三模式Tab切换置于顶部显著位置，视觉差异化（图标+文字）
2. 左侧主区域为对话/任务输入 + 快捷任务入口
3. 右侧侧边栏为最近会话/任务 + 推荐提示词（参考飞书布局）
4. 对话区域不占满全屏，与快捷入口共存（参考飞书「首页即工作台」）

### 6.2 三种模式交互建议

#### 日常办公模式
- **参考**：飞书智能伙伴的统一入口 + Kimi的场景提示词
- **交互**：对话框居中 + 场景化提示词推荐（办公效率/信息查询/写作辅助3类）
- **快捷入口**：写周报、总结文档、翻译内容、查询信息（参考飞书4个快捷入口）
- **上下文**：支持多轮对话，保留会话历史

#### 专家模式
- **参考**：Kimi+的侧边栏选择 + Coze的Agent卡片展示
- **交互**：专家卡片列表（MVP: 写作助手 + 会议纪要专家）+ 点击进入专家对话
- **卡片信息**：专家名称、简介、适用场景、使用示例
- **提示词模板**：每个专家内置3-5个提示词模板（参考Kimi常用语）
- **扩展性**：卡片区域预留「更多专家即将上线」入口

#### 定时任务模式
- **参考**：钉钉的定时触发器 + Notion的自然语言配置
- **交互**：任务模板列表（周报/巡检/数据汇总）+ 创建向导
- **创建流程**：选模板 → 填参数（数据源/输出格式）→ 选时间 → 选推送目标
- **任务管理**：已创建任务列表 + 运行状态 + 历史产出查看
- **预览能力**：创建时支持「立即运行一次」测试效果（参考钉钉）

### 6.3 关键设计原则

| 原则 | 说明 | 竞品参考 |
|------|------|---------|
| **AI-first** | 首页以AI智能体为核心，而非将AI作为附属功能 | 区别于钉钉的「工作台+AI助理二级入口」 |
| **三模式统一** | 三种模式在同一首页通过Tab切换，而非分散入口 | 区别于各竞品的单一模式或多入口分散 |
| **极简创建** | 定时任务创建极简化，选模板+填参数即可 | 借鉴Notion自然语言配置 + 钉钉可视化预览 |
| **场景引导** | 每种模式提供场景化提示词和快捷入口 | 借鉴Kimi场景提示词 + 飞书快捷任务 |
| **合规优先** | 避免过度拟人化，明确AI身份 | 规避通义千问/豆包合规风险 |
