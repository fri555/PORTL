## 0. 框架总览

### 0.1 指标分层架构

本指标框架遵循 **"北极星 → 核心指标 → 过程指标 → 健康度指标"** 四层结构：

| 层级 | 定位 | 回答的问题 | 指标数量 |
|------|------|-----------|---------|
| L0 北极星 | 唯一核心价值标尺 | 产品的核心价值是否在增长？ | 1 |
| L1 核心指标 | 价值交付的关键路径 | 用户是否在用？用得怎么样？ | 4 |
| L2 过程指标 | 转化漏斗各环节 | 哪里堵了？哪里漏了？ | 12 |
| L3 健康度指标 | 质量与长期可持续性 | 体验好不好？用户留不留？ | 8 |

### 0.2 指标全景图

```
                        ┌─────────────────────────┐
                        │    北极星指标（L0）       │
                        │  周有效任务完成数(WECT)  │
                        └────────────┬────────────┘
                                     │
              ┌──────────────────────┼──────────────────────┐
              ▼                      ▼                      ▼
   ┌──────────────────┐  ┌──────────────────┐  ┌──────────────────┐
   │  首页表现（L1）   │  │  模式使用（L1）   │  │  对话质量（L1）   │
   │  访问→发起→完成   │  │  三模式分布与质量 │  │  满意度与深度     │
   └────────┬─────────┘  └────────┬─────────┘  └────────┬─────────┘
```

## 1. 北极星指标（L0）

### 1.1 指标定义

| 属性 | 内容 |
|------|------|
| **指标名称** | 周有效任务完成数（Weekly Effective Completed Tasks, WECT） |
| **定义** | 每周通过首页智能体发起并**成功完成**的任务总数。"成功完成"需同时满足：①用户未中途主动放弃；②末轮对话后24h内无负反馈（点踩/重新提问）；③定时任务模式下任务按计划执行成功。 |
| **计算公式** | WECT = Σ(日常办公模式有效完成任务) + Σ(专家模式有效完成任务) + Σ(定时任务模式有效执行任务) |
| **统计周期** | 自然周（周一00:00 ~ 周日24:00） |
| **更新频率** | 每周一更新上周数据 |

### 1.2 选择理由

| 候选指标 | 优点 | 否决原因 |
|---------|------|---------|
| DAU | 简单、易衡量 | 只反映"来了"，不反映"用了"，无法区分刷量和真实使用 |
| 周活任务发起数 | 反映使用意愿 | 不区分成功与失败，低质量回答也能刷高指标 |
| **周有效任务完成数** ✅ | 同时覆盖**使用广度**（多少用户）、**使用深度**（人均几任务）、**质量**（完成才算） | — |
| 满意度评分 | 直接反映质量 | 样本量小、主观偏差大，不适合做北极星 |

### 1.3 北极星拆解公式

```
WECT = WAU × 人均周发起任务数 × 任务有效完成率
       │         │                │
       │         │                └── 反映产品质量（L1 对话质量）
       │         └── 反映使用深度（L1 模式使用）
       └── 反映触达广度（L1 首页表现）
```

> **洞察**：WECT 的三个因子分别对应 L1 的三大核心指标域，任何一个因子下降都会直接拉低北极星，使问题定位路径清晰。

## 2. 首页表现指标（L1-L2）

### 2.1 L1 核心指标

#### 2.1.1 首页日活跃用户数（Portal DAU）

| 属性 | 内容 |
|------|------|
| **定义** | 每日访问AI工作门户首页的去重用户数（以用户ID去重，单日多次访问计1次） |
| **计算公式** | DAU = COUNT(DISTINCT user_id WHERE 日期 = 当日 AND 页面 = 首页) |
| **统计口径** | 仅统计首页实际打开行为（含iframe嵌入、桌面端打开），不含后台API调用 |
| **关联指标** | MAU、DAU/MAU比值（粘性比） |

#### 2.1.2 首页任务发起率（Task Initiation Rate）

| 属性 | 内容 |
|------|------|
| **定义** | 访问首页的用户中，发起至少一次有效任务（发送至少一条消息/创建一个定时任务）的占比 |
| **计算公式** | 任务发起率 = 发起任务用户数 / 首页DAU × 100% |
| **漏斗位置** | 访问首页 → **发起任务** → 完成任务 |
| **关键阈值** | < 30% 需警惕（说明首页引导不足或入口过深）；> 60% 为优秀 |

#### 2.1.3 搜索框使用率（Search Usage Rate）

| 属性 | 内容 |
|------|------|
| **定义** | 访问首页的用户中，使用搜索/命令框发起查询的占比 |
| **计算公式** | 搜索框使用率 = 使用搜索框用户数 / 首页DAU × 100% |
| **业务含义** | 搜索框是高级用户的快捷入口，使用率反映产品对高效用户的吸引力 |
| **细分维度** | 按用户角色（管理层/普通员工/技术）、按使用时段 |

#### 2.1.4 常用技能区点击率（Quick Skills CTR）

| 属性 | 内容 |
|------|------|
| **定义** | 首页"常用技能"区块各技能卡片的点击率 |
| **计算公式** | 技能CTR = 技能卡片点击数 / 技能卡片曝光数 × 100% |
| **业务含义** | 反映技能推荐的相关性和卡片设计的吸引力 |
| **细分维度** | 逐技能统计、按位置（首位/末位）统计 |

#### 2.1.5 推荐区点击率（Recommendation CTR）

| 属性 | 内容 |
|------|------|
| **定义** | 首页"推荐"区域（含推荐任务模板、推荐专家、推荐场景）的点击率 |
| **计算公式** | 推荐CTR = 推荐区点击数 / 推荐区曝光数 × 100% |
| **业务含义** | 反映推荐算法精准度和推荐内容吸引力 |
| **A/B测试** | MVP阶段建议对推荐策略做A/B测试（如"基于历史"vs"基于热门"） |

### 2.2 L2 过程指标 — 首页转化漏斗

```
访问首页(DAU)
    │  转化率 A: 访问→交互
    ▼
与智能体交互(发消息/点技能/搜索)
    │  转化率 B: 交互→发起任务
    ▼
发起任务(选择模式+发送首条消息)
    │  转化率 C: 发起→完成
    ▼
任务完成(获得有效结果)
```

| 漏斗节点 | 指标 | 计算方式 | MVP预警阈值 |
|---------|------|---------|------------|
| 访问→交互 | 首页交互率 | 交互用户/DAU | < 50% |
| 交互→发起 | 交互转化率 | 发起任务用户/交互用户 | < 60% |
| 发起→完成 | 任务完成率 | 完成任务数/发起任务数 | < 70% |
| **端到端** | **首页→完成转化率** | **完成任务用户/DAU** | **< 25%** |

### 2.3 L2 过程指标 — 首页元素表现

| 指标 | 定义 | 计算方式 | 说明 |
|------|------|---------|------|
| 模式切换率 | 用户在单次会话中切换模式的次数占比 | 切换模式次数/总会话数 | > 20%说明模式入口设计需优化 |
| 首页停留时长 | 用户在首页的平均停留时间 | Σ停留时长/DAU | 非核心指标，仅参考；过长可能意味犹豫 |
| 首屏可见率 | 首页核心元素（搜索框/模式切换/技能区）进入首屏的比例 | 进入首屏的元素数/核心元素总数 | 技术+设计联合保障 |

## 3. 三种模式使用指标（L1-L2）

### 3.1 L1 核心指标 — 模式使用分布

#### 3.1.1 各模式使用占比（Mode Distribution）

| 模式 | 预期占比（MVP参考） | 说明 |
|------|-------------------|------|
| 日常办公模式 | 60%-70% | 最高频、最通用，预期为主力模式 |
| 专家模式 | 20%-30% | 专业场景，频率较低但价值密度高 |
| 定时任务模式 | 5%-15% | 低频高粘性，创建一次长期复用 |

| 属性 | 内容 |
|------|------|
| **定义** | 各模式被选择使用的次数占总使用次数的比例 |
| **计算公式** | 模式i占比 = 模式i使用次数 / Σ(三模式使用次数) × 100% |
| **统计维度** | 按任务维度统计（一个任务 = 用户选择模式后的一次完整交互会话） |
| **预警条件** | 任一模式占比 < 3%（该模式可能未被感知，需检查入口/引导） |

#### 3.1.2 各模式任务完成率（Per-Mode Completion Rate）

| 属性 | 内容 |
|------|------|
| **定义** | 各模式下，用户发起的任务最终成功完成的比例 |
| **计算公式** | 模式i完成率 = 模式i完成任务数 / 模式i发起任务数 × 100% |
| **完成判定标准** | 日常办公/专家模式：用户未主动放弃 + 24h内无负反馈；定时任务模式：按计划执行成功 |
| **分模式预警** | 任一模式完成率 < 60% |

#### 3.1.3 各模式平均对话轮次（Per-Mode Avg Turns）

| 属性 | 内容 |
|------|------|
| **定义** | 各模式下，单次任务（会话）中用户与智能体的平均交互轮数 |
| **计算公式** | 模式i平均轮次 = Σ(模式i各任务对话轮数) / 模式i任务总数 |
| **解读维度** | 轮次过高（>8轮）可能意味着回答不准、反复追问；轮次过低（<2轮）可能意味着用户未深度使用即放弃 |

### 3.2 L2 过程指标 — 模式维度细分

#### 3.2.1 日常办公模式

| 指标 | 定义 | 计算方式 | 说明 |
|------|------|---------|------|
| 任务类型分布 | 写作辅助/信息查询/通用问答的占比 | 各类型任务数/日常模式总任务数 | 帮助识别高频场景 |
| 首轮解决率 | 用户首轮提问即获得满意回答的比例 | 首轮满意任务数/日常模式任务数 | 核心体验指标 |
| 放弃率 | 用户发起后未获得结果即离开的比例 | 放弃任务数/日常模式任务数 | 体验负面信号 |

#### 3.2.2 专家模式

| 指标 | 定义 | 计算方式 | 说明 |
|------|------|---------|------|
| 各专家使用分布 | 每个专家Agent被调用的次数及占比 | 专家j调用次数/专家模式总调用数 | MVP仅1-2个专家，关注是否均匀 |
| 专家调用深度 | 用户调用某专家后的平均对话轮次 | Σ(专家j对话轮次)/专家j调用数 | 高深度说明专家价值高 |
| 专家满意度 | 各专家获得点赞/点踩的比率 | 点赞数/(点赞+点踩数) | 评估专家质量 |
| 专家覆盖率 | 被使用的专家数/已上架专家数 | 已使用专家数/总专家数 | MVP阶段需确认两个专家均被使用 |

#### 3.2.3 定时任务模式

| 指标 | 定义 | 计算方式 | 说明 |
|------|------|---------|------|
| 任务创建数 | 每周新建的定时任务总数 | COUNT(WHERE 模式=定时 AND 事件=创建) | 反映该模式的采纳度 |
| 任务类型分布 | 日报/周报/巡检等各类型占比 | 各类型创建数/总创建数 | 帮助优先扩展高频类型 |
| 执行成功率 | 定时任务按计划成功执行的比例 | 成功执行次数/计划执行次数 × 100% | 核心质量指标，< 90%需告警 |
| 任务存活率 | 创建7天后仍处于激活状态的定时任务比例 | 7天后激活任务数/7天前创建任务数 | 反映持续价值 |
| 人均创建数 | 每位使用定时任务模式的用户平均创建的任务数 | 总创建数/使用该模式的用户数 | 评估粘性 |

## 4. 对话质量指标（L1-L3）

### 4.1 L1 核心指标

#### 4.1.1 首次回答满意度（First Response Satisfaction）

| 属性 | 内容 |
|------|------|
| **定义** | 用户对智能体首次回答的满意程度，通过显式反馈（点赞/点踩）衡量 |
| **计算公式** | 满意度 = 点赞数 / (点赞数 + 点踩数) × 100% |
| **统计口径** | 仅统计用户选择"赞"或"踩"的回答；未反馈的不计入分母 |
| **反馈率** | 反馈率 = (点赞+点踩) / 总回答数 × 100%，反映用户参与反馈的意愿 |
| **预警阈值** | 满意度 < 70% 或 反馈率 < 5%（反馈率过低说明反馈入口设计有问题） |

#### 4.1.2 全局平均对话轮次（Avg Conversation Turns）

| 属性 | 内容 |
|------|------|
| **定义** | 所有任务（会话）中用户与智能体交互的平均轮数 |
| **计算公式** | 平均轮次 = Σ(各任务对话轮数) / 任务总数 |
| **健康区间** | 3-6轮为健康区间；< 3轮可能任务过于简单或用户快速放弃；> 6轮可能回答质量不佳需追问 |
| **与分模式指标关系** | 全局轮次是三种模式轮次的加权平均，需结合模式占比解读 |

#### 4.1.3 上下文续问率（Context Continuation Rate）

| 属性 | 内容 |
|------|------|
| **定义** | 用户在获得首次回答后，基于同一上下文继续追问（而非结束/新建会话）的比例 |
| **计算公式** | 续问率 = 含续问的会话数 / 总会话数 × 100% |
| **业务含义** | 高续问率说明用户信任智能体的上下文理解能力，愿意深入对话；过低可能说明首次回答已终结需求或用户不信任续问能力 |
| **健康区间** | 30%-50% 为健康 |

#### 4.1.4 历史会话回访率（History Revisit Rate）

| 属性 | 内容 |
|------|------|
| **定义** | 用户回看/继续历史会话的频率 |
| **计算公式** | 回访率 = 回看历史会话的用户数 / DAU × 100% |
| **业务含义** | 反映历史会话的价值和用户对沉淀内容的依赖度 |
| **细分** | 按回访目的分：①继续未完成任务 ②查找历史答案 ③复制历史内容 |

### 4.2 L3 健康度指标 — 对话质量细分

| 指标 | 定义 | 计算方式 | 预警阈值 |
|------|------|---------|---------|
| 首轮解决率 | 单轮即完成（用户未续问且24h内无负反馈）的任务比例 | 单轮完成任务数/总任务数 | < 30% |
| 重试率 | 同一任务中用户重新提问（非续问）的次数占比 | 含重试的任务数/总任务数 | > 25% |
| 回答响应时长 | 智能体从接收消息到返回首字符/完整回答的时间 | P50/P90 响应时长 | P90 > 8s |
| 中途放弃率 | 用户发起任务后未到完成即关闭页面的比例 | 放弃任务数/总任务数 | > 20% |
| 点踩后修正率 | 点踩后用户继续对话并最终满意的比例 | 点踩后满意任务数/点踩任务数 | < 30%（说明点踩后挽回能力弱） |

## 5. 用户留存指标（L3）

### 5.1 留存指标

#### 5.1.1 次日留存率（D1 Retention）

| 属性 | 内容 |
|------|------|
| **定义** | 首次使用首页智能体的用户，次日再次访问的比例 |
| **计算公式** | D1留存 = 次日回访用户数 / 首日新增用户数 × 100% |
| **统计口径** | "首次使用" = MVP上线后首次与智能体交互（发送消息或创建任务） |
| **企业内部产品参考值** | D1 30%-45% 为合理区间（企业工具类产品天然低于消费级产品） |

#### 5.1.2 周留存率（D7 Retention）

| 属性 | 内容 |
|------|------|
| **定义** | 首次使用用户在第7天（±1天窗口）再次访问的比例 |
| **计算公式** | D7留存 = 第7天回访用户数 / 首日新增用户数 × 100% |
| **企业内部产品参考值** | D7 20%-30% 为合理区间 |
| **关键判断** | D7/D1 > 0.6 说明留存曲线趋于平稳，产品价值被验证 |

#### 5.1.3 留存曲线分析

| 分析方法 | 说明 | 行动标准 |
|---------|------|---------|
| 留存曲线形态 | 绘制D1-D30留存曲线 | 曲线在第7天后趋于平稳 = 产品价值确立 |
| 分模式留存 | 按用户首次使用的模式分组对比留存 | 若某模式D7显著低于全局，说明该模式体验差 |
| 分群留存 | 按用户角色/部门分群对比 | 识别高留存群体特征，针对性推广 |

### 5.2 核心功能使用深度

| 指标 | 定义 | 计算方式 | 健康参考值 |
|------|------|---------|-----------|
| 人均周任务数 | 每位活跃用户每周平均完成的任务数 | WECT/WAU | 3-8任务/周 |
| 功能使用广度 | 用户使用的不同功能/模式的数量 | DISTINCT(使用的模式+技能数) | 平均 ≥ 2种功能 |
| 深度用户占比 | 周任务数 ≥ 10的用户占WAU比例 | 深度用户数/WAU | 15%-25% |
| 定时任务留存贡献 | 使用定时任务模式的用户D7留存 vs 未使用用户D7留存 | A/B 对比 | 使用者D7高出 15pp+ |

## 6. 产品健康度指标（L3 补充）

| 指标 | 定义 | 预警阈值 | 说明 |
|------|------|---------|------|
| 崩溃率 | 首页或对话过程崩溃/报错的频率 | > 1% | 技术健康度底线 |
| 接口错误率 | 后端API调用失败率 | > 2% | 影响所有模式 |
| 首屏加载时间 | 首页首屏完整渲染时间 P90 | > 3s | 影响首页交互率 |
| 模式切换延迟 | 用户切换模式到界面就绪的时间 P90 | > 2s | 影响多模式使用体验 |
| NPS/CSAT | 用户满意度调研评分 | NPS < 10 | 季度调研，非实时 |

## 7. MVP成功标准建议

### 7.1 总体判断逻辑

MVP阶段的核心目标是**验证产品价值假设**：企业用户是否愿意将日常办公任务交给AI门户智能体处理。因此，成功标准聚焦于"是否有人用、用得是否有效、是否会回来"三个维度。

### 7.2 分阶段成功标准

#### 阶段一：上线后2周（冷启动验证期）

| 维度 | 指标 | 目标值 | 说明 |
|------|------|--------|------|
| 触达 | 首页DAU | ≥ 目标用户群30% | MVP优先面向种子用户群推广 |
| 激活 | 首页任务发起率 | ≥ 40% | 访问首页的用户中有四成发起任务 |
| 试用 | 三模式均有使用 | 各模式使用占比均 > 3% | 确认三种模式都被用户感知到 |
| 质量 | 任务完成率 | ≥ 65% | 超过六成任务成功完成 |

#### 阶段二：上线后4周（价值验证期）

| 维度 | 指标 | 目标值 | 说明 |
|------|------|--------|------|
| 活跃 | WAU | ≥ 目标用户群40% | 周维度稳定活跃 |
| 深度 | 人均周任务数 | ≥ 3 | 每位活跃用户每周至少完成3个任务 |
| 质量 | 首次回答满意度 | ≥ 75% | 四分之三的回答用户表示满意 |
| 留存 | D1留存率 | ≥ 35% | 次日留存超三成 |
| 留存 | D7留存率 | ≥ 22% | 周留存超两成 |

#### 阶段三：上线后8周（北极星达成期）

| 维度 | 指标 | 目标值 | 说明 |
|------|------|--------|------|
| **北极星** | **周有效任务完成数（WECT）** | **≥ WAU × 3** | 每位周活用户平均完成3个有效任务 |
| 模式健康 | 日常办公模式占比 | 50%-70% | 在合理区间内 |
| 模式健康 | 定时任务存活率 | ≥ 60% | 创建7天后仍激活 |
| 留存 | D7留存率 | ≥ 25% | 留存曲线趋于平稳 |
| 留存 | D7/D1比 | ≥ 0.6 | 留存曲线收敛 |
| 深度 | 深度用户占比 | ≥ 15% | 周任务数 ≥ 10的用户占比 |
| 质量 | 定时任务执行成功率 | ≥ 90% | 定时任务可靠性达标 |

### 7.3 成功标准汇总矩阵

```
                    2周(冷启动)    4周(价值验证)    8周(北极星)
                   ─────────────────────────────────────────
首页DAU覆盖率        ≥ 30%          ≥ 35%           ≥ 40%
任务发起率           ≥ 40%          ≥ 45%           ≥ 50%
任务完成率           ≥ 65%          ≥ 70%           ≥ 75%
满意度              —              ≥ 75%           ≥ 80%
D1留存              —              ≥ 35%           ≥ 40%
D7留存              —              ≥ 22%           ≥ 25%
人均周任务数          —              ≥ 3             ≥ 4
WECT（北极星）       —              —              ≥ WAU × 3
定时任务执行成功率     —              —              ≥ 90%
                   ─────────────────────────────────────────
                   不达标 → 诊断    不达标 → 迭代    不达标 → 重大调整
```

### 7.4 不达标应对策略

| 不达标指标 | 诊断方向 | 可能的改进措施 |
|-----------|---------|--------------|
| DAU覆盖率低 | 触达问题 | 检查推广渠道、入口位置、通知策略 |
| 任务发起率低 | 首页设计问题 | 优化引导、降低首次使用门槛、强化推荐区 |
| 任务完成率低 | 对话质量问题 | 优化Prompt、增强上下文理解、提升响应速度 |
| 满意度低 | 回答质量问题 | 分析点踩内容、优化知识库、调整模型参数 |
| D1留存低 | 首次体验问题 | 优化新手引导、首次回答质量、首次任务选择 |
| D7留存低 | 持续价值问题 | 增加定时任务粘性、推荐场景多样化、历史回访引导 |
| 某模式占比极低 | 入口/引导问题 | 检查模式切换入口可见性、增加引导提示 |

## 9. 附录

### 9.1 术语表

| 术语 | 定义 |
|------|------|
| WECT | Weekly Effective Completed Tasks，周有效任务完成数，北极星指标 |
| WAU | Weekly Active Users，周活跃用户数 |
| 任务 | 用户选择一种模式后的一次完整交互会话（从首条消息到结束/放弃） |
| 有效完成 | 用户未主动放弃 + 24h内无负反馈（日常/专家模式）；按计划执行成功（定时任务模式） |
| 续问 | 用户在同一会话上下文中继续追问（非新建会话） |
| 重试 | 用户在同一会话中重新提出相似问题（非续问，而是不满意后重问） |
| CTR | Click-Through Rate，点击率 |
| pp | percentage point，百分点（用于描述比率之间的差值） |

### 9.2 指标依赖关系图

```
WECT = WAU × 人均周发起任务数 × 任务有效完成率
                    │                    │
            ┌───────┴───────┐    ┌──────┴──────┐
            │               │    │             │
         DAU           任务发起率  满意度      放弃率
         /MAU          搜索框使用率  首轮解决率  崩溃率
                      技能CTR     续问率      响应时长
                      推荐CTR     重试率
```
