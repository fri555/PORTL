# 固定 PRD 模板与钉钉发布

## 固定结构

发布到钉钉的完整 PRD 使用以下结构；源文档已有格式时，仅对发布副本做映射。

1. 封面：`产品需求说明书`（26pt 斜体）与项目名称（36pt 粗体）。
2. 版本信息：位于目录前，不参与自动编号；Markdown 中在 `# 版本信息` 前放置 `<!-- preface -->`。
3. 关于本文档：术语表、参考文档、沟通要求。
4. 产品概述：背景、目标、范围、用户角色、用户故事地图，竞品调研可选。
5. 功能需求：全局规则、流程图、功能模块清单、功能详情。
6. 非功能需求：性能、安全、兼容性；仅填写已确认指标。
7. 迭代计划与 Non-goals。
8. 附录：提示文案、状态枚举、接口或提示词说明。

每个功能模块优先沿用主技能约定的章节顺序。`### M{n}-{功能名}` 为模块标题；模块清单固定为“编号 / 功能名称 / 功能描述 / 所属模块 / 优先级”。

## Markdown 约定

- 文件开头使用两行纯粗体文本作为封面，例如 `**产品需求说明书**`、`**项目名称**`，不要加 `#`。
- 章节从 `#` 开始，标题不要手写 `一、`、`1.1` 等编号，由转换器自动生成。
- Mermaid 使用围栏代码块并标记 `mermaid`。
- 表格表头使用灰底、黑色粗体、11pt；正文表格为 11pt，普通正文为 12pt。
- 示例占位表可在表格前加入 `<!-- 示例 -->`，其数据行使用橙色文字；确认后的正式数据表不要使用该标记。
- 不支持的 Markdown 表现应转为可读纯文本，不得因此删除需求内容。
- Markdown 表格单元格中的 `<br>` 仅作为源稿换行标记；`md2jsonml.py` 会将其转换为同一 `tc` 下的多个真实段落。发布前必须检查 JsonML 中不存在正文文字 `<br>`，发布后回读确认各条目已在单元格内分行。

## 转换

```powershell
python scripts/md2jsonml.py INPUT.md -o OUTPUT.jsonml -t "钉钉文档标题"
```

可使用 `--cover-a`、`--cover-b` 覆盖自动识别的封面文案。转换器输出完整的 `root` JsonML，包含封面、目录和正文。

## 发布边界

### 创建新文档

用户明确要求发布后，可使用当前环境提供的钉钉文档能力或等价命令创建文档。若使用 `dws`：

```powershell
dws doc create --name "DOC_TITLE" --content-file OUTPUT.jsonml --content-format jsonml -y
```

### 覆盖已有文档

覆盖前必须同时满足：

1. 用户明确要求覆盖；
2. 目标链接或 `nodeId` 可唯一确定；
3. 先执行只读检查或 dry-run，确认目标和 JsonML 可解析。

不得根据技能中的示例节点、本机历史文件或最近访问页面猜测覆盖对象。若目标不明确，停止在本地 JsonML 产物，并请用户提供目标。

若使用 `dws`，先 dry-run，再执行：

```powershell
dws doc update --node NODE_ID --content-file OUTPUT.jsonml --content-format jsonml --mode overwrite --yes
```

不要使用 `--fix-jsonml`；该选项可能导致内容被截断。

## 发布后校验

回读文档块并进行结构校验，不做简单字符串比对：

- 存在 `toc`，且标题锚点可解析；
- 一级至多级标题存在自动编号属性；
- 表格字体大小位于叶子节点，表头保持灰底；
- Mermaid 以 `syntax: mermaid` 写入；
- 文档块数量与主要章节完整，没有只剩首个块。

交付时提供钉钉链接、本地源 Markdown、本地 JsonML、创建或覆盖结果，以及未通过的校验项。
